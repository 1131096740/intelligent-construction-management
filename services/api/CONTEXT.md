# 项目经营后台领域词汇

本文件定义后台业务中心处理项目经营事实时使用的术语。跨端共同词汇见 [`项目经营共享领域词汇`](../../packages/shared-domain/CONTEXT.md)，完整规则以 [`项目经营总账、施工企业经营接管与统一业务录入正式规格`](../../docs/specs/2026-08-12-project-operating-ledger-construction-enterprise-takeover-unified-entry.md) 为准。

## 核心词汇

**正式经营事实**：已经完成场景所需确认并进入正式经营账的业务事实；不能通过修改草稿、覆盖字段或物理删除改变，只能更正、冲销或补充依据。

**经营账投影**：后台根据同一正式经营事实的主体、性质和状态，计算项目合并经营账、施工企业往来、我方公司分账、应收应付和资金位置；不是复制生成多份业务记录。

**付款核销**：把一笔实际付款按财务确认的金额清偿到明确应付款；不得由后台自行按最早欠款分配，也不得因付款再次确认项目成本。

**跨主体代付**：实际付款主体替债务主体清偿下游款。后台同时清偿原应付款并形成主体间代付往来，后续归还只清偿该往来。

**银行流水候选签名**：后台针对一条未消费的已核验银行流水候选签发给当前操作人的短效选择凭据；提交时必须在串行化事务内重新鉴权、重新解析并核对全部冻结事实，签名本身不构成授权或业务标识。

**正式后果权威适配器**：后台在确认事务内把逐轴业务选择解析为应付、项目资金、主体往来或经营的既有正式事实，并冻结完整后果引用；未找到封闭适配器、权威事实不一致或金额不闭合时整笔失败。

**事务统一录入冻结器**：由领域服务在自己的 `Prisma.TransactionClient` 内调用的原子能力；场景必须预先显式登记正式对象类型、业务动作、唯一项目归属解析器和领域授权解析器，定义校验、两次归属复验与快照持久化始终复用调用方事务。未登记、对象缺失、归属不唯一、跨项目、无权或冻结期间漂移均整笔失败。

**反向执行**：新建一条方向相反的资金执行事实，逐行引用原共享执行分配，在剩余可反向额度内复制原效果轴身份并追加精确逆后果；不得覆盖原执行或重新选择分类。

**对账快照**：按对账基准日冻结的系统推导值、外部对账值、匹配结果和差异；后续更正只标记影响，不覆盖原快照。

**受控期初汇总**：历史事实无法逐笔还原时，按相对方、类别和期间形成并经复核的 B 级事实；不得把整个项目压成一笔收入或成本。

**资金容器**：系统记录资金实际所在的位置，包括每家我方公司的登记资金和全系统唯一的公共现金；不是实时银行余额或银行账号档案，公共现金没有所属公司。

**资金来源批次**：一部分资金的实际来源及其核对状态，可保留出资方和项目归属；来源未明须保留待核对，不能自动猜测来源或把原有本金重复记作新到账。

**业务使用归属**：一次实际支出用于哪个项目或公司日常；与资金所在容器及出资来源分别说明，共用资金不等于复制项目余额。

**余额核对登记**：将经核对的余额及依据冻结留存，用于启用期初承接或经复核的后续更正；不是新到账、收入或垫资本金，已经包含的历史支出不得再次扣减。旧记录与来源保留，不能直接覆盖原正式事实。

## 避免使用

- **写入三本账**：同一事实不能为项目、公司和资金视角分别复制写入。
- **付款即成本**：付款只清偿应付款或往来，成本按对应业务事实确认。
- **最终余额入账**：不得用一个外部余额直接覆盖正式账；经核对的启用期初承接是冻结的历史依据，不代表新资金到账，后续系统余额仍由同一正式事实推导。
- **自动对账修正**：导入银行或财务资料只能辅助匹配，不得自动改写正式经营事实。

**公司互转**：我方不同公司账户之间经领导批准的真实资金划转；申请与实际出款、到账分别记录，按转存、临时借款调剂、归还已有往来区分后果。

**互转在途**：已实际出款而尚未确认到账或退回的本金；不作为接收公司已到账资金，不形成项目成本。

**公司自有资金归属**：明确不归属任何项目的资金；不能用随意指定项目代替，不能因未建立完整期初就展示为完整银行余额。
