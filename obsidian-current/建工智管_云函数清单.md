# 建工智管 - 后端模块清单

当前版本不再采用 41 个分散微信云函数作为主架构。旧标题“云函数清单”仅为历史兼容，当前真实后端是 Node.js + NestJS + PostgreSQL。

同步时间：2026-07-15。当前有 22 个 NestJS 业务/基础模块，以 `services/api/src` 实际代码为准。

## 当前 NestJS 模块

| 模块 | 说明 |
| --- | --- |
| `AppModule` | 应用入口，组装各业务模块 |
| `AuthModule` | Web 手机号密码登录、当前仍存在但待退出的微信登录入口、JWT、refresh、改密、权限 Guard |
| `OrganizationModule` | 部门、人员、全局/项目岗位、创建/停用、影响预览和权限完整性治理 |
| `ProjectModule` | 项目、项目经营总览、业主主合同、对上审定、实际收款、总包代付、例外结算额度、垫资额度 |
| `ProjectExpenseModule` | 零星付款、借款/备用金、综合费用（差旅/招待/报销最小闭环）等项目支出申请、审批、实付和资金池占用 |
| `ContractModule` | 合同主档、合同版本、状态机、审批、用章、归档 |
| `ContractTakeoverModule` | 历史合同接管、A/B/C 分级、历史余额快照、接管确认和付款前阻断 |
| `ContractWorkbenchModule` | 合同工作台 read/write、草稿、就绪校验 |
| `ContractTemplateModule` | 业务模板、版式模板、标准条款、预览、发布治理 |
| `ContractBillModule` | 合同清单、清单行、Excel 导入预览/应用 |
| `ContractDocumentModule` | DOCX/PDF 生成、附件归一、线下修订稿 |
| `BusinessPartyModule` | 合作单位档案、证照/身份证附件、合同多方快照 |
| `CompanyEntityModule` | 我方公司主体字典 |
| `SettlementModule` | 结算单、结算审批、结算归档、生效、结算附件模板下载 |
| `PaymentModule` | 付款申请、付款审批、实际付款、凭证、财务流水 |
| `ApprovalModule` | 审批冻结、会签/或签、撤回、退回、催办、转审、委托、审批单 PDF |
| `ArchiveModule` | 资料库归档检索、按项目可见性读取和授权下载入口 |
| `FileModule` | 私有文件上传、本地/COS 存储、下载权限、短时效票据、下载审计 |
| `PdfModule` | PDF 留档能力 |
| `AuditModule` | 审计记录、审计台账查询和敏感文件下载追溯 |
| `MeModule` | 当前用户能力，例如个人手写签名上传/预览 |
| `DatabaseModule` | Prisma 数据库访问 |

## 移动端与微信遗留边界

- 目标架构已改为桌面与手机共用响应式 Web，微信只用于打开普通 HTTPS 页面。
- 当前仍存在小程序目录、微信登录入口和 `wxOpenid`，属于待退出的运行时遗留，不再继续建设绑定、订阅消息或体验版。
- 运行时删除和数据库字段删除是两个独立生产单元；数据库字段只有在非空数据为零、备份和恢复演练通过并获得单独授权后才能删除。

## 定时任务与提醒

当前审批超时催办已有实例动作接口和节流逻辑。以下仍可作为后续定时任务补齐：

- 合同到期提醒。
- 待付款到账期提醒。
- 数据库备份检查。
- 审计日志归档检查。
- 站内、邮件或企业现有渠道的可审计提醒；不新增微信订阅消息依赖。

## 关键后端原则

- 所有权限在后端校验。
- 所有金额变动在数据库事务中完成。
- 文件下载必须鉴权并记录审计。
- 审批实例提交后固化流程。
- 历史结算和付款绑定当时的合同版本和付款条款版本。
- 历史合同接管后的历史余额必须参与后续付款容量控制。
