# 建工智管 - 审批流

当前第一阶段只建设审批与合同付款闭环相关流程。其他完整方案中的审批类型后续阶段建设。

同步时间：2026-07-01。当前代码已覆盖合同、结算、付款三类审批的冻结实例、会签、或签、撤回、催办、转审、委托、驳回上一节点、打回申请人和审计留痕；生产上线前仍需在真实组织岗位数据下做 UAT。

## 第一阶段审批流

| 编号 | 审批流 | 是否进入第一阶段 | 说明 |
| --- | --- | --- | --- |
| 1 | 合同签订审批 | 是 | 合同部编制，最终到董事长/总经理或签 |
| 2 | 合同变更/补充协议审批 | 是 | 生成新合同版本 |
| 3 | 用章申请 | 是 | 合同审批通过后自动触发 |
| 4 | 结算审批 | 是 | 不经过董事长/总经理 |
| 5 | 付款审批 | 是 | 所有付款都需董事长/总经理或签 |
| 6 | 报销审批 | 后续阶段 | 不纳入当前上线验收 |
| 7 | 借款申请 | 后续阶段 | 不纳入当前上线验收 |
| 8 | 备用金申请 | 后续阶段 | 不纳入当前上线验收 |
| 9 | 物资领料审批 | 后续阶段 | 与成本、材料核销联动 |
| 10 | 请假/考勤 | 后续阶段 | 与人事考勤模块联动 |
| 11 | 入职/离职/调岗 | 后续阶段 | 与组织权限变更联动 |

## 合同签订/变更审批

```text
合同部成员编制合同和付款条款
  → 物资类：物资主管
  → 机械/劳务/专业分包类：项目总工
  → 合同额 ≥ 100 万或特定类型：工程技术部
  → 合同部主管 + 预算部主管会签
  → 项目经理
  → 财务总监
  → 董事长/总经理或签
  → 自动触发用章审批
  → 综合部主管
  → 项目经理
  → 用章通过
  → 合同部成员上传盖章归档件
  → 合同部主管确认归档
  → 合同版本生效
```

董事长和总经理节点为或签。

合同生效后不允许直接修改原条款。合同条款变化必须走合同变更或补充协议审批，并生成新合同版本。

## 结算审批

结算审批不经过董事长/总经理。

物资类/机械类：

```text
合同部成员编制结算单
  → 物资员
  → 物资主管
  → 合同部主管 + 预算部主管会签
  → 项目经理
  → 财务总监
  → 合同部成员上传签章归档件
  → 合同部主管确认归档
  → 结算单生效
```

劳务/专业分包类：

```text
合同部成员编制结算单
  → 工长
  → 项目总工
  → 工程技术部
  → 合同部主管 + 预算部主管会签
  → 项目经理
  → 财务总监
  → 合同部成员上传签章归档件
  → 合同部主管确认归档
  → 结算单生效
```

未生效合同不能创建结算。未归档确认的结算不能发起付款。

## 付款审批

付款必须基于已生效结算单发起。

```text
付款申请
  → 项目经理
  → 财务总监
  → 董事长/总经理或签
  → 审批通过待付款
  → 出纳/财务人员实际付款
  → 上传付款凭证
  → 已付款或部分付款
```

付款审批通过不等于已付款。

同一结算单支持分批付款，系统必须控制累计申请和累计付款不超过合同条款允许额度。

## 审批引擎规则

- 审批实例提交后固化流程。
- 支持会签和或签。
- 支持条件节点，例如合同额 ≥ 100 万。
- 支持转审。
- 支持审批代理。
- 支持撤回。
- 支持驳回到上一级。
- 支持打回发起者重来。
- 审批超时只催办，不自动通过、不自动升级。
- 所有审批动作写入审计日志。
