## 第二周：理解数据库

### Day 1-3：学习数据建模基础

**前置知识（先花 2 小时看）：**
- 什么是关系型数据库？
- 什么是表、字段、主键、外键？
- 什么是一对多、多对多关系？

**任务：**
1. 打开 `services/api/prisma/schema.prisma`
2. 一个一个模型地看，对照 [[建工智管_数据库]] 笔记
3. 画一张关系图：哪些表通过什么字段关联

**重点理解的模型：**
```
User ──→ UserPosition ←── Position
  │
  └──→ ProjectMember ←── Project
                              │
Contract ←────────────────────┘
  │
  └──→ ContractVersion
         │
         └──→ PaymentTermsVersion
                │
                └──→ PaymentTermsStage

Settlement (绑定 Contract + ContractVersion + PaymentTermsVersion)
  │
  └──→ PaymentRequest (绑定 Settlement + Contract + Version)
         │
         └──→ PaymentExecution (实际付款)
```

### Day 4-5：理解状态机

**任务：**
1. 打开 `packages/shared-domain/src/statuses.ts`
2. 理解合同、结算、付款各自有哪些状态
3. 理解状态如何流转（参考下面的图）

**合同状态流转：**
```
draft → in_approval → approved_pending_seal → in_seal
  → seal_approved_pending_archive → pending_archive_confirm → effective
```
也可能会被驳回：`approval_rejected`，或被作废：`voided`

**结算状态流转：**
```
draft → in_approval → approved_pending_archive → pending_archive_confirm
  → effective → partially_paid → paid
```

**付款状态流转：**
```
draft → in_approval → approved_pending_payment → partially_paid → paid
```

### Day 6-7：学习金额处理

**任务：**
1. 打开 `packages/shared-domain/src/money.ts`
2. 理解为什么用"分为单位"存金额
3. 运行测试：理解金额校验逻辑

## 第三周：看懂后端 API

### Day 1-2：学习 NestJS 基础

**前置知识（先花 4 小时看 NestJS 官方文档第一章）：**
- Module、Controller、Service 是什么关系？
- Decorator（`@Get()`、`@Post()`、`@Body()`）是干嘛的？
- 依赖注入是什么？

### Day 3-4：跟踪一个完整请求

**任务：选一个最简单的读接口跟踪**

以 "查看合同详情" 为例：

```
前端请求 GET /contracts/:id
    ↓
contract.controller.ts 的 @Get(':id') 方法收到请求
    ↓
调用 contract-read.service.ts 的 findOne() 方法
    ↓
service 用 prisma.contract.findUnique() 查数据库
    ↓
返回给 controller → controller 返回给前端
```

**代码对应：**
1. `contract.controller.ts` — 路由处理器（守门员）
2. `contract-read.service.ts` — 业务逻辑（做事的人）
3. `prisma/schema.prisma` — 数据模型定义
4. 在 controller spec 测试中看如何模拟请求

### Day 5-6：理解认证和权限

**任务：**
1. 打开 `auth/auth.controller.ts` — 登录接口
2. 打开 `auth/auth.service.ts` — JWT 生成、验证
3. 打开 `auth/guards/jwt-auth.guard.ts` — 拦截未登录请求
4. 打开 `auth/guards/permission.guard.ts` — 检查用户角色
5. 打开 `packages/shared-domain/src/permissions.ts` — 权限策略表

**关键流程：**
```
用户登录 → 生成 JWT token
    ↓
后续每次请求带 Authorization: Bearer <token>
    ↓
JwtAuthGuard 验证 token → 提取用户信息
    ↓
PermissionGuard 检查用户角色 → 允许/拒绝
```

### Day 7：运行测试

**任务：**
1. 学会在终端运行 `pnpm test` 看测试结果
2. 选一个简单的测试文件，理解它测了什么
3. 推荐从 `shared-domain` 的测试开始看（纯逻辑，不依赖数据库）

## 第五周+：核心业务逻辑

### 审批引擎（难度：★★★★★）

这是项目最复杂的部分。建议先看懂概念再看代码。

**审批引擎做什么？**
- 定义了审批流模板（哪些节点、哪个角色审批）
- 提交审批时"冻结"当前流程（固化，后续模板改了不影响已提交的）
- 按节点顺序找人审批
- 支持会签（所有人同意）、或签（任一人同意）
- 支持驳回、撤回、转审、委托

**关键文件：**
1. `packages/shared-domain/src/approval.ts` — 审批动作定义
2. `services/api/src/approval/approval-freeze.service.ts` — 冻结节点服务

### 合同状态机（难度：★★★★）

**关键文件：**
1. `services/api/src/contract/contract.service.ts` — 合同 CRUD + 状态流转
2. `services/api/src/contract/contract-status.service.ts` — 状态校验
3. `services/api/src/contract/contract-read.service.ts` — 详情查询

### 付款金额校验（难度：★★★）

**关键文件：**
1. `services/api/src/payment/payment-amount.service.ts` — 付款金额校验
2. `packages/shared-domain/src/money.ts` — 金额计算

**核心逻辑：**
```
本次申请金额 ≤ 结算可付金额 - 已审批待付款 - 已实际付款
```

## 如何参与开发？

### 从小的开始

1. **修一个小 bug**：比如某个页面的文案错误、样式问题
2. **补一个单元测试**：找测试覆盖率低的模块，加测试用例
3. **加一个字段显示**：在详情页加一个已有字段的展示

### 开发流程

1. 先读 `PROGRESS.md` 了解当前进度
2. 读 `AGENTS.md` 了解项目约束
3. 拉最新代码 `git pull`
4. 改代码
5. 运行测试 `pnpm test`、类型检查 `pnpm typecheck`、代码检查 `pnpm lint`
6. 更新 `PROGRESS.md`
7. 提交 `git commit` + `git push`

### 需要的工具

1. **VS Code** — 代码编辑器
2. **Docker Desktop** — 用于本地启动 PostgreSQL
3. **Node.js 20+** — 运行后端
4. **pnpm 9+** — 包管理器
5. **Git** — 版本控制

## 遇到不懂的怎么办？

1. **先看项目文档**：Obsidian 笔记里的 `建工智管_*.md` 文件
2. **看 AGENTS.md**：项目约束规则
3. **看测试代码**：测试用例往往是最好的使用文档
4. **问 AI**：把代码片段贴给 AI 解释
5. **运行起来**：让代码跑起来，加 `console.log` 看运行结果
