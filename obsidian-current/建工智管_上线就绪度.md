## 已具备的上线基础

- Web/API 已部署到腾讯云轻量应用服务器，`jgzg.site`、HTTPS 和基础安全响应头可用。
- PostgreSQL 不对公网开放，数据库迁移和备份/恢复脚本已存在。
- 腾讯 COS 私有桶、中文文件名上传/绑定/授权下载和审计已有生产验证记录。
- 合同、结算、付款、实付、凭证、财务记录、PDF 和审计主链路有后端实现。
- 金额使用分值 BigInt、高精度 Decimal、数据库事务和关键行锁。
- 项目可见性、岗位权限、委托、敏感动作二次确认和审计已形成基础闭环。
- 自动部署、typecheck、lint、单元测试、构建和 UI 规则已进入 CI。
- 当前全量本地验证为 3,198 个测试通过，P0 E2E 32 通过、2 个按环境条件跳过。

## 发布版本边界

当前公网生产运行 `origin/main` 的 `c1fcd236`。本地 `main` 另有 5 个 P0/P1 UI 提交，响应式治理分支再多 10 个提交；当前候选相对公网生产涉及 126 个文件。

因此下一次 UI 上线必须作为独立发布候选验收，不得把“本地测试通过”直接等同于“生产已部署”。发布前必须固定目标 SHA、变更清单、截图、测试结果和回滚方式。

## 正式扩大使用前的 P0 门禁

| 门禁 | 最小验收标准 |
| --- | --- |
| 真实历史合同接管 | 约 20 份合同完成分级、资料、余额来源和业务复核；缺资料不得释放付款 |
| 3-5 条真实长链路 | 合同/归档/结算/付款/实付/凭证/审计由真实岗位跑通 |
| 合同母版和业务场景 | 合同部/法务逐页验收 DOCX，业务场景与模板映射可实际创建合同 |
| 普通账号权限 UAT | 不同项目的列表、详情、附件、直接 URL 和写操作均符合岗位范围 |
| 财务幂等 | 网络超时、重复点击、并发请求不会形成重复实付或重复入账 |
| 数据库历史约束 | 对 `NOT VALID` 约束覆盖的数据做只读一致性检查，再安排受控验证迁移 |
| 依赖安全 | 5 个中等级别依赖公告完成适用性判断、升级/接受/缓解记录 |
| 发布安全 | 部署前备份、人工批准、部署后深度健康检查和失败回滚可演练 |
| 运行保障 | 数据库、COS、API、磁盘和关键任务有可验证监控与告警 |
| Go / No-Go | 用户、业务负责人和技术共同形成明确结论，不额外建设签字审批模块 |

## 当前运维缺口

- `/api/health` 当前主要证明 API 进程响应，不会检查数据库或 COS。
- `main` 推送会自动部署，工作流尚无生产 Environment 人工批准门。
- 远程部署没有自动执行数据库备份、原子版本切换或自动回滚。
- 数据库迁移已成功但应用部署失败时，恢复仍依赖人工操作。
- 本机备份脚本已具备，但异地保留、自动清理和定期恢复演练需要制度化。
- 缺少请求关联 ID、结构化请求日志、指标/APM 和前端异常上报。

## 当前安全注意事项

- Web access/refresh token 仍保存在 `localStorage`，公网尚无 CSP；需要独立认证安全专项。
- 登录/刷新限流主要依赖 Nginx，需保留真实配置和压力验证证据。
- COS 直传会把文件整体读入 API 内存，大文件并发需做容量验证。
- 下载票据和下载原因位于 URL 查询参数，后续宜改成不暴露业务信息的一次性票据。
- 生产密钥不得进入仓库、截图、日志或客户端；应记录轮换责任人和周期。
- HTTPS 证书有效期至 2026-09-29，应在到期前确认自动续期任务实际执行成功。

## 移动端边界

目标为桌面与手机共用响应式 Web。当前小程序、微信登录入口和 `wxOpenid` 仍存在，退出尚未实施；不再安排 AppID、体验版和真机验收。

小程序运行时清理与数据库字段删除必须分开执行。数据库字段删除只有在生产非空数据为零、最新备份、临时恢复库演练和单独授权全部满足后才允许进行。

## 推荐推进顺序

1. 固定当前生产 SHA 和下一次候选 SHA，不混合发布。
2. 完成依赖公告、财务幂等和数据库历史约束的只读技术审查。
3. 补齐发布前备份、人工批准、深度健康和回滚演练。
4. 用普通岗位账号完成跨项目权限 UAT。
5. 完成历史合同批量接管、母版/场景签认和 3-5 条真实长链路。
6. 只修阻断真实使用的 P0/P1，重新跑全量门禁。
7. 形成 Go / No-Go 结论后分阶段发布 UI 候选。
8. 试运行稳定后再处理包体、长文件拆分、可观测性和认证安全专项。
