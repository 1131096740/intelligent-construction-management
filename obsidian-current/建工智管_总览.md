# 建工智管 - 总览

建工智管是建筑企业项目经营管理系统，不是单纯微信小程序。

## 当前版本定位

当前版本为第一阶段 MVP，主线是 **审批与合同付款闭环**。

当前实现状态同步时间：2026-07-04。

后端核心闭环与 Web 管理端第一阶段核心能力已基本收口：合同工作台、真实合同 Word/PDF 生成、线下修订稿上传、历史合同接管、历史余额付款容量扣减、真实首页待办、业务选择器、合同/结算/付款审批、用章归档、项目付款审批表 PDF、结算附件模板下载、综合费用最小付款闭环、实际付款、凭证、财务流水、PDF 留档、私有文件、审计、权限和二次确认均已具备本地验收能力。Web/API 已完成首版公网部署和 HTTPS，仍需 COS 实配、真实组织/岗位/项目初始化、停用 seed 通用密码、备份恢复演练、日志告警、合同母版人工逐页验收和生产等价环境复验。

当前上线试运行边界已经明确：先做 **1 个真实项目 + 约 20 个已签在执行历史合同接管 + 3-5 个活跃合同跑后续结算/付款闭环**。历史合同不重走合同审批和用章审批，而是通过补录、归档、历史余额初始化和业务确认建立系统事实起点；试运行开始后的新合同、新结算、新付款、实付、凭证和归档必须进入系统。

系统由三部分组成：

- Web 管理端：企业主系统。
- 微信小程序端：移动工作端。
- 统一后端：业务规则、权限、审批、文件、PDF、审计中枢。

## 第一阶段主线

```text
历史已签合同接管
  → 基础信息、合同类型、附件、付款条款和历史余额补录
    → 合同部/预算/财务/项目负责人确认
      → 建立系统事实起点
        → 后续结算申请
          → 结算审批
            → 结算归档确认
              → 结算生效
                → 按合同发起付款申请
                  → 系统扣减历史已付、已批待付、总包代付和预付款扣回
                    → 付款审批
                      → 审批通过待付款
                        → 出纳/财务实际付款登记
                          → 付款凭证、财务流水、PDF 留档、审计
```

真实试运行还纳入 P0-7 常用单据：项目付款审批表 PDF 必须贴近公司真实审批表；收方单、签工单、零星机械签认单、台班记录表提供模板下载后线下填写并上传归档；差旅、招待、报销先走最小综合费用付款闭环，不做完整 OA 报销。

少量新签合同仍走完整合同工作台链路：合同编制、DOCX/PDF 初稿、合同审批、用章审批、签章归档确认、生效，再进入结算和付款。

## 技术架构

| 端 | 技术 |
| --- | --- |
| Web 管理端 | Vue 3 + TypeScript + TDesign Web + Vite |
| 小程序端 | 原生微信小程序 + TDesign 小程序 |
| 后端 | Node.js + NestJS + PostgreSQL |
| 文件 | 本地私有存储 / 腾讯云 COS 私有桶，经后端鉴权访问 |
| 部署 | 腾讯云轻量应用服务器 |

## 核心原则

- Web 是主系统，小程序是移动工作端。
- 所有业务规则在后端执行。
- 合同、结算、付款必须强顺序绑定。
- 合同和结算必须上传归档件并确认后才生效。
- 付款审批通过不等于已付款。
- 合同付款条款版本化，历史结算和付款按当时版本追溯。
- 历史合同接管后的历史余额必须进入后续付款容量控制，不能只展示不控制。
- 不做固定 IP 白名单，采用强身份、强权限、私有文件、全审计。
