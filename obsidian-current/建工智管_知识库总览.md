# 建工智管 - 知识库总览

> 面向新手小白的入门指南。不要求有任何编程基础，从零理解这个项目。

---

## 一、这个项目是做什么的？

**建工智管** = 建筑工程项目智能化管理。

简单说：这是一个帮建筑公司管理「项目合同、付款、审批」的系统。

举例说明：

- 公司签了一个 500 万的施工合同 → 在系统里录入合同 → 领导们线上审批 → 盖完章后归档
- 公司已有一个正在执行的项目，里面有约 20 个已签合同 → 在系统里补录接管 → 确认历史结算和已付余额 → 后续结算付款从系统继续
- 每个月要给施工队结算 → 在系统里发起结算单 → 走审批 → 归档
- 到了付款节点 → 从系统发起付款申请 → 领导审批 → 财务打款 → 上传银行回单
- 差旅、招待、报销这类真实常用费用 → 先作为项目综合费用走最小付款申请、审批、实付、凭证和审计闭环

所有这些步骤都在系统里有记录、可追溯、可审计。

## 二、系统有哪些组成部分？

想象一家公司的工作方式：

| 部分 | 比喻 | 谁用？ |
|---|---|---|
| **Web 管理端** | 公司办公室的大电脑 | 合同部、财务部、项目经理在电脑上管理合同、审核付款 |
| **响应式 Web** | 办公室电脑和手机浏览器共用的工作入口 | 合同、财务、项目和管理人员按权限办理业务 |
| **后端服务** | 公司的"大脑" | 不直接给人用，负责处理所有数据、规则、权限 |

前后端的关系：Web 只负责**展示和交互**，所有**业务规则和判断**都在后端做。就像 ATM 机的屏幕只管显示，真正判断余额够不够的是后台服务器。仓库当前仍有旧小程序骨架，但已确定退出，不再作为目标客户端。

## 三、用到的技术是什么？（通俗版）

### 前端部分

| 技术 | 通俗解释 |
|---|---|
| **Vue 3** | 一个帮你快速搭建网页界面的框架，就像搭乐高一样拼组件 |
| **TypeScript** | JavaScript（网页语言）的升级版，加了类型检查，写代码时更容易发现错误 |
| **TDesign** | 腾讯开源的一套界面组件库，提供现成的按钮、表格、表单，不用自己画 |
| **Vite** | 一个超快的"打包工具"，把你写的代码变成浏览器能跑的网页 |
| **Pinia** | Vue 的状态管理库，可以把登录信息、用户数据存在一个地方让所有页面共享 |

### 后端部分

| 技术 | 通俗解释 |
|---|---|
| **Node.js** | 让 JavaScript 可以在服务器上运行的技术（以前 JS 只能在浏览器里跑） |
| **NestJS** | 一个 Node.js 框架，帮你把后端代码组织得井井有条（像搭积木一样分模块） |
| **PostgreSQL** | 一个免费的数据库，用来存所有数据（用户、合同、付款记录） |
| **Prisma** | 数据库的"翻译官"，让你用 TypeScript 代码操作数据库，不用写 SQL |
| **JWT** | 登录令牌技术，登录后发一个令牌，以后每次请求带着它证明身份 |

### 工程工具

| 工具 | 说明 |
|---|---|
| **pnpm** | 包管理器，管理项目依赖的第三方库 |
| **Git / GitHub** | 版本控制，记录每次代码修改，可以回溯历史 |
| **Docker** | 把数据库等环境打包成"容器"，一键启动开发环境 |
| **monorepo** | 把前端、后端、共享代码放在同一个仓库里管理 |

## 五、核心业务流程

第一阶段只做最重要的：「合同 → 结算 → 付款」

```
合同部编合同
  ↓
合同部录入付款条款（分几期付？每次付多少？什么条件？）
  ↓
一路审批：物资部 → 项目总工 → 合同部+预算部会签 → 项目经理 → 财务总监 → 董事长/总经理
  ↓
用章审批：综合部主管 → 项目经理
  ↓
合同部上传盖章归档件 → 合同部主管确认 → 合同生效
  ↓
（合同生效后，才能做结算）
  ↓
合同部编制结算单（这个月干了多少活？该付多少钱？）
  ↓
结算审批（两条路：物资机械类 / 劳务专业分包类）
  ↓
上传签章结算单 → 合同部主管确认 → 结算生效
  ↓
（结算生效后，才能申请付款）
  ↓
付款申请 → 项目经理 → 财务总监 → 董事长/总经理 → 待付款
  ↓
出纳打款 → 上传银行回单 → 财务记录 → 结束
```

**关键规则：**

- 合同没盖章归档不能做结算
- 结算没签字归档不能申请付款
- 付款审批通过了 ≠ 钱已经付了（需要出纳真正打款才算）
- 同一个结算可以分多次付款
- 历史合同接管后，历史已付、已批待付、总包代付和预付款扣回都要扣减后续可付款金额
- 每个动作都有审计记录，谁在什么时间做了什么

## 六、核心角色（谁做什么？）

| 角色 | 干什么 |
|---|---|
| **董事长 / 总经理** | 最终拍板，合同和付款的最后一关（两人任一人批就行） |
| **项目经理** | 项目老大，合同/结算/付款都要经过他 |
| **财务总监** | 管钱的，合同/结算/付款都要财务审核 |
| **出纳 / 财务人员** | 真正执行打款的人，上传银行回单 |
| **合同部主管** | 审核合同和结算，确认归档 |
| **合同部成员** | 编制合同、录入付款条款、上传归档文件 |
| **预算部主管** | 预算复核与可选审批，不承担当前合同变更和结算的强制节点 |
| **物资主管 / 物资员** | 管物资类合同和结算 |
| **项目总工 / 工长** | 管劳务和分包类合同结算 |
| **工程技术部** | 100 万以上大合同要他们审核 |
| **综合部主管** | 管盖章（用章审批） |

## 七、关键概念解释

| 概念 | 解释 |
|---|---|
| **合同版本** | 合同签完后不能直接改。如果要改，走"补充协议审批"，生成新版本。历史结算引用的是当时的合同版本。 |
| **付款条款版本** | 付款条款（分几期、每期多少比例）也是版本化的。改了条款就生成新版本。 |
| **结算单** | 每个月或每个施工节点，确认实际完成了多少工作，该付多少钱的单据。 |
| **付款申请** | 基于有效的结算单发起的付款请求。 |
| **实际付款** | 出纳真正打款并上传银行回单后才算。 |
| **归档件** | 盖章合同/签字结算单的扫描件，必须上传并由主管确认后才生效。 |
| **历史合同接管** | 对已经签完、正在执行的老合同，不重新走审批，而是补录合同、附件和历史余额，经业务岗位确认后作为系统事实起点。 |
| **会签** | 一个节点配置多个必签角色时，必须全部同意才能通过；当前引擎仍保留该能力。 |
| **或签** | 多个角色任意一人同意就行。比如董事长「或」总经理任一人批就行。 |
| **审计日志** | 记录谁在什么时间做了什么操作，方便追责。 |
