# 开发与隔离验证规程

生效：2026-11-13；验证节奏修订：2026-11-22。本文规定已授权开发的执行方式；当前任务和优先级以当前主控的 PROGRESS 与 Issue 依赖为准。历史单次执行记录保留，不作为未来普通开发的逐次审批要求。

## #382 持续开发授权

用户原话：
> 同意，按这套提速方案落地，更新项目开发规则并应用到 Issue #382。授权在独占隔离环境中使用虚构数据，反复进行测试迁移、调试、修复和验证，普通失败后无需逐次申请。生产和真实数据操作仍单独确认，优先打通任务12、16的完整业务链。

在已确认规格范围内，授权覆盖独占隔离资源上的测试迁移、真实受限角色/客户端、虚构业务、故障注入、并发、本地文书转换、诊断修复验证及本轮自建资源清理。候选变化后记录新指纹并复验受影响部分；同范围继续开发不重新申请。已确认公开HTTP/服务/Web测试接缝持续适用；技能中的首次确认要求不得变成同一边界逐用例审批。

旧once目录、令牌和失败回执封存；为新运行生成独立标识及新候选材料。可最小修改执行入口以消费本次持续开发授权，但保留身份、资源归属、权限、事务、审计与清理检查，不能用关闭保护来过验收。

生产、真实数据、状态不明或共享资源、真实云服务写入及新增费用不在本授权内，仍须单独明确确认。Git操作遵循已有具体授权，本规程不新增main合并或发布授权。

## 失败处理

| 情况 | 执行动作 |
| --- | --- |
| 普通代码、配置、测试库权限或非预期测试失败 | 停止当前失败运行，保存脱敏首因；自行诊断、最小修复并复验；无共享影响的其他工作继续 |
| 预期故障注入 | 核对回滚、持久事实、幂等及审计断言，满足则该用例通过 |
| 业务结果未知 | 按原幂等键查询；查不清保留未知并停止该场景，不换键盲重发 |
| 误连环境、身份/归属不明、边界失守、清理失败 | 停止受影响资源操作，保留证据并报告；不处理陌生资源 |

同一失败连续出现两轮，先缩小复现或补可定位的诊断，禁止无新信息原样重跑。失败记录不能被后继成功覆盖。

## 验证节奏

| 阶段 | 执行范围 | 完成判据 |
| --- | --- | --- |
| 定位与修复 | 原失败用例或最窄行为检查；数据库语义问题直接用相关 SQL/受限角色的最小真库复现 | 得到可定位首因，修复后原行为通过 |
| 业务片交付 | 相关回归与受影响包 typecheck/lint；Web UI 加 check:ui；按影响补真实接口/事务检查 | 本片业务行为可演示，相关检查通过，未验证部分明确 |
| 集成与最终验收 | 对最终候选执行 Issue/运行手册规定的完整 CI、真实数据库及必要浏览器/文书门 | 各项结果绑定准确候选，规定验收项齐全 |
| 文档维护 | 内容、指针和差异检查 | 无失效引用或规则冲突；不触发应用测试 |

小步修改先走窄检查，形成连贯业务片后再做包级检查和规定审查。同一候选未变化的成功检查复用；已有命令、检查或 CI 能回答问题时，直接使用。金额、权限、状态、归档、PDF 和审计行为变化必须做相关后端回归；数据库语义、迁移或 Nest/Prisma/数据库接缝变化必须补相应真实隔离验证，模拟不能替代真实事务证明。每次改动按下一小节的档位取得必做清单；分档表与本节其他表述冲突时，以分档表为准（取高档）。

### 变更分档与必做检查

按改动**实际触碰的风险**分档，不按票的大小分档。同一变更内取最高档；判断不了升一档。

| 档位 | 触发条件（满足任一） | 必做检查 | 可省略 |
| --- | --- | --- | --- |
| **T1 资金与不可逆** | `services/api/prisma/migrations/**`、`services/api/prisma/schema.prisma`、任何 `*.sql`；`services/api/src/**` 或 `packages/shared-domain/src/**` 中路径含金额/结算/合同/审批/权限/审计/归档/台账/现金/垫资/往来/退款/转账/凭证/精度等关键词 | 受影响后端回归；真实隔离 PostgreSQL 16（受限角色、一次性容器）；页面或文书受影响时加浏览器/文书门；主回执记录候选、命令、结果与未覆盖边界 | 无 |
| **T2 业务行为** | 其余 `services/api/src/**`、`apps/web-admin/src/**`、`packages/**` | 相关单测/回归；受影响包 `typecheck`、`lint`；Web 改动加 `check:ui` | 真实库门（未触碰事务、约束、迁移时不新增） |
| **T3 展示与文档** | `docs/**`、`*.md`、`.github/**`、`scripts/**`、样式与静态资源 | 引用/清单检查（`inspect:* --check`）；Web 可见改动加 `check:ui` | 真实库门、完整 CI |

分档由 `node scripts/verify-verification-tier.mjs --explain` 按改动路径自动计算；判定规则源码在该入口的 `TIER_RULES`，本表是它的说明，冲突时以脚本为准。

**声明与执行：**

- PR 正文必须写一行 `验证分档: T1|T2|T3`。低于自动计算值的声明被拒绝；高于自动计算值允许（自愿升档）。
- CI 在 `quality-gates` 的 `Verify change verification tier` 步骤执行同一入口；缺声明或降档即失败，不靠自觉。
- 推送前先跑 `pnpm verify:verification-tier:local`，得到同一份判定与必做清单。
- 新入口有 `scripts/verify-verification-tier.test.mjs` 覆盖，规则改动必须让它保持通过。

**不因分档而省略的**：金额与状态唯一终态、权限越权与自审、迁移可回滚、审计与文件哈希——即使只改一行也按 T1 走。

**分档不替代整票验收**：一票可分段交付，各段按自身改动定档并复用已有回执；整票关闭仍按 Issue 的验收范围与验收情景，分档只决定每段必做哪些检查。

### 结果复用

先核对代码、依赖、配置和涉及的不变量，列明本轮受影响检查。无影响的页面、版式、工具或业务回执沿用原范围；迁移变化要核对相关数据/权限影响，不自动使所有页面或文书回执失效。文书复用同时核模板、转换器、字体和输入类别。影响无法判断时扩大相关检查。最终完整 CI 和规定门仍须在最终准确 SHA 上完成，旧回执不改写为新 SHA 的通过证据。

### 新增检查与审查

- 新增测试、检查器或包装层，按同一业务片在当前主回执合并简记对应的已发生故障、明确验收项或具体业务/安全不变量，以及现有检查的缺口；无需为每个用例另建回执或新增逐项审批。优先检查公开行为和持久业务结果，内部文件布局、调用次数或临时实现形状仅在本身属于受影响契约时锁定。
- 验收准备先用已有只读预览/清单检查用途名、候选、入口和输出目录，并核对本地与 CI 的实际入口。接线不一致时优先修正原入口，独立封包只证明其覆盖范围。包装错误先在最小入口修复并验证，再回到原业务场景；历史包和失败记录保留，身份、资源归属、权限、事务、审计和清理保护继续生效。
- 工具链只在自身变化、相关依赖变化或已观察到工具故障时补对应回归。诊断/清理链改动才验证首因与次因组合，普通业务修改不重复整套工具证明。既有用户明确的单次/停止条件与正式验收要求保持。
- 审查按任务要求覆盖连贯业务片及实际增量；阻断意见说明具体风险或未满足的验收项。可选风格、无关重构和假设场景记录后续，不扩成本片交付门；有明确规定的审查数量和最终门保留。

## 反馈与交付

1. 按上表选择当前阶段的检查；通过且无新影响后继续业务推进，按业务片完成判据交接。
2. 分别标记本地模型、真实隔离资源与 CI 结果，说明候选和覆盖范围。
3. 先测构建、安装、连接、装配、校验和业务分段耗时，再优化最慢环节。典型窄检查约1分钟、已准备环境冒烟约3—5分钟为优化目标，不是已达到的结果或放宽测试的理由。
   现有回执按候选和运行标识保留脱敏首因、HTTP状态或SQLSTATE及分段耗时；后置核验与清理错误另记次因，未知业务保持未知。记录本轮业务执行与准备/验证耗时，准备持续占主导时先缩小入口，不新增一轮无关全量检查。
4. 优先改进现有增量检查。开发基线可取上一已检查集成点并覆盖所有本轮差量；结果只证明差量，未知影响扩大检查。
5. 复用只读依赖与稳定工具，生成输出及可写缓存按树隔离。迁移/Schema/权限等变化使相关缓存失效；模板用于开发，正式迁移验收仍完整重放并核新实例身份。
6. 每片交付完整可演示行为，业务片完成后独审并集成。至多两条业务实现线，共享控制源码明确单一修改负责人，保护其他在制工作。
7. 规格与验收范围保留。依赖图需明确修订后才调整领取规则；分别记录准备产物、运行前置及业务验收状态，延期项注明承接任务与完成判据，不以源码准备或模型通过关闭整票。

业务链示例：任务16为登录→期初→实付→同键重放/查询→独立核账，再补受影响的故障/竞争/凭证/待办；任务12为提交→并联批准→盖章→归档→授权下载，再补规格矩阵。按当前任务的未证部分推进，已完成任务不因本段示例而重开。正常链通过只是里程碑，既定验收范围保留。

## 状态与证据

PROGRESS只写当前候选、两条工作线、已证业务、剩余阻断、授权指针及下一步；历史用既有收据链接。每次集成保留一份主回执，记录指纹、命令、范围、结果、耗时与产物，各参与者补自己的证据归属，不重复堆全文。评估提速用反馈时间和完整业务片周期，不用测试数量或封包数量代替业务完成。

进度查询引用同一主回执，列明新通过的业务行为、首要阻断和下一验证判据。百分比注明固定验收项分母，未验证或阻塞项单列；工期注明前提和下一校准点。
