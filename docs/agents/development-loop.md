## 失败处理

| 情况 | 执行动作 |
| --- | --- |
| 普通代码、配置、测试库权限或非预期测试失败 | 停止当前失败运行，保存脱敏首因；自行诊断、最小修复并复验；无共享影响的其他工作继续 |
| 预期故障注入 | 核对回滚、持久事实、幂等及审计断言，满足则该用例通过 |
| 业务结果未知 | 按原幂等键查询；查不清保留未知并停止该场景，不换键盲重发 |
| 误连环境、身份/归属不明、边界失守、清理失败 | 停止受影响资源操作，保留证据并报告；不处理陌生资源 |

同一失败连续出现两轮，先缩小复现或补可定位的诊断，禁止无新信息原样重跑。失败记录不能被后继成功覆盖。

## 反馈与交付

1. 每次修改先跑原失败用例和相关检查；通过后运行受影响包typecheck/lint，Web另做check:ui。现有机械质量检查在集成前执行。
2. 接缝改动使用真实Nest/Prisma/受限角色/PG验证；模拟与CI分别标记，不能代替真实事务证明。
3. 先测构建、安装、连接、装配、校验和业务分段耗时，再优化最慢环节。典型窄检查约1分钟、已准备环境冒烟约3—5分钟为优化目标，不是已达到的结果或放宽测试的理由。
   现有回执按候选和运行标识保留脱敏首因、HTTP状态或SQLSTATE及分段耗时；后置核验与清理错误另记次因。用业务失败叠加后置失败、业务失败叠加清理失败、请求已返回后资格核验失败三种反例验证首因不丢失，未知业务保持未知。
4. 优先改进现有增量检查。开发基线可取上一已检查集成点并覆盖所有本轮差量；结果只证明差量，未知影响扩大检查。最终候选仍完成准确SHA的规定完整门禁。
5. 复用只读依赖与稳定工具，生成输出及可写缓存按树隔离。迁移/Schema/权限等变化使相关缓存失效；模板用于开发，正式迁移验收仍完整重放并核新实例身份。
6. 每片交付完整可演示行为，业务片完成后独审并集成。至多两条业务实现线，共享控制源码明确单一修改负责人，保护其他在制工作。
7. 规格与验收范围保留。依赖图需明确修订后才调整领取规则；分别记录准备产物、运行前置及业务验收状态，延期项注明承接任务与完成判据，不以源码准备或模型通过关闭整票。
