建工智管企业流程系统前端改造可视化方案

这一版不是换技术栈，也不是引入大平台。目标是把 Flowable / 若依 / Yudao / JeecgBoot / O2OA / Snowy 里成熟的企业流程产品能力，压缩成能在现有系统里稳稳落地的前端方案。

保留架构 Vue 3 + TDesign + NestJS + PostgreSQL 优先解决 待办、动作、附件、审批、签名 不做 BPMN 设计器、低代码运行时、换底座

一、这轮调研得到的结论

BPM / 流程

学 Flowable / Yudao

借待办、已办、退回、撤回、或签、时间线。不引入 Java 流程引擎。

  • P0：工作池
  • P0：动作元数据
  • P0：审批时间线
表单 / 低代码

学 JeecgBoot

借分组表单、字典、附件控件、按钮权限、主子表。不要低代码运行时。

  • P0：详情分区
  • P0：文件卡片
  • P1：导入预检
OA / 签批

学 O2OA

借办公中心、待阅/已阅、附件分组、手写签批。不迁移 OA 底座。

  • P0：待我处理
  • P0：Canvas 签名
  • P1：签批进 PDF
后台治理

学 Snowy / 若依类后台

借菜单权限、按钮权限、操作日志、登录日志、字典和数据权限。

  • P0：日志可查
  • P0：权限可看
  • P1：字典统一

二、落地总路线

1

先修详情页

合同详情先改成可用流程页：动作、附件、时间线都从后端读模型来。

2

复制到结算付款

同一套动作区、资料区、审批时间线，复制到结算和付款详情。

3

首页变工作池

从查表入口变成待办入口：待我处理、阻塞事项、我发起的进行中。

4

签批闭环

审批、归档、付款实付接 Canvas 签名，后端保存并进入审计/PDF。

三、P0 / P1 / P2 看板

P0：现在就做

无 ID 文件下载附件从当前单据上下文选择，不再手填 fileId。
availableActions详情接口告诉前端能做什么、为什么不能做。
附件证据区文件名、用途、版本、上传人、下载/禁用原因。
审批时间线节点、处理人、意见、签名、耗时。
Canvas 签批板先接审批通过、归档确认、付款实付。
日志可查操作日志、登录日志、文件下载审计放进系统治理。

P1：稳定后做

最近打开先做最近 5 个单据，不做完整多页签框架。
转办 / 抄送先转办，不做复杂委派回流。
导入预检历史合同和结算清单导入前先校验。
签批固化 PDF签名进入审批单 PDF，不直接改原业务文件。
字典页面P0 代码枚举，P1 再给后台维护入口。

P2：先别碰

BPMN 设计器当前流程强业务约束，不让业务自由拖拽。
低代码表单引擎字段强约束，运行时配置会削弱测试和类型。
附件图标视图/版本对比可用性锦上添花，不是试运行阻断。
复杂委派/加签/减签容易破坏状态一致性，等真实需求。

十、UI/治理专项落地蓝图

这一轮专项调研的共同结论：后台 UI 要稳定、克制、可查。业务菜单和治理菜单分开；列表、详情、弹窗、日志都用统一套路。

治理面 借鉴做法 建工智管落地 优先级
导航 若依/Yudao/Snowy 都把业务菜单和系统治理分区。 左侧固定为工作台、合同、结算、付款、资料库、基础档案、系统治理。日志、权限、字典只放系统治理。 P0
工作台 O2OA 用待办、已办、待阅、已阅；Flowable 用 assignee、candidate、dueDate 管任务。 首页做待我处理、我发起的进行中、阻塞/逾期；候选岗位任务显示“我来处理”。 P0
列表 JeecgBoot/若依稳定采用查询区 + 表格 + 分页 + 操作列。 合同/结算/付款列表统一 4-6 个筛选：项目、状态、负责人、时间、金额；危险动作不放列表。 P0
详情 企业后台详情按摘要、信息、明细、附件、流程、日志组织。 合同详情先改成顶部摘要 + 页签分区；结算/付款复用同一结构。 P0
动作权限 成熟后台按钮可见性和后端权限要同源。 后端返回 `availableActions`、`primaryAction`、`disabledReason`；前端只渲染。 P0
数据权限 Yudao/JeecgBoot 有数据范围；但通用引擎复杂。 先在服务层按项目参与关系、岗位、业务状态过滤；不做通用 SQL 权限引擎。 P0
日志台账 若依/Yudao/Snowy/O2OA 都把登录日志、操作日志作为治理入口。 系统治理加登录日志、操作日志、文件下载审计、审批动作日志。全部脱敏，生产 UI 不提供清空按钮。 P0
字典 JeecgBoot/Yudao 用字典统一标签。 P0 用代码枚举 + 前端统一标签；P1 再做字典维护页，且不开放业务状态语义。 P1
导入导出 若依/JeecgBoot 导入导出走按钮权限和预检。 合同台账导入保留预检；列表导出当前查询结果；导入不直接写库。 P1
流程治理 Flowable 有任务认领、候选组、到期、优先级、历史。 OR 签/岗位池任务增加“我来处理”；工作池显示停留时长、逾期、优先级。 P0
配置治理 Snowy 把系统、登录、密码、文件、短信、邮件等配置分组。 P1 只做安全登录、文件下载、上传限制、通知开关四组；COS 密钥不在前端展示。 P1

P0 页面清单

  • 工作台：待办、阻塞、进行中。
  • 合同详情：摘要、附件、流程、审计。
  • 系统治理：登录日志、操作日志、文件下载审计。

P0 交互规则

  • 列表只查和进入详情，不做危险审批。
  • 详情只显示后端允许的动作。
  • 弹窗说明影响，再签名和确认。

暂不做

  • 完整多页签缓存。
  • 通用数据权限引擎。
  • 全量接口日志和日志清空按钮。
  • 流程设计器和低代码表单运行时。

十二、2026-07-09 合同工作台与模板库修订

当前结论

  • 设计语言方向统一：企业后台、高信息密度、浅灰边界、低饱和状态色。
  • 组件库依赖统一为 TDesign，不引入第二套 UI 库。
  • 已有薄 token 层，合同工作台和模板中心仍需继续替换硬编码样式。

一线工作台

  • 首屏只回答：这是什么合同、卡在哪、缺什么、我能做什么。
  • 按项目与相对方、核心信息、金额清单、付款条款、附件证照、文档生成、提交审批推进。
  • 只显示当前账号可办理动作，不展示永远不可点的按钮。

模板库模式

  • 使用模式：一线用户只选模板和新建合同。
  • 配置模式：合同主管/法务维护字段、条款、附件、版式、编号规则。
  • 发布必须经过检查、样张、签认和版本冻结。

本轮已落地

  • 英文权限和网络错误统一映射为中文。
  • 动作面板和合同/结算/付款详情动作组只展示可办理动作。
  • Excel 导出隐藏系统字段行，Word 模板改中文占位符。
  • 版式检查和文档渲染共用中文占位符注册表。
  • 版式页、条款库、编号规则、合同文档区去除一批 JSON、内部编号和英文格式文案。
  • 版式模板合同类型改为下拉选择，文件上传支持类型提示改为中文业务口径。

后续路线

  • P1：模板详情读模型，不再手填版本编号。
  • P1：合同工作台改成一线向导式流程。
  • P2：版式模板绑定业务模板版本，检查字段、条款、清单循环一致性。
  • P2：母版验收包自动生成，合同部/法务签认后发布。
