# 建工智管 Web Admin 中文业务语言规范与检查清单

日期：2026-07-09

## 目标

Web Admin 所有用户可见文字必须让业务人员看得懂、知道为什么、知道下一步。技术名可以留在代码、接口、数据库和内部日志里，但不能直接出现在页面、按钮、错误、空态、确认弹窗、导出文件名或审批记录中。

## 禁用技术词

| 禁用词 | 用户可见表达 |
| --- | --- |
| Forbidden | 当前账号暂无办理权限，并说明需要联系谁 |
| Invalid status transition | 当前单据状态不能办理，并说明下一步 |
| contractVersionId required | 请选择有效合同版本 |
| Missing required project role | 当前账号缺少该项目岗位权限 |
| Failed to fetch | 网络连接失败，请检查网络后重试 |
| snapshot | 审批稿 |
| workflow | 审批进度 |
| forceSave | 保存当前正文 |
| billItem | 合同清单项 |

## 改写格式

错误和禁用原因按三段写：

```text
发生了什么 + 为什么不能做 + 下一步怎么办
```

示例：

```text
当前合同还没有形成有效版本，不能发起结算。请先完成合同归档确认。
这张结算单已经提交审批，不能直接修改。如需调整，请先退回修改。
当前账号不是该项目合同人员，不能提交合同。请联系合同部主管调整项目人员。
```

## 页面检查清单

- 页面标题、按钮、表单项、表格列、空态和弹窗只使用中文业务名。
- 禁用按钮必须说明不能办的业务原因。
- 失败提示必须说明下一步，而不是只显示状态码或英文错误。
- 审批页面使用“审批稿、审批进度、审批意见”，不使用技术词。
- 合同、结算、付款页面使用“合同版本、付款条款版本、合同清单项、有效结算”等业务词。
- 导出文件名和 Excel 表头不得包含内部字段名。

## 自动检查

`pnpm --filter @jiangkong/web-admin check:ui` 已同时检查：

- 新增/触达页面是否绕开 TDesign 基础控件。
- 新增/触达页面是否继续硬编码颜色、阴影和高风险内联样式。
- 新增/触达页面和配置是否直接暴露高风险英文技术词。

当前检查是防回归闸门，不替代人工文案评审。业务含义不清时，优先让页面说清楚“谁能办、为什么、下一步找谁或做什么”。
