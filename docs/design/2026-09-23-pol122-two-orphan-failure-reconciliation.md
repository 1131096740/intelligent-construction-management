# #122 两个隔离文件清理：失败对账与恢复决策契约

状态：本地设计，尚未批准或实现生产恢复。适用范围仅为已签精确两文件计划及其全部已备份版本；不扩展为 POL-22 全量归零或普通文件删除入口。

## 停止与证据封存

任一命令失败、超时、进程消失或日志校验失败，保持 API 与全部数据库业务写、私有对象写冻结；不得再次执行同一批次，也不得换批次绕过失败。保留原始计划、签名授权、两类备份及隔离恢复证明、私有 `0700/0600` 链式日志、数据库审计和对象版本快照。仅在受限环境输出脱敏状态、数量及摘要，不输出对象键、秘密、姓名或手机号。

对账必须从同一候选 SHA、批次、数据库身份、Schema 摘要和冻结代际开始。只读验证计划与授权签名、日志链及每条事件的前序摘要；若任何一项失配，状态为 `evidence_invalid`，停止自动判断。随后在 `READ ONLY` 事务中核对两个精确 FileObject 主键、该批次数据库审计、其余记录完整行摘要；只读枚举已批准的两个对象键的全部版本，对照备份清单、`object_intent` 与 `object_deleted`。不读取文件内容，不对 COS 发 DELETE/PUT，不根据“请求返回错误”推断服务器一定未删除。

## 结果分类

| 可证明状态 | 必须同时成立 | 后续 |
| --- | --- | --- |
| `not_started` | 日志止于 `prepared`；两个目标行和全部版本仍与计划一致；无该批次删除审计 | 保留失败批次证据。只有新授权、新批次和新鲜全套预检可再次尝试。 |
| `database_rolled_back` | 已记录 `database_intent`，但两个目标完整行、其余记录及全部版本仍与计划一致，且无该批次删除审计；已排除仍在运行的事务 | 保留原批次证据。只有新授权、新批次和新鲜全套预检可再次尝试。 |
| `database_unknown` | 有 `database_intent`，但缺少可核验的提交回执，或数据库目标行与批次审计相互矛盾 | 保持冻结，调查数据库提交结果；不得依据进程退出码判定回滚。 |
| `database_committed_objects_pending` | 两个目标行均已不存在；唯一 `database_deleted` 审计匹配计划；保留行未漂移；对象版本与计划及耐久处置事件可逐项对齐 | 保持冻结。由独立授权在“精确继续收敛”与“数据库及对象协调恢复”中选择；当前 CLI 不提供自动续删。 |
| `object_outcome_unknown` | 存在 `object_intent`，但对应的 `object_deleted` 缺失，或版本集合与耐久事件不一致 | 保持冻结。逐版本只读查明实际状态；不得重发该 DELETE 请求。 |
| `completed` | 日志 `completed`、数据库完成审计、全部批准版本消失、保留行指纹不变且独立后检同批次通过 | 仅可用于该两个文件的清理收据；它不是 #122 全量归零终态。 |

上述分类按最不确定的证据取值。日志可核验但数据库或对象不可读取时，不能提升为 `not_started` 或 `completed`。若发现非目标行、对象版本、Schema、冻结租约或执行身份漂移，立即停在 `evidence_invalid`，不得用数量相同替代逐项一致。

## 恢复决策与交付边界

精确继续收敛须另设计受审的恢复命令、为当前剩余版本重新生成清单与签名授权，并证明不会重放任何已有 `object_intent`；本候选尚未实现。协调恢复须在新的停写与恢复授权下，从本窗口已验证的数据库及私有对象备份恢复到隔离环境先演练，再按批准顺序恢复正式环境并复核保留资料、文件绑定和对象全版本。不能仅恢复数据库或仅恢复对象。

每次人工决策应记录：候选 SHA、原批次/日志链摘要、数据库两目标与批次审计结论、两个对象的逐版本差异摘要、保留行摘要、备份恢复坐标、选择的处置路径、审批者及新授权、执行和独立后检结果。证据不齐或无法证明一致时，继续保持维护态，#122 不签发 `zeroing_receipt`，#123/#124 不启动。
