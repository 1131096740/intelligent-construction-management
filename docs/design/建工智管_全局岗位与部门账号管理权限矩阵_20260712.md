# 建工智管：全局岗位与部门账号管理权限矩阵

确认日期：2026-07-12

## 1. 基本原则

- 全局岗位通过 `UserPosition.projectId = null` 表示，对全部现有及未来启用项目生效。
- 项目岗位必须显式分配到项目，不得从全局岗位或其他项目岗位自动推导。
- 同一人员可以同时持有全局岗位和一个或多个项目岗位，各岗位只提供自身业务动作。
- `super_admin` 仅提供技术治理能力，不进入任何业务审批动作。
- 全局可见不绕过审批节点、会签/或签、自审、金额、状态和审计约束。

## 2. 全局岗位白名单

| 业务岗位 | role key | 范围 |
| --- | --- | --- |
| 董事长 | `chairman` | 全部项目 |
| 总经理 | `general_manager` | 全部项目 |
| 公司工程技术部部长 | `engineering_department_director` | 全部项目，最多一名启用人员 |
| 财务部成员 | `finance_staff` | 全部项目，不需要项目安排 |
| 财务部主管 | `finance_director` | 全部项目 |
| 合同部主管 | `contract_director` | 全部项目 |
| 预算部主管 | `budget_director` | 全部项目 |
| 物资部主管 | `material_director` | 全部项目 |
| 综合部主管 | `comprehensive_director` | 全部项目 |

`super_admin` 另作为全局技术岗位，可查看组织治理事实，但不自动获得业务动作。

未列入白名单的业务岗位即使错误写成全局记录，也不得因此看到全部项目；应由权限完整性检查提示修复。

## 3. 项目岗位

- `project_manager`：项目经理。
- `engineering_department_member`：公司工程技术部成员；这是项目级身份，只在明确加入的项目生效，且任命时必须已经持有同一项目的 `project_manager`。
- `engineering_director`：项目总工，不再表示公司工程技术部部长。
- `engineering_foreman`：工长。
- `engineering_tech`：项目工程技术人员。
- `contract_staff`：合同员。
- `budget_staff`：预算员。
- `material_staff`：物资员。
- `employee`：普通员工。

以上岗位只能在显式分配的项目中查看和执行业务。

## 4. 公司工程技术部

- 公司工程技术部成员必须由董事长从已经持有同一项目 `project_manager` 岗位的启用人员中按项目明确选择，不自动包含所有项目经理，也不形成全局项目可见性。
- 部长是全局岗位，但任命人必须先在至少一个项目中同时持有 `engineering_department_member` 和 `project_manager`，再由董事长任命。
- 同一时点最多一名启用部长；更换前必须预览在途审批影响并明确接替人。
- 劳务/专业分包结算路线固定为：工长 → 项目总工 → 公司工程技术部部长 → 合同部主管 → 项目经理 → 财务部主管。预算岗位保留，但不作为固定强制节点。
- 普通工程技术部成员不审批“公司工程技术部”节点。

## 5. 部门账号管理

所有账号创建、停用、调部门和授岗操作都必须使用操作者当前密码、影响预览、事务写入和审计。

| 管理岗位 | 可管理范围 | 可授予岗位 |
| --- | --- | --- |
| 董事长、总经理 | 全部部门及下属部门 | 全部业务岗位；`super_admin` 仍走技术治理专用流程 |
| 财务部主管 | 本部门及下属部门 | `finance_staff`；该岗位只允许全局范围，不安排项目 |
| 合同部主管 | 本部门及下属部门 | `contract_staff`，必须安排项目后才获得业务范围 |
| 预算部主管 | 本部门及下属部门 | `budget_staff`，必须安排项目后才获得业务范围 |
| 物资部主管 | 本部门及下属部门 | `material_staff`，必须安排项目后才获得业务范围 |
| 公司工程技术部部长 | 工程条线部门及下属部门 | `engineering_director`、`engineering_foreman`、`engineering_tech`，必须安排项目 |
| 综合部主管 | 暂无下属岗位 | 暂不显示创建员工和安排项目入口 |

补充约束：

- 同级部门主管不能互相管理。
- 部门主管不能修改自己、给自己扩权或跨部门管理。
- 项目经理不能自行拉人进入项目。
- 项目可从全部启用项目中选择；部门主管只能安排自己管理范围内的人员。
- 创建账号只填写登录手机号、所属部门、初始岗位和项目；姓名显示“待本人确认”，首次登录时本人填写真实姓名并强制改密。
- 停用前阻止：停用自己、最后一个启用全局管理员、存在当前审批待办、有效委托、未交接关键项目岗位或未输入当前密码。
- 停用成功立即撤销全部 refresh token，并记录审计。

## 6. 敏感文件

- 所有全局岗位白名单账号及全局 `super_admin` 可以下载全部项目的敏感文件。
- 下载仍必须输入当前密码、填写下载原因、使用短时效票据并记录完整审计。
- 不提供公开桶、永久链接或无审计批量裸下载。
- 项目级账号继续按项目归属和原业务文件权限判断。

## 8. 验收门禁

- 全局岗位白名单账号能看到全部项目并执行对应动作，不能越过冻结审批节点。
- 非白名单项目岗位只看到显式分配项目。
- 工程技术部成员、部长和项目总工三类角色互不混淆；成员只能看到其明确加入的项目。
- 部门主管跨部门、越权授岗、管理自己、停用关键人员均失败关闭。
- 财务部成员无需 `ProjectMember` 仍能处理全部项目财务动作。
- 全局账号下载任一项目敏感文件时仍要求密码、原因、短链和审计。
- 普通项目账号不能借全局错误记录或 query 参数扩大可见范围。
