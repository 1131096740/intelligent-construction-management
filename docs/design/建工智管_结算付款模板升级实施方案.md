## 5. 合同模板库

导航名称改为“合同模板库”。

合同模板库包含 3 个页签：

- 合同模板
- 结算单模板
- 标准条款库

移出内容：

- 合作单位独立为“合作单位档案”
- 编号规则进入“系统配置”

标准条款库只有一套数据源。合同模板编辑里的“条款库”读取同一套标准条款。

模板编辑中的条款操作：

- 引用已发布标准条款版本
- 复制为模板专用条款
- 提交标准条款新版本审批

模板、结算单模板、标准条款均走审批：

- 合同部成员发起
- 合同部主管审批
- 通过后发布

模板版本规则：

- 新建为草稿
- 提交后为审批中
- 审批通过后为已发布
- 新版本发布后旧版本变为历史版本
- 停用后新建业务不能选择，但历史业务可追溯

创建合同联动：

- 选择业务类型后，只能选择该类型下已发布且未停用的合同模板
- 创建合同草稿时锁定当时模板版本
- 若无可用模板，阻断创建并提示先发布模板
- 可以保留已发布的通用合同模板作为兜底

结算单模板联动：

- 选择合同后，系统根据合同类型推荐结算单模板
- 允许在兼容范围内人工切换

结算单模板类型：

- 清单计量结算单
- 无合同数量清单结算单
- 总价形象进度结算单
- 变更签证结算单

模板预览：

- 页面结构预览
- DOCX/PDF 生成预览入口

## 6. 结算单业务规则

### 6.1 合同计价方式

合同创建时必须明确计价方式：

- 清单合同有数量
- 清单合同无数量
- 总价合同

### 6.2 清单合同有数量

结算单必须从合同清单中选择行，不允许随便新增合同外项目。

若有合同外项目，必须先走补充协议或合同变更，生效后才能办理对应结算。

结算单行展示：

- 清单名称
- 工作内容
- 单位
- 合同含税单价
- 税率
- 本期完成数量
- 本期结算金额
- 累计结算金额
- 备注

结算单不展示合同数量和合同金额。

后端必须校验：

- 累计结算数量不能超过合同数量
- 累计结算金额加本期新增结算额不能超过合同金额

### 6.3 清单合同无数量

合同清单保留：

- 项目名称
- 单位
- 不含税单价
- 含税单价
- 税率

结算时录入本期数量，系统自动计算本期金额。

累计数量不设上限，但审批时提醒：

```text
该合同为清单单价合同，无预估工程量，请结合工程量确认单、照片、验收单、收方单等资料审核。
```

### 6.4 总价合同

总价合同结算支持三种方式：

- 形象进度节点
- 本期完成比例
- 本期结算金额

规则：

- 按完成比例时自动计算金额
- 按本期结算金额时反算比例
- 形象进度节点由结算时手填
- 必须上传证明资料

### 6.5 期次和最终结算

结算编号格式：

```text
JS-项目简称-合同编号-期次
```

同一合同下期次顺序递增。

最终结算必须单独标记。

每张结算单必须保存：

- 期前累计结算金额
- 本期结算金额
- 期后累计结算金额

最终结算单口径：

```text
最终结算本期金额 = 最终审定累计结算总额 - 前序已生效累计结算金额
```

不能把最终审定累计结算总额重复作为本期金额。

### 6.6 日期和附件

结算日期由合同员选择，但不能早于合同签订日期。

提交审批前必须上传附件：

- 总价形象进度结算：证明资料
- 无数量清单结算：工程量确认单、照片、验收单、收方单等
- 有数量清单结算：送货单、收方单等

### 6.7 Excel/PDF 生成

结算单先生成 Excel。

草稿阶段可下载带“草稿”水印的 Excel。

提交审批后生成正式审批 PDF，供后续审批人阅读。

审批过程中每个审批人通过后，重新生成带前序签字的最新 PDF。

PDF 签字栏显示：

- 审批节点名称
- 审批角色
- 审批人姓名
- 审批意见
- 审批时间
- 手写签名图；若无签名图，则显示姓名

版式要求：

- A4 横向
- 参考 `结算相关` 文件夹中的结算单
- 清单跨页时重复清单表头
- 每页底部保留完整审批人员签字板块
- 不允许签字板块单独被挤到下一页

### 6.8 乙方盖章归档

结算审批通过后：

```text
生成正式结算单
  -> 线下乙方盖章
  -> 合同员上传盖章件
  -> 合同部主管确认归档
  -> 结算生效
```

结算生效后计入合同累计结算。

正式结算单 Excel/PDF 不展示累计支付金额。

## 7. 内部审批签名和线下盖章

不做法律级电子签章，不接第三方电子签。

内部审批签名只作为内部审批留痕：

- 员工本人在个人设置上传签名图
- 合同部主管或管理员审核后启用
- 无签名图不阻断审批，PDF 显示用户姓名
- 每次生成 PDF 保存当时签名图快照
- 历史 PDF 不受员工后续更换签名影响

正式对外确认走线下盖章：

- 合同线下盖章后上传归档
- 结算线下乙方盖章后上传归档
- 合同部主管确认归档后生效

## 8. 付款条款结构化录入

合同员在合同工作台结构化录入付款节点，合同正文可以引用这些节点生成。

系统不从合同正文自动识别付款条款。

付款计算只信结构化付款节点。

合同生效时锁定付款条款版本。

后续修改必须走合同变更或补充协议。

### 8.1 付款节点字段

付款节点包含：

- 节点类型：预付款、进度款、竣工款、质保金、其他
- 节点名称
- 触发起点：合同生效日、每期结算生效日、最终结算生效日
- 账期月数：1 个月、2 个月、3 个月、自定义
- 付款基数：合同金额、本期结算金额、最终累计结算金额
- 支付规则：支付至某比例、支付固定金额
- 是否纳入当前可申请付款计算
- 发票附件提醒
- 备注

### 8.2 预付款

预付款按合同生效日 + 账期自动纳入可付，不依赖结算单。

基数：

- 合同金额

支付规则：

- 固定比例
- 固定金额

### 8.3 预付款扣回

预付款只有实际支付后，才进入待扣回金额。

扣回只影响付款申请可付额度，不影响结算金额。

支持三种扣回方式：

- 不扣回
- 按比例逐期扣回
- 达到指定条件后开始扣回，按比例扣完为止

付款申请页显示：

- 预付款已付金额
- 本次应扣回预付款金额
- 累计已扣回预付款
- 剩余待扣回预付款
- 扣回后本次可申请金额

### 8.4 进度款

进度款按每一期结算单分别计算账期。

规则：

```text
每期结算生效日 + 账期后，该期本期结算金额 × 支付比例 纳入可付
```

“支付至 80%”是累计上限，不是本期之外另加 80%。

### 8.5 竣工款

只有最终结算生效后，竣工款规则才开始计算。

规则：

```text
最终结算生效日 + 账期后，最终审定累计结算总额 × 竣工款支付比例 纳入可付
```

不需要项目经理额外确认，因为最终结算审批流中已经确认。

### 8.6 质保金

是否有质保金完全以合同付款条款为准。

若合同约定质保金比例和期限，则生成质保金规则。

若合同未约定质保金，则不生成质保金规则。

质保期起算日：

```text
最终结算生效日期
```

质保金释放：

```text
最终结算生效日 + 质保期限后，剩余质保金纳入可付
```

不需要项目经理额外确认。

### 8.7 发票

发票只作为附件提醒，不作为付款申请硬性前置条件。

## 9. 项目付款申请

### 9.1 入口

付款申请按合同发起，不按单张结算单发起。

流程：

```text
选择合同
  -> 系统列出该合同下全部已生效结算单
  -> 系统生成累计结算金额
  -> 引出合同付款比例/时间条件
  -> 生成当前累计可付款金额
  -> 扣减已实际付款、已批待付、预付款扣回
  -> 得到本次最多可申请金额
  -> 申请人填写本次申请金额
```

全部已生效结算单默认纳入累计，不允许申请人排除某几张。

不做付款金额到每张结算单的分摊。

### 9.2 金额控制

本次可申请上限：

```text
当前累计可付款金额
- 已实际付款金额
- 已批待付款金额
- 本次应扣回预付款金额
= 本次最多可申请金额
```

不允许提前付款。

不允许领导特批绕过额度。

要改变额度，必须走合同变更或补充协议。

### 9.3 付款申请页展示

付款申请页按付款条款类型分区展示计算明细：

- 预付款
- 进度款
- 竣工款
- 质保金

每行至少展示：

- 来源
- 本期结算金额
- 期前累计结算金额
- 期后累计结算金额
- 生效日期
- 预计可付日
- 付款规则
- 当前是否到账期
- 本行可计入金额

未到账期的行灰色显示，并展示预计可付日期。

最终结算未生效前，不展示竣工款和质保金的可付额度。

若无质保金条款，不显示质保金区域。

### 9.4 项目付款审批表字段

项目付款审批表应覆盖新增 Excel 中的核心字段：

- 项目名称
- 申请日期
- 付款主体
- 经办人
- 付款事由
- 计划付款日期
- 合同名称
- 合同编号
- 付款方式
- 付款类型
- 合同金额
- 累计生效结算金额
- 累计已付款
- 当前可申请余额
- 发票类型提醒
- 本次付款金额
- 收款方名称
- 开户银行
- 银行账号
- 转款手续费
- 备注

### 9.5 项目付款审批流

项目付款审批流需要升级，不能只保留董事长/总经理。

建议审批节点：

```text
经办人提交
  -> 项目经理
  -> 合同结算部
  -> 财务
  -> 董事长/总经理 OR-sign
```

董事长和总经理仍为或签节点，任意一人批准即可。

付款审批通过后进入：

```text
已批待付款
```

出纳或财务登记实付并上传凭证后，才进入已付款或分次付款中。

支持分次付款登记。

## 10. 零星付款

零星付款单独成模块，不复用合同付款额度控制。

字段参考新增 Excel：

- 项目名称
- 申请日期
- 付款主体
- 付款事由
- 申请金额
- 付款方式：现金、微信、支付宝、网银转账、其他
- 对方账户信息
- 经办人
- 部门经理或项目经理
- 综合部
- 财务部
- 董事长/总经理

流程建议：

```text
经办人提交
  -> 部门经理或项目经理
  -> 综合部
  -> 财务部
  -> 董事长/总经理 OR-sign
  -> 已批待付款
  -> 出纳实付
  -> 凭证上传
  -> 财务记录
```

零星付款需要金额上限和用途分类，但本轮先不定义复杂预算系统。

## 11. 当前系统差距

当前系统已有：

- 合同状态机
- 结算状态机
- 付款申请、审批、实付、凭证、财务记录
- 私有文件、审批 PDF、归档、审计
- 审批撤回、退回、转审、委托、催办
- 合同工作台和模板基础能力

当前主要差距：

- Web 仍存在英文可见文案和英文路径
- 模板中心不像业务模板库
- 结算仍是金额字段级别，不是结算单
- 付款申请仍按单张结算单发起
- 付款审批流过短，仅董事长/总经理节点
- 付款条款不够结构化，缺账期、质保金、预付款扣回
- 结算 Excel/PDF 版式和分页规则未落地
- 零星付款未建模

## 13. 待确认边界

以下问题需要继续确认，确认前不应贸然实现：

1. 项目付款审批表中的“每月资金计划范围额度”是否要作为 P0 硬控制？还是先作为审批提示，P1 再做资金计划模块。
2. 项目付款审批中的“未付款余额”页面字段，建议拆成“合同剩余未付金额”和“当前可申请余额”，是否同意。
3. 项目付款审批流是否所有合同付款类型都统一为：项目经理 -> 合同结算部 -> 财务 -> 董事长/总经理；材料、机械、劳务、工程分包是否需要不同前置节点。
4. 零星付款金额上限是否需要按角色配置。例如超过 1 万必须董事长/总经理，低于 1 万是否也必须终审。
5. 付款主体是否只能从公司主体字典选择，不允许手填。
6. 收款方是否必须从合作单位档案选择；个人收款是否允许手填并上传身份证或银行卡信息。
7. 结算单底部签字栏最终显示“合同部”还是“合同结算部”，需要统一公司内部岗位名称。

## 14. 验收标准

上线前至少验证：

- Web 管理端无可见英文状态、按钮、菜单、空态、错误提示
- 中文路径可访问，旧英文路径重定向到中文路径
- 无可用模板时不能创建合同或结算
- 合同生效后付款条款版本锁定
- 有数量清单结算累计数量不能超过合同数量
- 结算累计金额不能超过合同金额
- 无数量清单审批时出现风险提醒
- 最终结算本期金额按差额计算
- 结算草稿 Excel 带草稿水印
- 结算审批 PDF 每次审批后带前序签名
- 结算跨页重复表头，每页保留签字栏
- 结算盖章件上传并确认后才生效
- 付款申请按合同累计结算和付款条款计算上限
- 未到账期付款条件不计入可付额度
- 预付款实付后才参与扣回
- 本次付款申请不能超过系统计算上限
- 付款审批流包含项目经理、合同结算部、财务、董事长/总经理
- 付款审批通过不等于实付
- 分次实付不能超过已批金额
- 实付必须上传凭证
- 财务记录不能超过已实付金额
- 所有关键动作写审计日志
