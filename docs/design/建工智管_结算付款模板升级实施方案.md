## 2. 产品边界

### 2.1 本轮核心范围

本轮只做企业经营主链。项目是经营主体，系统必须同时管住收入侧、支出侧和合同结算付款链条：

```text
项目经营
  -> 实际收款、总包代付、对上审定、垫资额度
  -> 合同模板库
  -> 合同工作台
  -> 合同审批、用章、归档、生效
  -> 结算单生成、审批、乙方盖章归档、生效
  -> 项目付款申请
  -> 付款审批
  -> 出纳实付、凭证上传
  -> 财务记录、PDF 归档、审计
```

### 2.2 本轮纳入的轻量支出

新增“零星付款”和“借款/备用金”作为独立支出类型，复用审批、文件、实付、凭证、财务记录能力，但不进入合同结算付款条款控制。

零星付款适用于：

- 临时小额支出
- 项目零星费用
- 非合同结算链条下的对外支付

借款/备用金适用于：

- 员工借款
- 老板借款
- 项目备用金

零星付款和借款/备用金不走合同结算额度，但必须走项目现金资金池控制。

### 2.3 暂不进入本轮

以下表单不纳入本轮核心，不塞进合同付款模块：

- 差旅费申请单
- 差旅费报销单
- 业务招待费申请
- 开票申请
- 综合部采购申请表
- 零星小额材料采购申请表

后续可分别进入：

- 综合费用模块：差旅、招待、报销、借款冲销
- 开票管理模块：开票申请、发票台账、应收联动
- 采购管理模块：采购申请、采购执行、材料入库

## 5. 合同模板库

导航名称改为“合同模板库”。

合同模板库包含 3 个页签：

- 合同模板
- 结算单模板
- 标准条款库

移出内容：

- 合作单位独立为“合作单位档案”
- 编号规则进入“系统配置”

标准条款库只有一套数据源。合同模板编辑里的“条款库”读取同一套标准条款。

模板编辑中的条款操作：

- 引用已发布标准条款版本
- 复制为模板专用条款
- 提交标准条款新版本审批

模板、结算单模板、标准条款均走审批：

- 合同部成员发起
- 合同部主管审批
- 通过后发布

模板版本规则：

- 新建为草稿
- 提交后为审批中
- 审批通过后为已发布
- 新版本发布后旧版本变为历史版本
- 停用后新建业务不能选择，但历史业务可追溯

创建合同联动：

- 选择业务类型后，只能选择该类型下已发布且未停用的合同模板
- 创建合同草稿时锁定当时模板版本
- 若无可用模板，阻断创建并提示先发布模板
- 可以保留已发布的通用合同模板作为兜底

结算单模板联动：

- 选择合同后，系统根据合同类型推荐结算单模板
- 允许在兼容范围内人工切换

结算单模板类型：

- 清单计量结算单
- 无合同数量清单结算单
- 总价形象进度结算单
- 变更签证结算单

模板预览：

- 页面结构预览
- DOCX/PDF 生成预览入口

## 6. 结算单业务规则

### 6.1 合同计价方式

合同创建时必须明确计价方式：

- 清单合同有数量
- 清单合同无数量
- 总价合同

### 6.2 清单合同有数量

结算单必须从合同清单中选择行，不允许随便新增合同外项目。

若有合同外项目，必须先走补充协议或合同变更，生效后才能办理对应结算。

结算单行展示：

- 清单名称
- 工作内容
- 单位
- 合同含税单价
- 税率
- 本期完成数量
- 本期结算金额
- 累计结算金额
- 备注

结算单不展示合同数量和合同金额。

后端必须校验：

- 累计结算数量不能超过合同数量
- 累计结算金额加本期新增结算额不能超过合同金额

### 6.3 清单合同无数量

合同清单保留：

- 项目名称
- 单位
- 不含税单价
- 含税单价
- 税率

结算时录入本期数量，系统自动计算本期金额。

累计数量不设上限，但审批时提醒：

```text
该合同为清单单价合同，无预估工程量，请结合工程量确认单、照片、验收单、收方单等资料审核。
```

### 6.4 总价合同

总价合同结算支持三种方式：

- 形象进度节点
- 本期完成比例
- 本期结算金额

规则：

- 按完成比例时自动计算金额
- 按本期结算金额时反算比例
- 形象进度节点由结算时手填
- 必须上传证明资料

### 6.5 期次和最终结算

结算编号格式：

```text
JS-项目简称-合同编号-期次
```

同一合同下期次顺序递增。

最终结算必须单独标记。

每张结算单必须保存：

- 期前累计结算金额
- 本期结算金额
- 期后累计结算金额

最终结算单口径：

```text
最终结算本期金额 = 最终审定累计结算总额 - 前序已生效累计结算金额
```

不能把最终审定累计结算总额重复作为本期金额。

### 6.6 日期和附件

结算日期由合同员选择，但不能早于合同签订日期。

提交审批前必须上传附件：

- 总价形象进度结算：证明资料
- 无数量清单结算：工程量确认单、照片、验收单、收方单等
- 有数量清单结算：送货单、收方单等

### 6.7 Excel/PDF 生成

结算单先生成 Excel。

草稿阶段可下载带“草稿”水印的 Excel。

提交审批后生成正式审批 PDF，供后续审批人阅读。

审批过程中每个审批人通过后，重新生成带前序签字的最新 PDF。

PDF 签字栏显示：

- 审批节点名称
- 审批角色
- 审批人姓名
- 审批意见
- 审批时间
- 手写签名图；若无签名图，则显示姓名

版式要求：

- A4 横向
- 参考 `结算相关` 文件夹中的结算单
- 清单跨页时重复清单表头
- 每页底部保留完整审批人员签字板块
- 不允许签字板块单独被挤到下一页

### 6.8 乙方盖章归档

结算审批通过后：

```text
生成正式结算单
  -> 线下乙方盖章
  -> 合同员上传盖章件
  -> 合同部主管确认归档
  -> 结算生效
```

结算生效后计入合同累计结算。

正式结算单 Excel/PDF 不展示累计支付金额。

## 7. 内部审批签名和线下盖章

不做法律级电子签章，不接第三方电子签。

内部审批签名只作为内部审批留痕：

- 员工本人在个人设置上传签名图
- 合同部主管或管理员审核后启用
- 无签名图不阻断审批，PDF 显示用户姓名
- 每次生成 PDF 保存当时签名图快照
- 历史 PDF 不受员工后续更换签名影响

正式对外确认走线下盖章：

- 合同线下盖章后上传归档
- 结算线下乙方盖章后上传归档
- 合同部主管确认归档后生效

## 8. 付款条款结构化录入

合同员在合同工作台结构化录入付款节点，合同正文可以引用这些节点生成。

系统不从合同正文自动识别付款条款。

付款计算只信结构化付款节点。

合同生效时锁定付款条款版本。

后续修改必须走合同变更或补充协议。

### 8.1 付款节点字段

付款节点包含：

- 节点类型：预付款、进度款、竣工款、质保金、其他
- 节点名称
- 触发起点：合同生效日、每期结算生效日、最终结算生效日
- 账期月数：1 个月、2 个月、3 个月、自定义
- 付款基数：合同金额、本期结算金额、最终累计结算金额
- 支付规则：支付至某比例、支付固定金额
- 是否纳入当前可申请付款计算
- 发票附件提醒
- 备注

### 8.2 预付款

预付款按合同生效日 + 账期自动纳入可付，不依赖结算单。

基数：

- 合同金额

支付规则：

- 固定比例
- 固定金额

### 8.3 预付款扣回

预付款只有实际支付后，才进入待扣回金额。

扣回只影响付款申请可付额度，不影响结算金额。

支持三种扣回方式：

- 不扣回
- 按比例逐期扣回
- 达到指定条件后开始扣回，按比例扣完为止

付款申请页显示：

- 预付款已付金额
- 本次应扣回预付款金额
- 累计已扣回预付款
- 剩余待扣回预付款
- 扣回后本次可申请金额

### 8.4 进度款

进度款按每一期结算单分别计算账期。

规则：

```text
每期结算生效日 + 账期后，该期本期结算金额 × 支付比例 纳入可付
```

“支付至 80%”是累计上限，不是本期之外另加 80%。

### 8.5 竣工款

只有最终结算生效后，竣工款规则才开始计算。

规则：

```text
最终结算生效日 + 账期后，最终审定累计结算总额 × 竣工款支付比例 纳入可付
```

不需要项目经理额外确认，因为最终结算审批流中已经确认。

### 8.6 质保金

是否有质保金完全以合同付款条款为准。

若合同约定质保金比例和期限，则生成质保金规则。

若合同未约定质保金，则不生成质保金规则。

质保期起算日：

```text
最终结算生效日期
```

质保金释放：

```text
最终结算生效日 + 质保期限后，剩余质保金纳入可付
```

不需要项目经理额外确认。

### 8.7 发票

发票只作为附件提醒，不作为付款申请硬性前置条件。

## 9. 项目付款申请

### 9.1 入口

付款申请按合同发起，不按单张结算单发起。

流程：

```text
选择合同
  -> 系统列出该合同下全部已生效结算单
  -> 系统生成累计结算金额
  -> 引出合同付款比例/时间条件
  -> 生成当前累计可付款金额
  -> 扣减已实际付款、已批待付、预付款扣回
  -> 得到本次最多可申请金额
  -> 申请人填写本次申请金额
```

全部已生效结算单默认纳入累计，不允许申请人排除某几张。

不做付款金额到每张结算单的分摊。

### 9.2 金额控制

本次可申请上限：

```text
当前累计可付款金额
- 已实际付款金额
- 已批待付款金额
- 本次应扣回预付款金额
= 本次最多可申请金额
```

不允许提前付款。

不允许领导特批绕过额度。

要改变额度，必须走合同变更或补充协议。

### 9.3 付款申请页展示

付款申请页按付款条款类型分区展示计算明细：

- 预付款
- 进度款
- 竣工款
- 质保金

每行至少展示：

- 来源
- 本期结算金额
- 期前累计结算金额
- 期后累计结算金额
- 生效日期
- 预计可付日
- 付款规则
- 当前是否到账期
- 本行可计入金额

未到账期的行灰色显示，并展示预计可付日期。

最终结算未生效前，不展示竣工款和质保金的可付额度。

若无质保金条款，不显示质保金区域。

### 9.4 项目付款审批表字段

项目付款审批表应覆盖新增 Excel 中的核心字段：

- 项目名称
- 申请日期
- 付款主体
- 经办人
- 付款事由
- 计划付款日期
- 合同名称
- 合同编号
- 付款方式
- 付款类型
- 合同金额
- 累计生效结算金额
- 累计已付款
- 当前可申请余额
- 发票类型提醒
- 本次付款金额
- 收款方名称
- 开户银行
- 银行账号
- 转款手续费
- 备注

### 9.5 项目付款审批流

项目付款审批流需要升级，不能只保留董事长/总经理。

建议审批节点：

```text
经办人提交
  -> 项目经理
  -> 合同结算部
  -> 财务
  -> 董事长/总经理 OR-sign
```

董事长和总经理仍为或签节点，任意一人批准即可。

付款审批通过后进入：

```text
已批待付款
```

出纳或财务登记实付并上传凭证后，才进入已付款或分次付款中。

支持分次付款登记。

## 10. 零星付款

零星付款单独成模块，不复用合同付款条款额度控制，但必须走项目现金资金池控制。

字段参考新增 Excel：

- 项目名称
- 申请日期
- 付款主体
- 付款事由
- 申请金额
- 付款方式：现金、微信、支付宝、网银转账、其他
- 对方账户信息
- 经办人
- 部门经理或项目经理
- 综合部
- 财务部
- 董事长/总经理

流程建议：

```text
经办人提交
  -> 部门经理或项目经理
  -> 综合部
  -> 财务部
  -> 董事长/总经理 OR-sign
  -> 已批待付款
  -> 出纳实付
  -> 凭证上传
  -> 财务记录
```

零星付款提交审批时占用项目现金资金池。撤回、驳回、作废时释放占用；实付后转为项目实际支出。

## 11. 项目经营与资金控制

### 11.1 基本口径

项目作为经营主体，分为两个层面：

- 收款：实际收入，指实际进入我方账户、实际可控且可支出的钱。
- 付款：实际支出，指对下游和项目相关费用的实际成本。

甲方付给总包的钱不算我方项目收入。只有总包或甲方实际付给我方、进入我方账户的钱，才算项目实际收款。

总包直接代付下游的工程款、材料款、机械款等，做“总包代付登记”。总包代付形成一笔经营收入和一笔经营成本，但不增加项目可用现金。

### 11.2 项目经营盘指标

现金口径：

- 实际收款
- 实际付款
- 审批中付款占用
- 已批待付款
- 公司垫资额度
- 当前可用资金

当前可用资金：

```text
项目实际收款
+ 可用垫资额度
- 我方实际付款
- 审批中付款占用
- 已批待付款
```

经营口径：

- 实际收款收入
- 总包代付收入
- 经营收入合计
- 我方实付成本
- 总包代付成本
- 经营成本合计
- 当前经营毛利

经营收入合计：

```text
实际收款收入 + 总包代付收入
```

经营成本合计：

```text
我方实付成本 + 总包代付成本
```

当前经营毛利：

```text
经营收入合计 - 经营成本合计
```

总包代付不进入现金资金池，避免虚增项目可用资金。

### 11.3 资金全貌权限

所有收入、支出、资金池、经营毛利只对以下角色开放：

- 项目财务
- 项目经理
- 财务主管/财务总监
- 总经理/董事长

超级管理员仅做技术管理，不默认拥有业务查看权，除非单独授权。

业务办理角色只看到办理所需信息：

- 合同部：合同、结算、付款申请业务字段；付款额度只显示可申请、不可申请和拦截原因。
- 预算部：对上审定、下游结算金额；不看实际收款和项目毛利。
- 工程/物资：审批相关清单和附件；不看收入支出全貌。
- 经办人：自己发起的单据。

### 11.4 业主主合同

业主主合同只作为上游额度锚点和文件归档，不做完整合同工作台。

一个项目可以有多个业主主合同。

流程：

```text
合同部录入上传
  -> 合同部主管确认
  -> 生效
```

最小字段：

- 所属项目
- 业主单位
- 合同名称
- 合同编号
- 签订日期
- 合同金额
- 税率
- 计价方式
- 付款条款摘要
- 质保金约定
- 合同文件

补充协议、变更签证必须纳入主合同有效金额。

主合同有效金额：

```text
主合同原始金额 + 已生效补充协议金额 + 已确认变更签证金额
```

下游合同总额控制按项目汇总，不强制每个下游合同绑定某个业主主合同。

### 11.5 对上审定

对上审定结算不是现金收入，而是控制下游结算额度的依据。

字段：

- 项目
- 期次
- 是否最终结算
- 申报金额
- 甲方审定金额
- 审定日期
- 审定结算单文件
- 备注

规则：

- 预算人员录入。
- 必须上传审定结算单文件。
- 提交前二次确认。
- 录入即生效并写审计。
- 作废、更正写审计。
- 只有甲方审定金额计入项目对上累计审定金额。
- 申报金额只做记录和对比。
- 期次顺序递增，最终结算单独标记。

### 11.6 实际收款登记

实际收款指进入我方账户并归属该项目的可控资金。

字段：

- 项目
- 收款日期
- 收款金额
- 付款单位
- 收款来源类型：总包付款、甲方直付、其他
- 收款说明
- 收款凭证
- 关联对上主合同，可选
- 关联对上审定结算，可选

规则：

- 只能由财务录入。
- 必须上传收款凭证。
- 一笔收款只归属一个项目，P0 不做拆分。
- 录入即生效，计入项目实际收款。
- 作废需要二次确认并写审计。

### 11.7 总包代付登记

总包直接代付下游款项时，系统登记一张“总包代付单”。

字段：

- 项目
- 总包单位
- 代付日期
- 代付金额
- 代付对象
- 代付类型：材料、机械、劳务、专业分包、其他
- 关联下游合同，可选
- 关联下游结算，可选
- 代付说明
- 代付凭证

登记后自动形成镜像经营记录：

```text
经营收入：总包代付收入
经营成本：按代付类型归类
现金影响：无
```

如果关联下游合同或结算，则计入该下游合同或结算的累计已支付。

付款台账必须区分：

- 我方实付
- 总包代付

下游合同累计已支付：

```text
我方实付 + 总包代付
```

### 11.8 下游合同额控制

下游合同提交审批时硬拦截：

```text
项目已生效下游合同总额
+ 审批中下游合同占用
+ 本次下游合同金额
<= 项目业主主合同有效总额
```

### 11.9 下游结算额度控制

下游结算提交审批时硬拦截：

```text
项目下游累计已生效结算金额
+ 审批中下游结算占用
+ 本次下游结算金额
<= 项目对上累计审定金额
+ 对应下游合同可用例外结算额度
```

额度不足时，必须先申请例外结算额度，审批通过后才能提交结算。

### 11.10 例外结算额度

例外结算额度绑定项目和对应下游合同。

规则：

- 一次性额度池。
- 申请额度、原因、有效期、附件必填。
- 审批通过后增加该下游合同的可结算额度。
- 有效期内可分多次使用。
- 累计使用不能超过批准额度。
- 到期未使用余额失效。
- 合同作废或终止后余额失效。
- 提交结算审批时占用。
- 结算撤回、驳回、作废时释放。
- 结算归档生效后转为已使用。
- 使用、释放、过期写审计。

审批流：

```text
项目经理
  -> 预算/合同结算部
  -> 总经理/董事长 OR-sign
```

### 11.11 项目垫资额度

资金池不足时，允许申请项目垫资额度。

垫资额度增加项目现金可付款能力，但不计入经营收入。

规则：

- 一次性额度池。
- 审批通过后增加项目现金资金池。
- 有效期内可分多次使用。
- 到期未使用余额失效。
- 项目关闭或终止后余额失效。
- 提交付款审批时占用。
- 付款撤回、驳回、作废时释放。
- 实付后转为已使用。
- 使用、释放、过期写审计。

审批流：

```text
项目经理
  -> 财务
  -> 总经理/董事长 OR-sign
```

### 11.12 项目付款资金池控制

所有项目付款提交审批时硬拦截：

```text
本次付款申请金额
<= 项目实际收款
 + 可用垫资额度
 - 我方实际付款
 - 审批中付款占用
 - 已批待付款
```

付款申请提交审批时占用项目现金资金池。

撤回、驳回、作废时释放占用。

付款审批通过后仍保持占用，状态变为已批待付。

实付后从占用转为项目实际支出。

合同付款同时受两道硬控制：

```text
本次付款申请金额 <= 合同付款条款计算出的当前可申请金额
本次付款申请金额 <= 项目现金资金池可用金额
```

零星付款、综合费用、借款/备用金不走合同付款条款，但必须走项目现金资金池。

### 11.13 支出分类

一级类型：

- 合同付款
- 零星付款
- 综合费用
- 借款/备用金
- 其他支出

合同付款二级：

- 材料采购
- 机械租赁
- 劳务分包
- 专业分包
- 工程分包
- 其他合同付款

零星付款二级：

- 零星材料
- 零星机械
- 零星用工
- 临时服务
- 其他零星

综合费用二级：

- 差旅
- 招待
- 办公
- 后勤
- 车辆
- 其他费用

借款/备用金二级：

- 员工借款
- 老板借款
- 项目备用金

P0 实现合同付款、零星付款、借款/备用金。综合费用先作为类型保留，差旅、招待、报销表单后续实现。

## 12. 当前系统差距

当前系统已有：

- 合同状态机
- 结算状态机
- 付款申请、审批、实付、凭证、财务记录
- 私有文件、审批 PDF、归档、审计
- 审批撤回、退回、转审、委托、催办
- 合同工作台和模板基础能力

当前主要差距：

- Web 仍存在英文可见文案和英文路径
- 模板中心不像业务模板库
- 缺项目经营模块，无法区分现金口径和经营口径
- 缺实际收款、总包代付、对上审定、垫资额度
- 缺项目资金池硬拦截
- 缺下游合同额、下游结算额与对上额度联动
- 结算仍是金额字段级别，不是结算单
- 付款申请仍按单张结算单发起
- 付款审批流过短，仅董事长/总经理节点
- 付款条款不够结构化，缺账期、质保金、预付款扣回
- 结算 Excel/PDF 版式和分页规则未落地
- 零星付款、借款/备用金未建模

## 14. 待确认边界

以下问题需要继续确认，确认前不应贸然实现：

1. 项目付款审批中的“未付款余额”页面字段，建议拆成“合同剩余未付金额”和“当前可申请余额”，是否同意。
2. 项目付款审批流是否所有合同付款类型都统一为：项目经理 -> 合同结算部 -> 财务 -> 董事长/总经理；材料、机械、劳务、工程分包是否需要不同前置节点。
3. 零星付款和借款/备用金是否需要按金额分级审批。
4. 付款主体是否只能从公司主体字典选择，不允许手填。
5. 收款方是否必须从合作单位档案选择；个人收款是否允许手填并上传身份证或银行卡信息。
6. 结算单底部签字栏最终显示“合同部”还是“合同结算部”，需要统一公司内部岗位名称。

## 15. 验收标准

上线前至少验证：

- Web 管理端无可见英文状态、按钮、菜单、空态、错误提示
- 中文路径可访问，旧英文路径重定向到中文路径
- 无可用模板时不能创建合同或结算
- 项目经营模块仅资金全貌权限可访问
- 实际收款必须由财务录入并上传凭证
- 总包代付形成经营收入和经营成本，但不增加可用现金
- 对上审定必须上传审定结算单，且只有甲方审定金额进入额度控制
- 下游合同提交审批时不能超过项目业主主合同有效总额
- 下游结算提交审批时不能超过对上累计审定金额加可用例外额度
- 例外结算额度在结算提交审批时占用，撤回/驳回释放，生效后转为已使用
- 项目付款提交审批时占用项目现金资金池
- 项目垫资额度审批通过后才增加可用资金，且不计入经营收入
- 合同生效后付款条款版本锁定
- 有数量清单结算累计数量不能超过合同数量
- 结算累计金额不能超过合同金额
- 无数量清单审批时出现风险提醒
- 最终结算本期金额按差额计算
- 结算草稿 Excel 带草稿水印
- 结算审批 PDF 每次审批后带前序签名
- 结算跨页重复表头，每页保留签字栏
- 结算盖章件上传并确认后才生效
- 付款申请按合同累计结算和付款条款计算上限
- 未到账期付款条件不计入可付额度
- 预付款实付后才参与扣回
- 合同付款同时不能超过合同付款条款上限和项目现金资金池
- 零星付款、借款/备用金不走合同付款条款，但必须走项目现金资金池
- 付款审批流包含项目经理、合同结算部、财务、董事长/总经理
- 付款审批通过不等于实付
- 分次实付不能超过已批金额
- 实付必须上传凭证
- 财务记录不能超过已实付金额
- 所有关键动作写审计日志
