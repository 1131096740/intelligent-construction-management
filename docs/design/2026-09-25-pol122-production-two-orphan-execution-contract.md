## 单独入口及信任边界

生产入口应是新的受信启动器子命令，与现有本机 CLI 分开；执行代码、Node/Prisma/runtime 及启动器均纳入既有 `executionCodeSha256`。没有任何 `--production`、`--force`、`--skip-*` 或自动重试选项。执行人不能同时签发决定、冻结租约和最终授权；私钥不进入执行主机，公钥、执行身份和租约仅从既定 root 持有固定路径读取。

入口只接受以下四步、每步独立新输出路径：

1. `inspect`：只读，要求新的正式 POL-22 报告与当前候选 SHA、数据库身份、171 项迁移/Schema 摘要和新 `schema_compatibility_receipt` 精确相符。来源报告只允许**恰好两个** `ORPHAN_FILE` blocker，其他 blocker、删除候选或目标不明均停止。逐条绑定完整 `FileObject` 主键及行哈希、`quarantined` 状态、隔离审计与零业务引用；同键共享、继承引用或未知绑定均停止。
2. `dry-run`：重新只读检查全库保留行摘要、两目标行、触发器/函数定义、两类本窗口备份及隔离恢复、两个对象的所有版本/删除标记。输出精确操作清单与恢复锚点，但不写数据库/COS。报告和计划均绑定签名处置决定、执行身份、代码 SHA、双范围冻结租约代际及本批次；任何变化须重新 inspect。
3. `execute`：另行签发仅含该批次、两个主键/行哈希、精确 bucket/key/版本 ID、计划摘要、前序收据摘要、有效期与租约代际的 Ed25519 授权。先独占创建 `0700/0600` 耐久日志；对数据库使用串行化事务、表锁、锁内重建、逐行 CAS、同事务审计，提交结果不明时绝不推断回滚。每个对象版本删除前重读授权/租约、只读重扫目标版本集，只有精确版本 ID 可发出一次 DELETE；不允许前缀删除、重新列举后扩大范围或自动重发。任一失败立即停止，转入独立只读对账，不进入下一版本。
4. `postcheck`：独立只读核对两个 FileObject 缺失、全部批准版本缺失、非目标逐行摘要不变、审计及日志链吻合；数据库完成审计必须在既定冻结下提交。此结果仅为“两文件已处置”子回执，不能替代 POL-22 全量正式归零后的权威 terminal marker 和 `zeroing_receipt`。

## 实现和验证硬门

- 复用现有精确两行数据库检查、版本备份校验、耐久日志和失败对账；把实际 PG/COS 访问作为受签名范围约束的生产适配器。保留本机 CLI 的固定隔离边界及原测试，不提供共享的可切换“环境模式”。
- 逐版本 COS DELETE 的单请求传输现已抽成受精确 bucket/region/key/version、签名头、HTTPS 和 204 确认约束的内部模块，并在本机执行链与隔离假服务上验证。它不开放生产 execute；正式适配器仍须把目标 host 与已签计划、运行环境及实时冻结绑定，并在每次请求前复验。
- 新增生产对象操作内部模块并接入执行协调器内仍被顶层硬阻断的生产分支：构造时拒绝非 Linux 主机、容器、两目标重复坐标或非当前正式 bucket；每次枚举/删除前重新检查运行环境、控制面连续性与授权，只接受计划内完整对象与 version ID；同一进程内对同一版本最多尝试一次 DELETE，未知结果不重发。协调器使用有界无重试 GET 和精确单次 DELETE 传输，并在保存计划使用前重新核对备份回执内容摘要。该分支未通过正式入口正向整链测试，且 `execute`/`postcheck` 仍在参数解析前直接拒绝，不能视为生产执行能力。
- 纯 `validateProductionApplyAuthorization` 仅接受 Ed25519 精确签名的两目标 dry-run 报告：绑定 #296 前序摘要、新连续性 envelope、候选 SHA、数据库/代码/执行身份、备份和恢复锚、两行与全版本快照、冻结代际、固定日志根及有效期；重签后扩大目标或版本也因报告内部快照关系而被拒绝。该函数尚未接入任何生产写入入口，不代表授权材料已签发或生产执行能力已开放。
- 生产入口仅接受既定 `jiangkong_runtime` 数据库登录角色，再校验已签数据库 fingerprint 对应目标；owner、postgres 或其他登录角色在连接前拒绝。对象只访问已签两个精确 bucket/key，枚举全版本时要求精确 `prefix`、固定分页参数、签名 Host/Authorization、有界分页、无重试和 HTTPS 固定域名，删除仅允许计划列明的 version ID。服务器返回、超时或进程失联均以结果未知处理。
- 测试必须先证明旧 CLI 在生产上下文零写、缺失/伪造/过期签名与租约零写、其他 blocker 零写、对象多一个版本零写、数据库审计提交不明后不发 COS DELETE，以及单版本 DELETE 不明后不重试。然后在一次性 PG16 和隔离版本对象服务上证明精确两文件成功与后检；完整本机门和双轴审查绑定最终 SHA。
- 生产安装、材料签发、正式 inspect/dry-run、备份/恢复、`execute`、COS DELETE、数据库删除、#122 `zeroing_receipt` 及 #123/#124 均不在本次本地设计/实现授权内。每个正式窗口仍须以候选 SHA、前序收据、目标清单、备份恢复、冻结和命令逐项另行确认；首次失败保持停机，按[失败对账契约](2026-09-23-pol122-two-orphan-failure-reconciliation.md)处理。
