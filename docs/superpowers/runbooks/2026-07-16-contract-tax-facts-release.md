# 合同税务事实与含税计价发布、UAT 与回滚手册

日期：2026-07-17

状态：本地发布候选准备中；本手册不构成推送、部署、生产迁移或生产业务写入授权。

## 1. 发布目标与不可改变的边界

本次发布只建立以下事实：

- 合同版本级发票类型、计税模式、默认税率和确认状态；
- 合同清单含税单价、税率来源、价格确认状态和新录入两位小数规则；
- 历史合同按“合同员录入、财务主管复核、合同部主管确认”形成不可覆盖修订记录；
- 税务或价格事实缺失时允许保存结算草稿，但禁止提交结算审批；
- 提交结算时冻结合同版本、票种、税率、含税单价和税务事实修订号。

不得借本次发布改变：

- 审批节点顺序、角色权限、路由地址和业务状态；
- 合同、结算、付款金额来源及元分转换；
- 既有结算 `manual_adjustment` 语义；
- 文件上传 API、文件类型、大小、私有桶和下载权限；
- 既有合同、结算、付款和实付历史金额事实。

## 2. 候选、迁移与发布前门禁

最终发布前必须填写并由用户明确批准：

| 项目 | 要求 |
| --- | --- |
| 目标候选 SHA | 精确 40 位，必须与待部署运行时代码一致 |
| 生产当前迁移数 | 51 |
| 候选迁移数 | 52 |
| 新迁移 | `20260716160000_contract_tax_facts_and_settlement_drafts` |
| 数据库写迁移 | 是；新增列、表、索引、约束并做受限兼容回填 |
| 生产业务写入 | 发布验证前禁止；发布后只按获批 UAT 清单执行 |
| 安全回滚点 | `d090e5c31bf85094b5661b67e67f60ade191a28f` |

发布前必须全部通过：

1. 候选工作区洁净，`git diff --check` 通过。
2. shared-domain、API、Web 全量测试、类型检查、lint、业务错误检查、UI 规则、build 和 P0 E2E 全部通过。
3. 受保护目录相对 `origin/main` 无差异：

   ```bash
   git diff origin/main -- \
     apps/web-admin/src/routes \
     services/api/src/payment \
     services/api/src/file \
     services/api/src/storage \
     services/api/src/approval
   ```

4. 使用最新 COS 异机备份恢复到 `jiangkong_restore_*` 隔离库，并在精确候选 SHA 上完成 51 → 52 迁移。
5. 隔离库迁移前后金额、数量、单价、结算和付款事实对比通过。
6. 用户明确批准最终 40 位候选 SHA 后，才能推送、部署和执行生产迁移。

## 3. 隔离迁移演练

必须遵循 `2026-07-15-production-offsite-db-backup-runbook.md` 的恢复边界：

1. 从最新 `.offsite.json` 收据指定的 COS 对象重新下载 dump 和 checksum，不能使用服务器本地 dump 冒充异机恢复输入。
2. 校验 dump SHA-256、checksum 内容和 `pg_restore --list`。
3. 创建名称以 `jiangkong_restore_` 开头的空数据库，并限制连接数。
4. 恢复生产备份，记录迁移前 51 个已完成迁移、0 个未完成迁移。
5. 在精确候选 SHA 的洁净临时检出中执行：

   ```bash
   pnpm --filter @jiangkong/api prisma:migrate:deploy
   pnpm --filter @jiangkong/api exec prisma migrate status
   ```

6. 确认最终为 52 个已完成迁移、0 个未完成迁移。
7. 使用 `default_transaction_read_only=on` 重新执行数据核验。
8. 删除隔离数据库和临时检出；不得删除 COS 备份对象。

### 3.1 迁移前后必须一致的事实

- `ContractVersion.amountCents` 逐行值和总和；
- `ContractBillRow` 原数量、单价、税率、含税金额、不含税金额和税额；
- `Settlement`、`SettlementLine`、`PaymentRequest`、`PaymentExecution` 的记录数和金额合计；
- 原合同、结算、付款、实付和入账状态；
- 原审批实例和审批节点数量。

### 3.2 迁移后允许新增或变化的事实

- 新增 `ContractTaxFactRevision`、`SettlementDraft` 空表；
- 新增合同版本税务字段、清单价格状态字段和结算税务快照字段；
- 迁移前既有清单行统一标记 `precisionPolicy = legacy`；
- 只有同时具备可证明票种和有效税率的非历史接管合同允许按迁移规则回填；
- 无法证明的历史事实保持 `null`、`unconfirmed`，不得推断成 `0` 或默认税率；
- 迁移不得创建结算草稿、审批实例或业务操作日志。

## 4. 角色 UAT

UAT 使用隔离测试数据或用户另行批准的生产试运行数据。每一步记录操作者、时间、业务编号、预期结果和实际结果，不记录密码或私有文件内容。

### 4.1 新合同

合同员：

1. 创建固定总价无清单合同，选择发票类型和税率，填写含税合同总价。
2. 创建单一税率有清单合同，录入最多两位小数的数量和含税单价。
3. 创建特殊多税率合同，只对例外行填写覆盖税率。
4. 创建不设总价框架合同，预计数量留空。
5. 保存后重新打开，确认未知预计数量显示“按实际发生量结算”，不显示伪造的 `0`。
6. 提交合同审批，确认税务事实冻结且审批路线保持不变。

预期：

- 未选择票种、税率或必要含税单价时不能提交审批；
- 新录入数量、含税单价超过两位小数时被中文提示阻断；
- 合同金额只由既定后端口径产生；
- 固定总价无清单合同不虚构清单单价。

### 4.2 历史合同补录

合同员：

1. 打开票种、税率和单项含税单价均缺失的历史接管合同。
2. 新建税务事实修订，录入候选票种、税率和缺价行。
3. 不上传附件时填写明确确认说明。
4. 提交财务复核。

财务主管：

1. 查看变更前快照、候选事实和行级价格。
2. 退回一次并填写原因。
3. 确认原修订记录未被覆盖，合同员基于退回意见重新提交。
4. 复核通过。

合同部主管：

1. 查看财务复核意见。
2. 确认补录。
3. 验证合同版本当前事实、修订号和行级价格仅在最终确认后更新。

预期：

- 历史接管本身不自动确认税务事实；
- 每次提交、退回、复核和确认均保留独立时间与操作者；
- 合同员没有财务复核或合同部确认权限；
- 财务主管不能代替合同部主管最终确认。

### 4.3 结算草稿与提交

合同员：

1. 对缺失含税单价的历史合同创建结算，选择受影响行并填写本期数量。
2. 保存草稿。
3. 确认草稿未占用额度、未创建审批实例，提交按钮被精准阻断。
4. 完成 4.2 的税务事实确认后，从结算台账“我的草稿”继续填写同一草稿。
5. 确认页面自动重新请求后端核算，原数量和备注仍存在。
6. 提交结算审批。

预期：

- 未选择的缺价行不阻断本期结算；
- 已选择缺价行只显示“待确认”，不显示 `0`；
- 税务事实补齐后复用同一草稿，不要求重建；
- 提交事务重新校验合同版本、税务事实、金额和审批资格；
- 提交后的结算快照包含票种、税率、含税单价和税务事实修订号。

## 5. 发布步骤

只有用户批准精确候选 SHA 后才能执行：

1. 快进并推送获批候选，不混入新提交。
2. 确认生产服务器当前运行 SHA、服务健康和 51 个迁移。
3. 执行发布前数据库备份；必须同时生成本地 dump、checksum 和有效异机收据。
4. 再次核对候选 SHA、迁移目录数量和备份收据。
5. 使用现有生产部署入口部署 Web/API 并执行第 52 个迁移。
6. 检查 PostgreSQL、API、Nginx、Cron 和数据库备份监控。
7. 运行公网 health、未认证 401、登录页及合同/结算关键页面只读验证。
8. 未经额外授权，不创建或修改真实合同、结算、付款和文件。

## 6. 发布后最小验证

- API health 成功，Web 可加载；
- `prisma migrate status` 显示最新，数据库为 52 个完成迁移；
- 原 4 个合同版本数量不变，无法证明的税务事实仍为未确认；
- 原结算、付款和实付记录数、金额与状态不变；
- 新合同工作台能选择发票类型和税率；
- 历史接管能看到税务事实缺口与复核入口；
- 结算草稿可以保存，正式提交仍由后端门槛决定；
- 审批、文件下载、付款和审计受保护流程无回归。

## 7. 回滚

### 7.1 应用回滚

安全应用回滚点：

```text
d090e5c31bf85094b5661b67e67f60ade191a28f
```

该提交已理解新增税务字段、空历史价格、新状态、税务修订和结算草稿结构。发生 UI、E2E 收口或非数据类运行问题时，数据库保留第 52 个迁移，应用回滚到该提交。

### 7.2 禁止回滚到旧生产代码的条件

一旦生产已经写入任一以下事实，不得回滚到 `48b5ec3f`、`b857a426` 或其他不理解新结构的代码：

- 合同税务事实修订；
- 新税务字段或行级价格状态；
- 结算草稿；
- 带税务快照的新结算。

### 7.3 数据库回滚

- 不在生产手写 down migration。
- 迁移已执行但尚无新功能写入时，优先保留兼容新增结构并回滚应用。
- 如必须完全撤销数据库，停止业务写入并使用迁移前已验证备份恢复；恢复目标、RPO、RTO 和数据差异须单独审批。

## 8. 停止条件

出现以下任一情况立即停止，不继续部署：

- 最终 SHA 与用户批准 SHA 不一致；
- 最新异机备份、checksum、收据或 `pg_restore --list` 任一失败；
- 隔离恢复不能从 51 正常升到 52；
- 迁移前后既有金额、数量、单价、结算或付款事实漂移；
- 受保护目录出现未经批准的差异；
- 全量测试、build、P0 E2E 或公网健康验证失败；
- 发现用户未提交修改冲突、权限扩大或审批路线变化。
