# P0-4A 真实试运行初始化清单与最小 Runbook

日期：2026-07-03
状态：试运行前执行模板；2026-07-04 已同步 P0-7 常用单据和试运行账号脚本
范围：1 个真实项目、约 20 个历史合同、3-5 个活跃合同、项目付款审批表 PDF、结算附件模板、差旅/招待/报销最小综合费用；不包含批量导入器、OCR、小程序、完整 OA 报销和多项目推广。

## 使用原则

- 本文只放脱敏字段、检查项和操作顺序，不保存真实姓名、手机号、合同金额、账号密码、业主信息或附件链接。
- 真实数据只进入生产或生产等价环境；沟通文档中使用 `<项目编号>`、`<合同编号>`、`<人员姓名>` 这类占位符。
- 现有代码已有试运行所需的最小入口：项目、岗位、项目成员、业主主合同、对上审定、业主收款、总包代付、历史合同接管、结算、付款、项目付款审批表 PDF、结算附件模板下载、综合费用、实付和审计。P0-4A 不新增导入平台。
- 金额资料统一按「元」收集，系统接口和数据库按「分」保存；录入前由经办人复核换算，禁止手工四舍五入不留痕。
- `super_admin` 只用于技术运维，不代表合同、预算、财务或项目经理做业务确认。

## 最小 Runbook

### 1. 资料准备

1. 确认唯一试运行项目，冻结项目编号、项目名称和项目经理。
2. 收集业主主合同扫描件、收款条款、质保金条款、对上审定资料、历史收款资料。
3. 汇总约 20 个历史合同，按 A/B/C 分级；先选出 3-5 个活跃合同。
4. 对 A 级合同逐份收齐合同扫描件、补充协议、结算单、付款审批单、银行回单、总包代付记录和余额来源摘要。
5. 标记缺资料项；缺资料允许存在，但必须写清楚是否阻断付款。

### 2. 账号 / 岗位初始化

1. 复用 `services/api/prisma/seed.cjs` 的岗位 key 和 Prisma 写法，初始化真实 `User`、`UserPosition`、`ProjectMember`。
2. 每个真实用户只使用自己的手机号；不得继续使用 seed 手机号段。
3. 真实账号初始密码只通过线下安全渠道发放，不写入仓库、聊天记录、截图或共享文档。
4. 设置 `mustChangePassword=true`，并让用户首次登录后调用 Web 改密入口或 `/api/auth/change-password`。
5. 用合同部、预算、财务、项目经理账号分别登录，确认 `/api/projects` 只返回自己有岗位的项目。

### 3. 项目初始化

1. 创建或确认 `Project(code, name, isActive=true)`。
2. 写入项目成员 `ProjectMember(projectId, userId, positionKey)`。
3. 合同部经办上传业主主合同私有文件，调用业主主合同登记入口。
4. 合同部主管用当前密码确认业主主合同。
5. 预算录入已有对上审定，财务录入已有业主收款；附件必须走私有文件。

### 4. 历史合同录入

1. 合同部经办进入 Web「历史合同接管」。
2. 先录 3-5 个 A 级活跃合同，再录剩余 B/C 合同。
3. 金额按元收集、按分提交；提交前二人复核换算。
4. `balanceSourceSummary` 写余额来源摘要，`evidenceSummary` 写证据和缺资料说明。
5. 当前最小系统只有一次接管确认；预算、财务、项目经理的复核结果先作为附件/证据摘要留存，合同部主管确认前必须看到这些留痕。

### 5. 复核确认

1. 合同部经办提交接管复核。
2. 预算复核历史结算口径，财务复核已付、待付、总代付和凭证，项目经理复核项目归属和履约状态。
3. 存在金额无法确认、关键附件缺失或合同归属不明时，保持「需补资料」或不确认。
4. 合同部主管用当前密码二次确认接管；系统会将历史合同版本和付款条款置为 effective，并写审计。
5. 确认后不得静默改关键金额；需要更正时先记录原因、责任人和附件，再进入后续更正切片。

### 6. 付款 / 结算试运行

1. 从 A 级活跃合同中选择 1 个付款案例，发起付款预览，确认历史余额已进入容量扣减。
2. 发起付款申请，跑完审批、出纳实付、凭证上传、财务记录和 PDF 归档。
3. 从 A 级活跃合同中选择 1 个结算案例，跑完结算审批、归档确认和后续付款预览。
4. 下载收方单、签工单、零星机械签认单、台班记录表模板中的至少 1 个，线下填写签字后上传为结算附件。
5. 以差旅、招待、报销中至少 1 类发起综合费用，跑完审批、已批待付、出纳实付、凭证上传、财务记录和审计。
6. 对比财务台账与系统读模型：合同金额、累计结算、已付、已批待付、总代付、可申请金额、综合费用支出。
7. 记录每个卡点，只修 P0 主链路问题，不扩外围模块。

### 7. 安全检查

1. seed 通用密码处理完成，且没有活跃 seed 账号可登录。
2. 生产 `DATABASE_URL`、JWT 密钥、COS 密钥、CORS 和 Web API 地址均为生产值，未提交仓库。
3. PostgreSQL 不公网暴露，COS 为私有桶，文件下载走后端鉴权和短时效票据。
4. 敏感动作二次确认可用：接管确认、业主主合同确认、收款、总代付、实付、文件下载。
5. 审计抽查可追到登录、接管、确认、付款、实付、文件下载和权限变更。
6. 每日备份与恢复演练有记录；日志轮转和错误告警已配置。

## seed 通用密码停用 / 修改步骤

当前 `services/api/prisma/seed.cjs` 使用 `const testPassword = "Jgzg@2026"`，并把 seed 账号写成 `mustChangePassword=true`。这只适合开发和演示，不适合真实试运行。

推荐处理方式：停用 seed 账号，真实用户使用真实手机号和一次性临时密码。

```sql
BEGIN;

UPDATE "RefreshToken"
SET "revokedAt" = now()
WHERE "revokedAt" IS NULL
  AND "userId" IN (
    SELECT "id" FROM "User" WHERE "id" LIKE 'seed-user-%'
  );

UPDATE "User"
SET "isActive" = false,
    "mustChangePassword" = true,
    "updatedAt" = now()
WHERE "id" LIKE 'seed-user-%';

COMMIT;
```

验收查询：

```sql
SELECT "id", "phone", "name", "isActive", "mustChangePassword"
FROM "User"
WHERE "id" LIKE 'seed-user-%'
ORDER BY "phone";
```

如因冒烟测试必须临时保留某个 seed 账号：

1. 仅在生产等价环境短时保留，记录保留原因和截止时间。
2. 立即把密码改为个人唯一密码，禁止继续使用 `Jgzg@2026`。
3. 改密后撤销该用户所有 refresh token。
4. 冒烟完成后停用账号。

注意：`mustChangePassword` 当前会返回给前端，但 Web 尚未强制拦截所有业务页；试运行验收必须以「seed 账号已停用」或「逐个账号人工确认已改密」为准。

## 验收标准

- 真实用户可登录，且 seed 通用密码无法登录真实试运行账号。
- 合同部、预算、财务、项目经理、董事长/总经理的项目岗位符合实际职责。
- 业主主合同已登记并确认。
- 约 20 个历史合同清单已完成 A/B/C 分级。
- 3-5 个活跃合同已补齐付款/结算试运行需要的历史余额来源。
- A 级合同完成接管确认后，付款容量能扣减历史已付、已批待付、审批中占用、总包代付和其他确认占用。
- 至少 1 条真实付款、1 条真实结算和 1 条综合费用能按 Runbook 跑完并留下审计。
- 项目付款审批表 PDF、结算附件模板下载和上传归档、综合费用凭证下载票据均由真实岗位账号验收。
- 缺资料和余额未确认的合同不能绕过系统发起付款。
