# P0-5C 真实试运行前最终闸门清单与人工 UAT 记录模板

日期：2026-07-03
状态：试运行 Go / No-Go 人工签认模板
范围：1 个真实项目、约 20 个历史合同、3-5 个活跃合同；用于 P0 真实试运行前最后一次业务、财务、合同、项目和技术共同验收。

## 使用原则

- 本文只记录脱敏编号、检查结论、证据路径和签字结论；不得写入真实手机号、密码、密钥、完整数据库连接串、COS Secret、银行账号、完整合同金额或敏感附件直链。
- 自动脚本通过不等于业务可上线。`verify:production-readiness` 和 `verify:trial-run` 只能作为辅助证据，最终 Go / No-Go 必须由人工签认。
- P0 问题未关闭时不得进入真实试运行；P1 问题必须有负责人、到期日和临时控制措施后，才能由老板决定是否带风险 Go。
- `super_admin` 只代表技术运维，不得代替合同部、财务、项目经理或老板做业务确认。
- 本模板可复制到 UAT 会议纪要中填写；仓库内模板保持占位符，不保存真实业务数据。

## 最终闸门规则

| 闸门 | Go 标准 | No-Go 条件 | 必签 |
| --- | --- | --- | --- |
| 生产安全 | 环境变量、密钥、HTTPS、数据库、COS、时间同步、日志告警全部通过或仅有已接受 WARN | 密钥疑似默认值、PostgreSQL 公网暴露、COS 公开读、HTTPS 不可用 | 技术 / 运维 |
| seed 密码 | `Jgzg@2026` 不能登录真实试运行账号，seed 账号停用或已逐个改密并撤销 token | 任一真实账号仍可用 seed 通用密码登录 | 老板、技术 / 运维 |
| 数据初始化 | 项目、成员、岗位、账号、业主主合同、20 个历史合同和 3-5 个活跃合同清单完成 | 项目成员或关键岗位缺失；业主主合同未确认；历史合同台账不完整 | 合同部、项目经理 |
| 历史余额 | A 级合同历史余额来源可追溯，财务确认已付、已批待付、审批中、总包代付和其他占用 | A 级活跃合同余额无法解释，仍允许发起付款 | 财务、合同部 |
| 核心链路 UAT | 自动 UAT 通过，人工 UAT 至少覆盖接管、结算、付款、超额拦截、审计、首页入口 | 未确认接管可付款；超额付款未拦截；关键审计缺失 | 财务、合同部、项目经理 |
| 文件安全 | 私有桶、短时效下载、权限拒绝、下载审计通过 | 未授权账号能下载敏感文件；公开链接可直接访问 | 合同部、技术 / 运维 |
| 备份恢复 | 数据库和附件备份可恢复到隔离环境，演练记录可追溯 | 没有恢复演练，或恢复后关键表/附件不可用 | 技术 / 运维 |
