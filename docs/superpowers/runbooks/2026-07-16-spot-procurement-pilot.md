# 零星采购真实表单试点与发布 Runbook

## 1. 边界

本 Runbook 仅覆盖公司现行真实表单的零星采购闭环：A4 竖向无价《零星/小额材料采购申请表》、A5 横向《项目零星付款申请单》、分次实际付款、一次最终收货、少货补货或退款、付款级可后补发票、不可变审批原件和追加式归档包。

新流程不写商户余额、不使用结构化发票覆盖或无票确认作为办结条件；费用报销、借款和员工项目往来不在本次发布范围。试点项目之外不得开放入口，`SPOT_PROCUREMENT_PILOT_PROJECT_IDS` 绝不能设为 `*`。

生产动作必须逐项获得用户授权：推送/合并、备份、隔离恢复、迁移、部署、白名单变更与真实 UAT。授权不允许代替真实人员登录、重置既有密码、伪造审批或直接写库。

## 4. 十三个受控 UAT 场景

每个场景都要记录项目、单号、真实操作角色、审批动作、A4/A5/A4 明细或归档版本、私有文件下载审计及最终状态。只在试点项目中执行。

1. 无价 A4 采购申请经物资主管、项目经理批准后生成唯一 A5 付款草稿。
2. 公司直付、商户与收款对象一致：一次实际付款、凭证、一次最终收货和复核。
3. 商户与收款对象不一致：填写简要说明并通过付款审批。
4. 经办人垫付报回：收款对象固定为采购经办人，仍走零星付款审批。
5. 一张付款两次实际付款，各自上传凭证；首笔有效付款后才开放收货。
6. 现金付款上传收据，后续可补传付款级发票。
7. 全部无票，付款、收货条件满足后正常办结。
8. 存在预计有票材料但暂未上传发票，正常办结后追加发票且只新增归档版本。
9. 同项目受托人从相册上传收货照片；服务端生成水印，物资主管复核。
10. 少货后选择商户继续补货：撤销复核、生成新收货修订并重新复核。
11. 少货多付后选择退款：财务登记退款到账并上传凭证。
12. 实付后由财务主管显式确认异常终止；不得改写已冻结审批或资金事实。
13. 核对 A4/A5 审批原件哈希不变；付款、退款或发票只追加 A4 明细/归档版本。

## 5. 发布前只读审计与停止条件

1. 绑定候选 SHA：核对 `git rev-parse HEAD`、`git status --short`、分支拓扑、`origin/main`、迁移清单与 `.superpowers/` 忽略边界；候选工作树必须完全干净。
2. 只读记录生产 HEAD、`prisma migrate status`、当前白名单、API/Nginx/PostgreSQL 健康、COS 私有文件下载和审计链路；生产入口应仍关闭。
3. 生成最新生产备份，并验证本地 dump、SHA-256、`pg_restore --list` 与异机回执。
4. 只在空的 `jiangkong_restore_*` 隔离库恢复备份，使用精确候选 SHA 运行 `db-restore-drill.sh` 的候选迁移模式；核对迁移前后计数、关键旧表摘要和零星采购新模型零记录保护。
5. 核对 A4 竖向 595.28 × 841.89pt、A5 横向 595.28 × 419.53pt、A4 明细附页，含固定签字格、长文本、九行以上分页和归档顺序。

任何一项出现生产零星采购新模型非零、迁移未完成、非试点 capability 开启、资金/文件/审计异常、PDF/水印不可读或健康失败，立即停止：白名单保持关闭，应用回到发布前 SHA，绝不执行破坏性 down migration。

## 7. 获授权后的执行顺序

1. 冻结写入窗口，记录生产 HEAD、`origin/main`、白名单、运行健康与候选 SHA。
2. 推送候选并以精确 SHA 快进合并 `main`；只部署该 SHA。
3. 在生产端执行经异机校验的发布前备份。
4. 在隔离恢复库恢复该备份，按 `CANDIDATE_SHA_CONFIRMATION` 运行候选迁移；失败或零记录保护触发即停止。
5. 使用既有 GitHub Actions 与服务器 `deploy-production-server.sh` 部署；脚本会在迁移前二次备份，在失败时恢复应用运行时目录，不回滚数据库迁移。
6. 核对运行 SHA、61 条迁移、内外网 `/health`、Nginx、PostgreSQL、COS 私有文件及审计；白名单仍为空时先做只读 capability 检查。
7. 仅将 `seed-project-jgxm-001` 写入白名单，核对它为 `enabled=true`、其他项目为 `enabled=false`。
8. 由真实人员本人完成最小链路和第 4 节抽验；失败立即清空白名单并保留所有审计/事实。

## 8. 回滚原则

应用故障：回退 API/Web 至发布前 SHA，恢复发布前环境文件并重启服务；数据库不执行 down migration，新增事实保留用于审计。只有确认历史数据被错误改写时，才另行取得恢复授权并使用已验证备份。
