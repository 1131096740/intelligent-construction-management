# 零星采购小项目试运行与发布 Runbook

## 1. 边界

本 Runbook 只覆盖零星采购、零星材料付款、最终收货、差异、退款、供应商余额、票据覆盖和自动办结。费用报销、借款和员工项目往来不在本次发布范围。

生产操作分成两个独立授权点：

1. 候选授权：确认试点项目和最小人员，允许在生产等价环境完成只读审计与受控 UAT。
2. 生产授权：分别允许推送/合并、备份、迁移、白名单变更、部署和真实写入。

没有逐项授权时，不得连接生产执行写操作，也不得把 `SPOT_PROCUREMENT_PILOT_PROJECT_IDS` 设置为 `*`。

## 4. 十三个零星采购 UAT 场景

每个场景记录项目、单号、角色、审批节点、跳过事实、三类 PDF、付款凭证、水印照片、送货单、实际成本、差异、退款/余额、发票/无票、办结和审计下载记录。

1. 物资员申请，经物资主管、项目经理批准，生成付款草稿。
2. 物资主管申请，跳过本级，由项目经理批准。
3. 公司直付供应商，多笔实际付款和凭证。
4. 经办人垫付后报回。
5. 先收货后付款。
6. 先付款后收货，委托同项目人员从相册上传。
7. 少货且未付满，取消未执行额度。
8. 少货多付，供应商整笔退款到账。
9. 少货多付，整笔转同项目同供应商余额并在后单抵扣。
10. 全部无票并由财务主管确认。
11. 部分发票、部分无票。
12. 发票类型或税率异常，经财务主管确认。
13. 最后一项条件满足后自动办结，办结后所有更正入口锁死。

借款和报销两个场景留给独立费用与报销计划。

## 5. 发布前只读审计

1. 核对候选提交与分支拓扑：`git rev-parse HEAD`、`git status --short`、`git log --oneline -20`。
2. 在临时恢复库执行全部迁移和 `prisma migrate status`；不得在生产库先试错。
3. 核对六条迁移只新增/强化零星采购及共享文件约束，不推断迁移、删除或改写旧 `ProjectExpenseRequest` 历史。
4. 核对 `/etc/jiangkong/api.env` 中 `SPOT_PROCUREMENT_PILOT_PROJECT_IDS` 只含用户确认项目，不得使用 `*`。
5. 只读验证 COS 私有文件、中文文件名、采购/付款/收货 PDF 和水印图片下载链路。
6. 回滚采用应用回滚并保留新增表数据，不执行破坏性 down migration。

授权完成不等于真实链路已经执行。真实账号的登录、首次改密和审批必须由账号本人完成，不允许以后台改库、伪造令牌或重置现有账号密码代替。

## 7. 获授权后的执行顺序

1. 冻结试点写入窗口并记录生产 HEAD、`origin/main` 和工作树。
2. 执行 `BACKUP_DIR=/srv/jiangkong-backups/db /opt/jiangkong/scripts/ops/db-backup.sh`。
3. 记录备份路径、大小、权限、SHA-256、文件格式与 `pg_restore --list`。
4. 在临时恢复库恢复该备份并应用迁移；核对旧项目支出行数和关键金额摘要不变。
5. 备份 `/etc/jiangkong/api.env`，仅写入确认后的项目 ID；权限保持 600。
6. 通过既有 GitHub Actions 和服务器 `deploy.sh` 部署，不绕过 `main` 发布门禁。
7. 核对生产 HEAD、Prisma migration status、API、Nginx、PostgreSQL、HTTPS 和 `/api/health`。
8. 运行 `/opt/jiangkong/scripts/ops/check-runtime-health.sh`。
9. 用 capability API 验证试点项目 `enabled=true`，其他项目 `enabled=false`。
10. 再次取得真实写入授权后，执行一条最小完整链路并留存审计证据。

## 8. 停止与回滚

出现迁移失败、权限越界、金额不一致、文件公开、PDF/水印不可读、非试点项目 capability 开启或健康检查失败时立即停止。应用回滚到发布前 SHA；恢复原环境文件并重启 API；保留已经写入的新表数据用于审计，不删除迁移表或执行 down migration。只有确认生产数据遭到错误改写时，才按独立恢复授权使用已验证备份。
