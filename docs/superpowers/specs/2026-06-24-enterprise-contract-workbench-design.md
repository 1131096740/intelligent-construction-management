# 建工智管企业级合同工作台设计

日期：2026-06-24  
状态：已由用户逐章确认  
范围：第一版企业级合同管理能力

## 1. 目标

把当前简易合同草稿升级为专业合同台账和高级合同编辑器，覆盖：

- 材料采购、机械租赁或服务、劳务分包、专业分包、采购服务；
- 补充协议、合同解除或终止协议、其他项目协议及其他合同类型；
- 合同字段、条款、多张清单、附件、正式 Word/PDF；
- 线下磋商、审批、用印、线下签署和电子归档；
- 结算、质保金、付款、发票、批量付款；
- 历史合同补录、电子档案包、提醒、权限和审计。

第一版必须形成以下闭环：

```text
合同草稿
  -> 合同编辑与文档生成
  -> 可选线下磋商
  -> 合同审批
  -> 用印审批
  -> 线下签字盖章
  -> 已签文件归档确认
  -> 合同版本生效
  -> 结算审批及归档生效
  -> 付款申请审批
  -> 财务人工付款
  -> 凭证、发票、档案包和审计
```

## 2. 核心原则

### 2.1 混合架构

采用“固定业务核心 + 版本化动态模板”：

- 审批、金额、价税、结算、付款、发票、版本、归档和审计使用固定关系型模型；
- 合同类型专属字段、清单扩展列、条款、附件要求和简单显示条件使用动态模板；
- 动态模板不得改变资金控制、状态机和审计字段的业务含义；
- 合同创建后冻结模板快照，模板更新不追溯影响历史合同。

### 2.2 唯一业务数据源

合同工作台中的结构化数据是正式数据源：

- Excel 是清单批量输入和交换格式；
- Word 是磋商和正式签署载体；
- PDF 是固定审批、预览和归档证据；
- Excel、Word 或 PDF 的线下修改不得直接覆盖系统数据；
- 接受的外部修改必须回填工作台，再重新生成文件。

### 2.3 资金控制

- 付款只能来源于生效结算单或生效的预付款依据；
- 结算单是付款申请、审批和支付的唯一业务依据；
- 结算、付款和实际支付金额由后端事务控制；
- 审批通过不等于实际付款；
- 系统不得直连网银或自动发起资金划转。

## 3. 总体架构

```text
Vue 3 + TypeScript + TDesign Web 合同工作台
                    |
                    v
              NestJS 业务 API
                    |
          +---------+---------+
          |                   |
          v                   v
 PostgreSQL 业务与审计     私有文件存储/COS
          |                   |
          +---------+---------+
                    |
                    v
       DOCX 生成 / PDF 转换 / OCR / 文件对比
```

文档生成、附件合并、OCR 和大型差异比较采用异步任务。任务状态包括排队、处理中、成功和失败；失败可重试，但不得重复产生正式版本。

直接复用现有能力：

- 审批实例冻结、会签、或签、转审、委托、撤回、催办和审计；
- 合同、结算和付款基础状态机；
- 私有文件、COS、下载权限、二次确认和下载审计；
- 合同、结算、付款审批单 A4 PDF、公司抬头、手写签名和下载水印；
- 后端金额事务校验。

不建设第二套审批引擎或文件系统。

## 4. 专业合同台账

合同台账是合同模块默认入口，不使用普通卡片列表。

### 4.1 检索与筛选

第一版支持：

- 合同编号、合同名称；
- 项目、合同类型、状态；
- 合作单位、统一社会信用代码；
- 经办人、合同负责人；
- 签订日期、履约期限和风险状态。

第一版不做：

- 合同条款全文检索；
- 清单项目名称或规格型号全文检索。

### 4.2 固定台账指标

- 原合同金额；
- 补充协议累计增加、累计减少；
- 当前有效合同金额；
- 累计有效结算金额；
- 累计付款申请金额；
- 累计实际支付金额；
- 未结算金额、应付未付金额；
- 质保金余额、欠票金额；
- 合同、审批、签章、归档和履约状态；
- 当前审批节点及风险数量。

### 4.3 导出

- 按当前筛选结果导出 Excel；
- 用户可选择导出列；
- 不导出条款正文和附件文件；
- 记录导出人、时间、筛选条件、字段和数据行数；
- 导出不得突破用户已有数据权限。

## 5. 合同工作台

### 5.1 创建

- 点击“新建合同”直接进入空白合同工作台；
- 用户先在工作台选择项目和合同类型；
- 首次选定二者后创建草稿并生成临时编号；
- 未选择任何内容即退出时不产生空草稿；
- 合同创建后指定一名合同管理员负责编辑；
- 第一版不支持多人分章节协同编辑。

### 5.2 页面结构

顶部固定展示：

- 临时或正式编号、合同名称、合同类型和项目；
- 当前状态、合同版本和审批节点；
- 当前金额、保存状态和最后保存时间；
- 完整度、风险数量和文档是否过期；
- 审批、用印、归档和生效状态。

左侧章节：

1. 合同概览
2. 基本信息
3. 合同主体
4. 专业字段
5. 工程量及价格清单
6. 价税与控制金额
7. 结算付款约定
8. 合同条款
9. 附件与资质
10. 磋商记录
11. 文档生成
12. 审批、签章与归档
13. 版本及审计

右侧实时检查：

- 必填字段；
- 金额及价税差异；
- 清单错误；
- 附件缺项或过期；
- 必备条款和文本规则；
- 未复核联动项；
- 送审准备状态。

### 5.3 保存与草稿版本

- 自动保存和手动“保存草稿”并存；
- 自动保存只更新当前草稿，不产生版本；
- 手动保存产生可恢复检查点；
- 每份合同只保留最近 5 个手动草稿版本；
- 已命名或锁定版本也计入 5 个名额；
- 超过数量时删除最旧版本前提示；
- 提交审批时才永久冻结送审版本；
- 保存批次记录修改摘要，关键变化记录前后值；
- 断网时本地暂存，恢复后受控同步；
- 多窗口版本冲突时暂停自动保存，禁止静默覆盖。

### 5.4 草稿入口与权限

- 合同台账提供“我的草稿/待提交合同”入口；
- 工作首页展示最近编辑草稿；
- 草稿仅合同负责人可编辑；
- 合同负责人上级可查看和转交负责人；
- 其他人员在提交前不可见；
- 草稿不物理删除，只能填写原因后作废；
- 已作废草稿可查询和恢复，操作永久留痕。

### 5.5 更换合同类型

- 草稿阶段允许更换合同类型；
- 更换前展示迁移预览；
- 通用字段保留；
- 不兼容的字段、条款和清单经确认后清除；
- 原数据进入审计记录；
- 提交审批后禁止更换合同类型。

## 6. 正式编号

- 编号模板可配置公司、项目、年份、合同类型和流水号；
- 草稿阶段使用临时编号；
- 提交审批前生成或确认正式编号；
- 正式编号全局唯一；
- 正式编号进入审批后锁定，修改需撤回并记录原因；
- 驳回或作废后编号永久保留，不回收；
- 历史补录优先保留原合同编号；
- 原编号重复时增加系统内部唯一档案号，并标记冲突。

## 7. 模板与条款治理

### 7.1 模板类别

- 业务模板；
- Excel 清单模板；
- DOCX 版式模板；
- 标准条款库。

业务模板和版式模板分离。业务模板负责数据与规则，版式模板负责正式文件呈现。发布时建立版本绑定。

### 7.2 状态

```text
草稿 -> 检测中 -> 待发布 -> 已发布 -> 已停用
                                 \-> 已撤销
```

- 合同管理员制作和提交发布；
- 合同负责人复核发布；
- 技术管理员不参与业务内容发布；
- 已发布版本不可覆盖；
- 修改必须复制形成新版本并重新检测、预览和发布；
- 已被合同引用的版本不得物理删除；
- 停用模板允许既有草稿继续使用，但显示提醒；
- 撤销模板禁止新合同使用，既有草稿必须换版后提交；
- 审批中和已生效合同不受模板状态变化影响。

### 7.3 动态字段

支持：

- 文本、长文本；
- 数字、金额；
- 日期；
- 单选、多选；
- 开关；
- 必填、默认值、选项、分组和排序；
- 仅支持“等于/不等于”的简单显示条件。

不支持：

- 自定义脚本；
- 任意公式；
- 任意数据库关联；
- 管理员编程式规则。

已发布字段只能在新模板版本中停用，字段编码永久唯一且不得复用。

### 7.4 标准条款库

- 按分类检索和插入；
- 条款草稿由合同管理员维护，合同负责人复核发布；
- 已发布条款不可覆盖，只能形成新版本；
- 插入合同后形成独立快照；
- 合同内可以针对本合同修改；
- 条款库更新不追溯影响既有合同；
- 偏离标准条款时显示差异并进入审批材料，但不自动禁止提交。

## 8. 多主体和主体档案

### 8.1 多主体

支持甲方、乙方、丙方、担保方、联合体成员等多个合同主体。每个主体冻结签约时档案快照。

### 8.2 主体档案

- 以统一社会信用代码作为企业主体主要唯一标识；
- 无统一代码时允许受控替代标识并提示重复风险；
- 名称、代码、法定代表人等变化时形成新档案版本；
- 新合同使用新版本，历史合同保留原快照；
- 营业执照、开户资料、身份证、授权书和资质文件可复用；
- 合同冻结附件引用和哈希，不重复保存相同文件实体；
- 原档案附件替换不影响历史合同；
- 资质附件可配置有效期和到期提醒；
- 过期附件是否拦截由合同模板决定。

### 8.3 银行账户

合作单位可维护多个收款账户：

- 户名、开户银行和账号必填；
- 账户证明附件可选；
- 合同管理员或付款经办人可提交新增账户；
- 财务负责人确认后生效；
- 确认前不得用于付款；
- 付款时只能选择有效账户库中的账户；
- 偏离合同冻结账户时仅风险提醒并留痕；
- 不强制上传账户变更证明，也不额外增加审批节点。

我方付款账户：

- 由财务人员提交维护；
- 财务负责人确认后生效；
- 业务人员只读；
- 实际付款只能选择有效账户。

## 9. 多清单和 Excel

### 9.1 多清单

一份合同允许包含多张独立清单，例如主材、辅材、运输费或机械台班表。

每张清单配置金额属性：

- 计入合同金额；
- 仅作参考；
- 不计价；
- 暂估金额。

系统分别计算小计，再汇总合同控制金额，并区分确定金额与暂估金额。

### 9.2 Excel 模板

- 不同合同类型使用不同 Excel 模板；
- 每张清单使用一个独立 Excel 文件；
- 文件可以包含填写说明工作表；
- 系统只解析一个指定的数据工作表；
- 数据区不得使用合并单元格；
- Excel 公式只用于辅助填写；
- 系统必须根据原始数量、单价和税率重新计算核心金额；
- 不信任 Excel 公式结果；
- 列识别使用稳定内部字段编码，不只依赖中文表头。

### 9.3 导入与网页编辑

支持：

- 下载对应模板；
- 上传 Excel 并进行导入预览；
- 网页新增、编辑、删除和复制清单行；
- 全量替换；
- 按内部行编号匹配更新；
- 仅追加新项目。

首次导入后系统生成内部行编号，后续导出带出该编号。

导入预览必须展示：

- 新增、更新、跳过行数；
- 工作表、行、列级错误；
- 导入后合同金额变化；
- 差异确认结果。

原始 Excel、导入方式、导入人、时间、变更前后差异和校验结果永久保留。

### 9.4 核心列

系统固定核心列至少包括：

- 项目编码、名称、规格型号；
- 单位、数量；
- 含税或不含税单价；
- 税率；
- 含税金额、不含税金额和税额；
- 是否暂定；
- 结算计量方式；
- 内部行编号。

模板可以增加专业扩展列，但结算和付款核心金额只依赖固定列。

### 9.5 精度与价税

- 第一版仅支持人民币；
- 数量精度由模板配置 0 至 6 位，默认 3 位；
- 单价精度由模板配置 2 至 6 位；
- 税率最多 4 位小数的百分数；
- 中间计算使用高精度十进制定点数，不使用浮点数；
- 行金额、税额、合同、结算和付款金额精确到分；
- 每行先舍入到分，再汇总清单和合同金额；
- 记录舍入差额；
- 不允许系统静默分摊尾差或修改单价。

每张清单固定一种主计价模式：

- 含税单价录入，系统反算不含税价和税额；
- 不含税单价录入，系统正算含税价和税额。

同一清单允许不同清单行使用不同税率。

合同约定总价与清单合计不一致时，通过优惠、取整、暂列或其他调整项处理，必须填写原因并审计。

## 10. 合同计价性质

支持：

- 固定总价；
- 暂定总价或单价合同；
- 框架合同。

规则：

- 固定总价可与清单合计不同，但必须填写差异原因；
- 暂定总价或单价合同以清单形成预计金额，结算按实际量；
- 框架合同可设置上限，也可不设置上限；
- 无上限框架合同提交审批时触发高风险提醒；
- 无上限框架合同的金额补充协议一律走加强审批。

## 11. 条款编辑与检查

### 11.1 编辑器

条款按章节管理，支持：

- 自动编号和模板固定编号；
- 多级编号；
- 加粗、下划线和列表；
- 小型表格；
- 结构化变量占位符。

固定编号模式检查重复和断号。网页不支持自由分页、浮动文本框等 Word 排版能力。

### 11.2 联动

清单、主体或字段变化时：

```text
重新计算价税和控制金额
-> 更新金额大写及条款变量
-> 标记受影响条款待复核
-> 标记既有 Word/PDF 已过期
```

系统计算值不可覆盖；允许调整值可以覆盖，但必须填写原因并保留原计算值。

### 11.3 必备条款检查

采用“必备条款清单 + 确定性文本规则”：

- 必备条款缺失、条款为空、核心付款依据缺失时硬性拦截；
- 质保金返还、争议解决、违约责任等不清晰时风险提醒；
- 风险提醒可说明后提交，说明进入审批记录；
- 合同管理员可维护各合同类型检查项；
- “有效结算依据是付款前提”“不得超过有效结算余额”等资金规则由系统固化，不可删除；
- 第一版不做 AI 法律风险判断。

## 12. DOCX 与 PDF

### 12.1 DOCX 版式

- 合同管理员上传已排版 DOCX 范本；
- 系统提供占位符清单；
- 上传后检测未知、重复和缺失占位符；
- 检测表格插入点、分页、字体和签章页；
- 发布前必须使用测试数据生成完整 Word/PDF 预览；
- 同一合同类型允许多个已发布版式；
- 不设置默认版式；
- 生成正式文件或提交审批前必须人工选择版式；
- 允许跨公司直接使用版式；
- 固定公司名称、页眉、落款或签章名称与当前主体不一致时强提醒并记录确认原因；
- 第一版不处理公司 Logo。

### 12.2 版式预览

版式选择提供：

- 封面预览；
- 正文预览；
- 清单预览；
- 签章页预览；
- 分页缩略图；
- 字段兼容性检查。

更换版式只改变排版，不改变合同结构化数据。

### 12.3 生成要求

- Word 和 PDF 均为 A4；
- 正文默认纵向；
- 复杂清单允许 A4 横向分节，前后恢复纵向；
- Word 与 PDF 的页边距、分页、表格宽度和页码一致；
- 表格跨页重复表头，行内容不得异常截断；
- 附件图片按比例缩放、居中并 A4 标准化；
- 外部 PDF 合并前统一为 A4；
- 字体必须嵌入或受控替换；
- 检查乱码、字体缺失、空白页、溢出和表格越界；
- 检查失败不得标记为正式版本；
- PDF 在线预览与下载文件一致。

### 12.4 文档用途

- 草稿；
- 对外磋商稿；
- 内部送审稿；
- 正式签署稿；
- 已签归档稿。

草稿、磋商稿和送审稿使用对应水印；正式签署稿和归档稿无水印。

提交审批时同时冻结 Word 和 PDF，审批以 PDF 为主。合同负责人、合同管理员、总经理和董事长可下载送审 Word，其他审批人下载 PDF。

审批通过后基于冻结数据重新生成无水印签署版，并做哈希、页数和内容一致性校验。生成失败不得进入用印环节。

### 12.5 历史可重现

每次正式生成保存：

- 合同数据和条款快照；
- 业务模板、Excel 模板和版式版本；
- 清单版本；
- 字体和生成引擎版本；
- 实际 DOCX/PDF；
- 文件哈希、页数、生成人和生成时间。

历史审批直接打开当时实际保存的文件。重新生成件必须标记为副本，不能替代原审批或归档文件。

## 13. 可选线下磋商

合作单位不使用本系统。合同管理员负责所有外部文件收发。

合同创建时不要求决定是否磋商。提交审批前可随时开启、结束或重新开启。

### 13.1 流程

```text
工作台编制
-> 生成并下载对外 DOCX
-> 管理员线下发送
-> 对方在自有电脑修改
-> 管理员上传返回 DOCX
-> 系统与我方发送稿比较
-> 管理员逐项处理
-> 回填字段、条款或清单
-> 重新生成
-> 结束本轮
```

### 13.2 差异比较

第一版以 DOCX 为自动比较标准格式：

- 正文、表格、金额、日期和关键条款差异；
- 业务内容变化与纯格式变化分开；
- Word 清单变化提示同步网页清单或重新导入 Excel；
- PDF、扫描件和旧 DOC 可归档，但不保证精确比较。

每条差异状态：

- 接受并已回填；
- 拒绝；
- 待协商；
- 无实质变化。

存在待协商或接受但未回填的差异时，不允许结束磋商或提交审批。系统只辅助发现变化，不自动接受或回填。

重新开启磋商时创建新轮次，历史轮次冻结只读。

## 14. 审批和退回修改

### 14.1 流程匹配

- 不同合同类型可维护不同审批流程；
- 不按合同金额区间动态增减节点；
- 审批流程绑定合同类型，不绑定 Word 版式；
- 董事长或总经理最终 OR 签规则保持固化；
- 提交时冻结审批流程版本；
- 流程修改只影响之后提交的合同。

### 14.2 送审冻结

提交审批时冻结：

- 合同结构化数据；
- 主体和附件快照；
- 多张清单；
- 条款；
- 业务模板、Excel 模板和 DOCX 版式版本；
- Word、PDF 和附件目录；
- 校验结果和风险说明；
- 审批流程版本。

审批人使用单页综合审阅，可查看摘要、金额、清单汇总、付款结算条款、风险、附件目录和送审 PDF，并穿透查看原始清单和附件。

### 14.3 审批动作

- 同意、驳回、退回上一步、退回申请人和转交必须填写意见；
- 普通同意可使用快捷意见；
- 董事长或总经理最终审批必须填写意见；
- 审批人可对字段、条款、清单行或附件添加定位批注；
- 审批人不能直接修改合同内容；
- 退回后合同管理员逐条标记已修改或说明不修改。

### 14.4 再次提交

再次提交必须生成字段、条款、清单、附件和金额的完整差异。

核心变化包括：

- 主体、类型或项目；
- 金额、金额性质和控制上限；
- 数量、单价、税率和计价方式；
- 付款、结算、质保金和发票规则；
- 履约范围、工期、质量标准；
- 违约、争议和生效条件；
- 关键附件内容；
- 风险等级或审批路线条件。

处理规则：

- 核心变化从第一审批节点重新开始；
- 非核心文字、排版或说明性整改从原退回节点继续；
- 驳回后重新提交始终从第一节点开始；
- 系统自动建议分类，合同负责人确认；
- 合同管理员不能自行把核心变化降级；
- 有争议时按核心变化处理；
- 历史审批意见保留并标记对应旧送审版本、已失效。

## 15. 用印、线下签署与归档

第一版不对接电子签章平台。

### 15.1 印章档案

维护最小印章档案：

- 印章名称；
- 所属公司；
- 印章类型；
- 保管人；
- 启停状态。

不管理实体印章借出和归还。

一份合同可申请多枚印章，并分别记录：

- 用印份数；
- 盖章位置；
- 骑缝章要求。

不记录预计用印日期，也不要求印章保管人在系统确认实际用印。

### 15.2 线下签署

```text
合同审批通过
-> 生成无水印签署版
-> 用印审批
-> 线下打印、签字和盖章
-> 合同管理员上传扫描件
-> 合同负责人核对并确认归档
-> 合同版本生效
```

合同管理员上传、合同负责人确认，同一人不得完成两步。

### 15.3 扫描件

支持：

- 多 PDF/图片分批上传；
- 排序、旋转和 A4 标准化；
- 合并为完整已签合同 PDF；
- 原始扫描文件永久保留；
- 归档退回时旧批次保留并标记作废，不覆盖删除。

### 15.4 OCR 辅助核对

对照冻结签署版检查：

- 页数、缺页和重复页；
- 合同编号；
- 主体；
- 金额和日期；
- 关键条款；
- 疑似换页或文字差异。

OCR 只辅助，合同负责人承担最终核对责任。

分级处理：

- 缺页、主体或金额不一致：硬性拦截；
- 关键条款疑似变化：逐项确认，必要时重新审批和签署；
- 印章遮挡、扫描模糊或 OCR 误识别：可说明后归档；
- 核对报告、人工结论和例外说明永久保存。

归档确认时间为系统生效时间，签署日期单独记录。生效后才允许创建结算。

## 16. 补充协议与终止协议

### 16.1 补充协议

补充协议必须关联原合同，并选择：

- 增加金额；
- 减少金额；
- 不调整金额。

允许变更：

- 清单项目、数量和单价；
- 合同金额；
- 局部施工、供货或服务范围；
- 履约期限、计划节点和交付地点；
- 联系方式和有限履约性条款。

禁止变更：

- 合同主体；
- 合同性质和根本标的；
- 整体承包范围；
- 付款结算基础规则；
- 违约责任、争议解决等基础性条款。

超出白名单时要求重新签订合同。

### 16.2 加强审批

- 以原始主合同签约金额为固定计算基数；
- 全部补充协议累计增加和累计减少分别计算；
- 任一累计值超过原合同金额 10% 时触发加强审批；
- 不能用增加和减少相互抵消；
- 无上限框架合同发生金额变更时一律加强审批。

加强审批包括：

- 预算负责人复核依据和价格；
- 财务负责人复核资金影响；
- 合同负责人判断是否应重新签订合同；
- 董事长或总经理最终 OR 签。

不建设招投标模块。

### 16.3 解除或终止协议

解除或终止协议为独立合同类型，必须记录：

- 终止日期和原因；
- 已完成和未完成范围；
- 应结未结金额；
- 违约或索赔处理；
- 是否需要最终结算。

完整执行审批、用印、线下签署和归档。生效后停止新增普通结算和付款，但允许终止前事项的最终结算和尾款支付。

未完成最终结算时状态为“已终止、待清算”。尾款、索赔和扣款必须进入生效的最终结算单。

## 17. 合同完成

- 最终结算生效后，合同可以进入“履约完成、待付款”；
- 存在未支付应付款、质保金或暂缓支付款时不能关闭；
- 全部支付或正式核销后，由合同管理员发起关闭；
- 合同负责人确认后进入“已完成”；
- 已完成合同停止新增结算和付款。

## 18. 结算

### 18.1 创建

- 仅有效合同版本可创建结算；
- 项目预算员、合同管理员或合同部负责人可创建；
- 合同部负责人可替代业务人员创建；
- 结算绑定原合同版本和付款条款版本。

### 18.2 方式

- 清单计量；
- 形象进度；
- 里程碑；
- 固定金额。

所有方式最终形成结构化结算明细和有效结算金额。

### 18.3 清单与调整

默认带出：

- 合同数量；
- 历史累计已结数量；
- 本期可结数量；
- 剩余数量。

允许：

- 合同清单项；
- 变更和签证项；
- 增加项；
- 扣款和其他调整项。

超合同数量、新增项或调整项必须填写依据并上传附件。

结构化扣款包括：

- 罚款；
- 材料代扣；
- 税费调整；
- 预付款抵扣；
- 其他扣款。

每项记录金额、依据、责任说明和附件。

### 18.4 金额口径

同时展示：

- 本期产值或计量金额；
- 增加项；
- 扣减项；
- 质保金扣留；
- 预付款抵扣；
- 有效结算金额；
- 本期可付款金额。

有效结算金额和可付款金额必须分开。

累计结算金额超过当前有效合同控制金额时硬性拦截，必须先让补充协议归档生效。无上限框架合同不做金额上限拦截，但提示累计风险。

### 18.5 最终结算和纠错

- 最终结算生效后禁止新增普通结算；
- 第一版不建设独立最终结算调整流程；
- 未关联实际付款时，可申请作废后重新审批；
- 作废由合同管理员或预算员发起，合同负责人和预算负责人复核；
- 已实际付款的结算不得作废；
- 已付款错误通过关联原结算的负数调整结算冲回；
- 负数结算必须说明原因、责任和附件；
- 负余额用于抵扣后续付款，不自动触发退款。

## 19. 质保金

质保金作为结算单结构化扣留项，记录：

- 比例和金额；
- 起算日期；
- 到期日期；
- 释放条件；
- 已释放和剩余金额。

到期仅生成提醒和待办，不自动创建付款申请。释放时仍需从关联的有效结算单手工发起付款。

默认提醒：

- 到期前 30 天；
- 到期前 7 天；
- 到期日。

提醒时间和对象可配置，默认通知合同管理员、项目经理和财务人员。

## 20. 付款条款、申请和执行

### 20.1 多阶段

支持预付款、进度款、结算款、质保金等多个阶段。

每个阶段记录：

- 比例或固定金额；
- 按实际结算或余额支付；
- 触发条件；
- 付款期限；
- 发票要求；
- 付款依据。

比例不强制合计 100%，但系统检查重复和超额。每个阶段最终必须关联有效结算单或预付款依据。

### 20.2 发起

可发起人：

- 合同管理员；
- 项目预算员；
- 项目经理；
- 合同部负责人；
- 物资部负责人。

财务人员不替业务方发起普通付款申请。

付款申请展示：

- 结算有效金额；
- 已申请金额；
- 已支付金额；
- 质保金和暂缓金额；
- 本次最大可申请金额；
- 计划付款日期；
- 普通或紧急优先级。

紧急付款必须填写原因，只突出提醒，不改变审批节点。

创建和审批通过时都在后端事务中重新锁定并校验可用余额。

### 20.3 审批后修改

收款账户、付款金额和关联结算等核心信息不得直接修改。确需变化时撤销并重新发起。

备注、计划付款日期等非核心信息允许留痕修改。

### 20.4 实际付款

- 一笔付款申请允许多次实际支付；
- 每次记录金额、日期、付款账户、收款账户、银行流水号和凭证；
- 累计实际付款不得超过批准金额；
- 全额支付后自动标记完成；
- 少付且不再支付时由财务人员发起差额关闭，财务负责人确认并填写原因；
- 退款、退票或错付不能删除原记录，只能登记冲正；
- 付款凭证必须上传；
- 支付登记属于敏感操作并保留审计。

## 21. 发票和欠票

支持：

- 付款前收票；
- 付款后收票；
- 不要求收票。

付款后收票记录：

- 应收发票金额；
- 已收金额；
- 税率；
- 最迟收票期限。

实际收到发票时记录开票日期、号码、代码、金额、税率和附件。

形成欠票台账和到期提醒。逾期欠票默认只提醒，合同付款条款可以配置是否禁止后续付款。

发票与付款为多对多分摊：

- 一张发票可分摊到同一合同多笔付款；
- 一笔付款可关联多张发票；
- 累计分摊不得超过票面价税合计。

发票状态：

- 正常；
- 红字；
- 作废。

红字发票必须关联原发票并以负数冲减；作废发票不得用于分摊。

第一版人工登记并检查重复号码、金额和分摊，不对接税务平台自动验真。

## 22. 批量付款

批量付款是财务执行容器，不改变原付款审批结果。

### 22.1 基本规则

- 仅纳入已批准待付款申请；
- 财务人员创建、导出和导入结果；
- 财务负责人复核入账；
- 创建人与复核人不得为同一人；
- 不直连网银；
- 高风险资金操作只允许人工在网银完成。

### 22.2 银行模板

- 不同银行维护不同 Excel 模板；
- 财务人员制作或修改；
- 财务负责人复核发布；
- 批次按我方付款账户匹配模板。

### 22.3 冻结和执行

- 银行文件导出后批次冻结；
- 付款申请、金额和收付款账户不得增删或修改；
- 错误只能作废整个批次并重新创建；
- 原导出文件和作废原因永久保存；
- 网银结果文件上传后先按批次流水号和付款申请编号匹配预览；
- 财务人员确认后才形成实际付款记录；
- 无结果文件时允许凭回单手工登记，仍需双人复核和凭证；
- 批次共同凭证和单笔补充凭证可以并存。

### 22.4 部分完成

- 只确认付款成功记录；
- 未成功项不建立失败原因、失败附件或重试记录；
- 未确认成功的申请继续保持已批准待付款；
- 批次标记部分完成；
- 剩余申请转入新批次后关闭原批次；
- 已成功记录和共同凭证继续保留。

## 23. 历史合同补录

历史合同跳过原合同审批和用印审批：

```text
合同管理员补录
-> 上传已签原件
-> 补齐核心台账和历史余额
-> 合同负责人复核
-> 确认归档
-> 合同生效
```

必须补齐：

- 核心合同字段和主体；
- 原合同编号和内部档案号；
- 截至补录日累计结算；
- 累计实际付款；
- 未付余额；
- 质保金余额；
- 对应结算单、付款凭证和已签 PDF。

资料不齐时可以保存草稿，但不得确认生效。

历史结算和付款优先逐笔补录。确实缺失时允许期初汇总记录，但必须填写依据和复核说明。

历史清单：

- 有可识别 Excel 或清晰表格时必须结构化；
- 只有无法可靠识别的扫描件时，允许上传原件并建立汇总控制清单；
- 此类合同标记数据不完整。

## 24. 电子档案包

合同、结算和付款分别生成独立档案包，不合并成单个巨大档案。

ZIP 包含：

- 标准 A4 业务单据 PDF；
- 现有审批单 PDF；
- 冻结附件目录；
- 原始附件；
- 文件哈希 `manifest`。

系统内仍逐项在线查看，不依赖 ZIP。

自动生成时间：

- 合同归档生效；
- 结算归档生效；
- 付款完成。

授权人员可以重新打包下载，但不得改变档案内容。

归档后补充不影响业务效力的说明附件时：

- 不覆盖原冻结包；
- 生成新档案包版本；
- 保留原版本；
- 记录追加原因、人员和时间。

## 25. 权限

### 25.1 项目范围

合同员、预算员、项目技术总工、项目经理、工长、物资员、测量员等只能查看和导出本人所属项目合同。

### 25.2 全公司范围

以下角色可以查看并导出全部合同台账：

- 合同部负责人；
- 预算部负责人；
- 工程技术部负责人；
- 物资部负责人；
- 财务部全体人员；
- 总经理；
- 董事长。

这些角色可以查看全部合同正文、清单和附件原件。

### 25.3 敏感附件

- 当前合同所有审批人员可查看原件；
- 全公司范围角色可查看原件；
- 项目人员可查看本项目业务附件；
- 身份证等敏感附件仅在参与审批或获得授权时查看；
- 默认在线预览；
- 下载需二次确认；
- 预览和下载记录审计日志。

## 26. 待办、通知和首页

第一版只做系统内待办和提醒，不接短信、邮件或企业微信。

待办中心包括：

- 我的审批；
- 退回整改；
- 草稿待提交；
- 归档待确认；
- 质保金到期；
- 欠票；
- 已批准待付款；
- 付款批次复核；
- 模板待发布。

支持按项目、类型和逾期状态筛选。

首页第一版包括：

- 个人待办；
- 最近草稿；
- 逾期提醒；
- 按权限可见的合同、结算和付款关键数字。

## 27. 文件与安全

- 私有文件只经后端权限检查和短时效访问；
- 单文件上限默认 100MB，可配置；
- 允许 DOCX、XLSX、PDF、PNG、JPEG；
- 禁止 DOCM、XLSM 等宏文件；
- 第一版不校验文件真实类型，也不做病毒扫描；
- 服务器不得执行或主动运行用户上传内容；
- 支持多文件批量上传、逐文件进度、取消和失败重试；
- 单文件失败不回滚其他成功文件；
- 第一版不做分片上传和断点续传；
- PDF、PNG 和 JPEG 在线预览；
- DOCX 和 XLSX 提供下载；
- 系统生成 DOCX 提供对应 PDF 预览。

已被业务引用的主体、模板、合同、结算、付款、发票、账户和附件记录不得物理删除，只能停用、作废或冲正。仅完全未引用的配置草稿允许物理删除。

审计日志永久保留，业务人员不得删除。

## 28. 浏览器与移动端

- Web 正式支持最新版 Chrome 和 Edge；
- 合同编辑、模板和清单管理只在 Web；
- 小程序后续只承担审批、PDF 查阅、待办和提醒；
- 小程序不承担复杂字段、条款、清单或模板编辑。

## 29. 错误处理

- 草稿允许不完整保存；
- 普通预览只提醒缺项；
- 正式送审稿和提交审批执行硬性校验；
- 自动保存失败不得清空本地编辑内容；
- 文档生成失败保留输入快照并允许重试；
- Excel 导入错误定位到工作表、行和列；
- 付款并发冲突返回最新可用余额，不写入部分数据；
- OCR 或文件对比失败不得自动判定合同有效或无效；
- 异步任务重试必须幂等；
- 任何资金、版本或归档关键操作失败时整体事务回滚。

## 30. 测试与验收

### 30.1 单元和集成测试

- 十进制数量、单价、税率、舍入和多清单汇总；
- Excel 导入、更新、追加、替换和错误定位；
- 模板发布、停用、撤销和快照不可变；
- 条款变量联动和必备规则；
- 补充协议累计增加、减少及 10% 阈值；
- 合同、结算、付款版本追溯；
- 并发付款和批量付款冻结；
- 发票分摊、红字和作废；
- 权限、敏感下载和审计。

### 30.2 文档测试

- 长主体名称；
- 空清单、大清单和多清单；
- A4 纵向和横向分节；
- 表格跨页和重复表头；
- 中文字体、金额大写和乱码；
- 图片和 PDF 附件 A4 合并；
- DOCX/PDF 页数和内容一致性；
- 水印用途；
- 历史文件哈希及不可替换。

### 30.3 端到端验收

至少覆盖：

1. 新建合同、保存草稿、恢复版本和提交审批；
2. Excel 导入后网页修改并生成 Word/PDF；
3. 可选磋商、DOCX 差异处理和重新生成；
4. 退回修改后核心变化重新审批；
5. 用印、线下签署、扫描上传、OCR 核对和归档生效；
6. 补充协议金额变化和加强审批；
7. 结算、质保金、付款和发票；
8. 并发付款不得超额；
9. 批量付款导出、冻结、人工网银、结果确认和部分完成；
10. 历史补录和余额一致；
11. 合同、结算和付款档案包；
12. 项目范围和全公司范围权限。

## 31. 交付顺序

四个阶段均属于第一版目标：

### 阶段 1

合同工作台、模板中心、多清单、Excel 导入和 Word/PDF 生成。

### 阶段 2

线下磋商、审批差异、用印、签署扫描和归档生效。

### 阶段 3

结算、质保金、付款、发票和批量付款。

### 阶段 4

历史补录、电子档案包、待办提醒、权限和审计收口。

每个阶段必须独立通过测试和端到端验收后再进入下一阶段。
