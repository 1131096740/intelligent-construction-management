# 建工智管微信小程序永久退出设计

日期：2026-07-14

状态：用户已确认，待制定实施计划

范围：微信小程序客户端、微信身份登录、微信专属配置、`wxOpenid` 数据结构、当前有效架构文档和生产验收

决策：采用方案 C，永久退出微信小程序路线；桌面端和手机端统一使用同一套 Web 系统

## 1. 背景与当前事实

建工智管当前以 Vue 3、TypeScript、TDesign Vue Next 和 Vite 构建 Web Admin，以 NestJS 和 PostgreSQL 提供统一业务后端。生产部署主链只部署 Web 与 API，`apps/miniprogram` 尚未进入生产发布主链。

仓库仍保留以下微信小程序专属实现：

- `apps/miniprogram` 原生微信小程序客户端骨架。
- `POST /auth/wx-login` 微信登录入口及其 DTO、微信会话交换逻辑和测试。
- 用户模型中的可空唯一字段 `wxOpenid`。
- 微信 AppID、AppSecret 相关环境变量读取约定。
- 当前有效文档中“小程序是移动工作端”的架构表述。

小程序曾使用的待办、审批、合同、结算和付款接口同时服务 Web，属于共享业务能力，不能随小程序一并删除。

用户已确认采用方案 C：微信小程序永久退出当前产品与架构。如果未来重新提出小程序，应作为新的产品立项重新评估，不能默认恢复旧客户端。

## 2. 目标

- 只维护一套 Web 客户端体系，桌面和手机共用登录、路由、权限、API、状态机和审计事实。
- 删除未进入生产主链的小程序客户端，停止维护第二套前端。
- 删除微信身份登录入口和微信专属密钥依赖，收窄认证攻击面。
- 在经过生产数据核验、备份和临时恢复库演练后，永久删除 `wxOpenid` 字段。
- 保留微信扫码打开普通 HTTPS 手机网页的能力。
- 保留手机 Web 的台账查看、审批、附件、手写签名和个人设置能力。
- 保留历史 Git、历史迁移和历史决策事实，明确标注取消结论。

## 3. 不做事项

- 不取消或削弱手机 Web。
- 不取消电脑二维码进入手机手写签名网页的方案。
- 不接入微信网页授权、公众号 OpenID、企业微信或其他替代身份平台。
- 不重构手机号密码认证、权限矩阵、业务流程或审计模型。
- 不修改合同、结算、付款、项目或人员业务数据。
- 不顺带实施已暂缓的手机 UI 改造。
- 不删除已执行的历史数据库迁移。
- 不改写 Git 历史或批量删除历史设计文档。
- 未经单独授权，不操作微信公众平台账号或删除外部应用。

## 4. 目标架构

### 4.1 客户端

建工智管只保留一套 Web 客户端：

- 桌面用户使用 Web Admin。
- 手机用户使用同一系统的响应式手机网页。
- 微信仅作为二维码扫描工具和网页容器，不作为身份凭证。

手机用户继续使用手机号和密码登录。账号、会话、权限和审计全部由现有后端管理。

### 4.2 共享业务后端

以下能力与微信小程序无关，必须保留：

- 手机号登录、首次改密、会话撤销和登录审计。
- `/me/work-items` 等待办与工作台读模型。
- 合同、结算、付款、审批、附件和安全下载接口。
- 手机手写签名及电脑二维码配对入口。
- Web 路由和权限过滤。

实现时必须按调用者逐项确认，不能因为某个共享接口曾被小程序调用就判定其可以删除。

## 5. 删除与保留边界

### 5.1 删除范围

- 删除整个 `apps/miniprogram` 目录。
- 删除 `POST /auth/wx-login` 路由。
- 删除微信登录 DTO、微信会话交换方法、OpenID 登录绑定逻辑及专属测试。
- 删除微信 AppID、AppSecret 等有效环境变量要求和当前配置说明。
- 删除当前架构中“小程序是移动工作端”的有效表述。
- 删除小程序专属构建、调试、发布和验收说明。
- 在第二个生产单元中，从 Prisma 用户模型和生产数据库删除 `wxOpenid`。

### 5.2 保留范围

- 手机号账号、密码、岗位、项目花名册、会话、审计和业务数据。
- Web 与小程序曾共用的后端接口和业务规则。
- 手机 Web 与手写签名的已确认设计。
- 微信扫码打开 `https://jgzg.site` 同源网页的能力。
- 已执行的历史数据库迁移。
- 历史 Git 提交和历史方案文档。

历史文档若仍会被当作当前方案阅读，应增加“已被 2026-07-14 取消决策取代”的提示；纯历史记录无需重写正文。

## 6. 两阶段实施与发布顺序

永久退出分为两个独立生产单元。不得把代码入口删除和数据库不可逆迁移挤在同一次部署中。

### 6.1 第一阶段：停止小程序运行能力

第一阶段完成客户端和认证运行面的清理：

1. 删除小程序客户端。
2. 删除微信登录路由、服务逻辑、DTO 和测试。
3. 删除微信专属有效配置要求。
4. 更新当前有效架构文档。
5. 暂时保留 Prisma 模型和生产数据库中的 `wxOpenid` 字段。
6. 发布后验证手机号登录、待办、审批、手机 Web 和二维码网页入口。
7. 验证 `/auth/wx-login` 已不可访问。
8. 检查现有日志保留范围内是否存在真实微信登录调用。

第一阶段不产生数据库迁移，因此可以通过回滚代码版本恢复。若服务器存在微信密钥，必须先确认新代码已无依赖，再从生产环境配置中移除；任何验证输出都不得打印密钥值。

### 6.2 第二阶段：永久删除 `wxOpenid`

第二阶段只处理数据结构，必须在第一阶段生产验收通过后开始：

1. 只读统计生产库中非空 `wxOpenid` 的账号数量，不输出具体 OpenID。
2. 如果数量大于 0，停止执行，不静默删除；先报告账号数量，并另行确认会话撤销、审计和历史映射处理方案。
3. 如果数量等于 0，创建最新生产数据库备份。
4. 校验备份可读取，记录路径、权限、大小和 SHA-256。
5. 从最新备份建立临时恢复库。
6. 在临时恢复库执行新的字段删除迁移。
7. 验证 Prisma 结构、认证、权限和手机号登录。
8. 演练通过后，才允许在正式库执行同一迁移。

正式迁移只允许删除用户表中的 `wxOpenid` 字段，不得修改其他用户字段、手机号、密码、岗位、项目、会话或业务数据。

## 7. 数据、会话与回滚

### 7.1 非空数据处理

非空 `wxOpenid` 数量大于 0 是第二阶段的硬阻断条件。实现任务不得以“字段已不使用”为理由自动清空数据。

后续处理至少需要回答：

- 哪些启用账号存在历史微信身份关联。
- 是否存在仍有效、但无法区分登录来源的旧会话。
- 是否需要撤销相关账号全部旧会话并记录权限或安全审计。
- 是否需要在受控备份中保留历史映射，满足回溯要求。

以上问题未获得明确授权前，第二阶段保持停止状态。

### 7.2 回滚原则

- 第一阶段只回滚代码，不涉及数据库恢复。
- 第二阶段执行前必须保留完整生产备份。
- 若字段确认始终为空，字段删除后出现结构兼容问题，优先通过补充迁移重新建立可空字段，避免整库恢复覆盖迁移后的新业务数据。
- 只有在确认需要恢复被删除数据且能够接受恢复点之后的新数据处理方案时，才考虑整库恢复。

## 8. 错误处理与停止条件

出现下列任一情况，当前阶段立即停止，不强行继续：

- 生产库存在非空 `wxOpenid`。
- 日志显示微信登录入口仍有真实调用。
- 删除范围触及仍被 Web 使用的共享接口。
- 手机号登录、首次改密、待办、审批或手机 Web 回归失败。
- 微信扫码无法打开普通 HTTPS 页面。
- 临时恢复库创建、备份读取或迁移演练失败。
- 正式发布后 API、Nginx、PostgreSQL 或 `/health` 异常。
- 生产提交、`origin/main` 与部署目录版本不一致。

所有错误使用现有中文业务错误和运维日志处理，不向用户暴露密钥、OpenID、内部数据库结构或堆栈。

## 9. 验证策略

### 9.1 仓库与自动化验证

- 扫描确认当前代码树不存在 `apps/miniprogram`。
- 扫描确认运行代码不存在 `/auth/wx-login` 和微信会话交换逻辑。
- 扫描确认有效配置不再要求微信 AppID 或 AppSecret。
- 运行认证模块定向 Jest。
- 运行手机号登录、首次改密、会话和权限相关测试。
- 运行 `/me/work-items` 等共享接口测试。
- 运行 API typecheck、lint 和 build。
- 运行 Prisma format、generate、validate 和迁移状态检查。
- 运行仓库差异检查，确认没有夹带无关修改。

残留名称只允许出现在历史迁移、历史说明和本取消决策中。扫描结果必须逐项分类，不能仅以关键词仍有命中就删除历史事实。

### 9.2 生产验证

- API 与 Nginx 正常运行，`/health` 正常。
- 手机号和密码可以正常登录。
- 手机网页可以读取待办并进入审批。
- 微信扫码可以打开普通 HTTPS 网页。
- 手写签名二维码入口不受影响。
- `/auth/wx-login` 已不可访问。
- 第二阶段完成后，生产数据库不存在 `wxOpenid` 字段。
- 生产日志没有因清理产生新的持续错误。

## 10. 文档治理

实施时必须同步以下当前真相：

- `AGENTS.md`：Web 是唯一客户端体系，手机端使用响应式网页。
- `PROGRESS.md`：分别记录第一阶段发布和第二阶段迁移的提交、备份、演练与验收结果。
- 当前认证与架构设计：删除微信身份登录作为有效能力的描述。
- 手机 Web 与手写签名设计：保持“微信只负责扫码打开网页，不负责身份认证”的边界。

历史文档、历史迁移和 Git 历史继续保留。不得提交 `.superpowers/` 本地执行草稿。

## 11. 外部微信平台边界

如果实际存在已经注册的小程序应用，仓库清理完成后提供人工关闭和密钥作废清单。外部动作至少包括检查应用发布状态、停用服务能力和作废不再使用的密钥。

这份设计不授权自动登录微信公众平台、修改主体资料或删除外部应用。任何外部平台变更都需要用户单独授权并由具备相应管理权限的账号执行。

## 12. 完成定义

只有同时满足以下条件，才能宣布方案 C 完成：

- 小程序客户端已经从当前代码树删除。
- 微信登录接口、服务逻辑和有效配置已经删除。
- 共享业务接口与手机 Web 能力通过回归验证。
- `wxOpenid` 已经过生产数据核验、备份、临时库演练和正式迁移后删除。
- 当前有效架构与进度文档已经同步。
- 两阶段生产发布均通过健康检查和业务冒烟。

仅删除 `apps/miniprogram` 或仅修改文档，均不能宣称永久退出已经完成。

## 13. 授权边界与后续步骤

本设计确认不等于代码、数据库或生产授权。后续顺序固定为：

1. 根据本设计编写实施计划。
2. 用户审阅并确认实施计划。
3. 在候选分支完成第一阶段代码清理与测试。

6. 只读核验生产 `wxOpenid` 使用情况。
7. 另行获得生产备份、临时恢复库演练和正式迁移授权。
8. 完成第二阶段迁移与最终验收。

任何步骤都不得从本次设计确认推导出生产写入权限。
