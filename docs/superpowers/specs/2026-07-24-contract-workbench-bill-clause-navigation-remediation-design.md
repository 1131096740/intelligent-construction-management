# 合同工作台清单、条款与顶部导航问题改造设计

日期：2026-07-24

状态：业务与交互方案已由用户逐项确认；等待用户对本文书面复核

范围：合同工作台清单多维表格、Excel 模板导入、合同条款编辑与保存、全站“最近打开”移除和路由滚动行为

## 2. 已核实的现状与根因

### 2.1 清单只能连续新增一行

当前 `ContractBillEditor.vue` 使用手写 HTML 表格，并通过 `hasUnsavedRow` 同时禁用新增、复制、移动、Excel 上传和应用操作。只要存在一条未保存行，用户就不能再新增第二条，也不能导入已经填好的标准模板。

这不是用户操作错误，而是当前页面把每一行都设计成“先单行保存，再进行下一步”的结果。

### 2.2 清单编辑区域过小

合同工作台主体目前是左侧主区域加右侧约 380–440px 辅助栏。清单表格最小宽度约 980px，却被放进右侧窄栏中，只能依赖局部横向滚动，无法满足 20–100 行、偶尔超过 100 行的工程清单录入和核对。

### 2.3 条款点击保存无反应并在切页后消失

条款输入当前使用 `value + change` 组合。输入内容尚未失焦时，文字只存在于输入控件内部，没有立即进入合同草稿模型，因此：

- 页面可能仍判断为“无修改”；
- 点击右上角保存时没有可提交的数据，也没有明确反馈；
- 切换到清单等分区后重新渲染，控件内尚未同步的内容消失。

后端草稿本身已经能够保存结构化条款；本次应修复前端受控输入、脏状态和保存反馈，不另建条款存储体系。

### 2.4 顶部“最近打开”与自动隐藏

当前 `AdminLayout.vue` 维护每个用户最多 5 条最近业务路由，并以本地存储持久化。该功能占据顶部空间，但不承担不可替代的业务入口，用户已明确选择移除。

页面跳转后顶部看似“自动隐藏”的直接原因是：路由完成后程序聚焦 `#main-content`，浏览器为把焦点元素滚入视口而自动向下滚动；路由又没有统一的 `scrollBehavior`，因此新页面没有可靠地回到顶部。

## 3. 已确认的改造目标

### 3.1 合同清单

- 合同清单完整迁移到现有 `JgBusinessGrid`，不保留手写表格作为并行编辑入口。
- 正常工作台仅展示清单摘要，包括行数、合计和关键状态，并提供“放大编辑”入口。
- “放大编辑”进入全宽清单专注模式，适合连续录入、粘贴、核对和导入 100 行以上数据。
- 用户可连续新增多行、编辑、复制、删除、排序，最后一次点击“保存全部”。
- 清单不采用逐单元格服务端自动保存。
- Excel 仅接受系统下载的标准 `.xlsx` 模板；上传后先预检，再整体替换。
- 如果页面已有未保存的手工行，应用 Excel 前必须明确提示“将替换当前未保存清单”，确认后才执行，取消则完整保留当前内容。
- 桌面端使用多维表格，移动端按既有整站规范使用逐行卡片编辑，不把宽表强塞进手机横向滚动区。

### 3.2 合同条款

- 选择标准条款后立即填充条款标题和正文，并允许继续修改。
- 当前条款已有内容时再次选择另一标准条款，必须先确认；确认后替换，取消则原内容不变。
- 每次输入立即进入本地草稿模型，切换合同工作台分区不得丢失。
- 保留标准条款来源和版本；用户修改标准正文后标记为“已调整”，不得继续伪装成未修改的标准条款。
- 保存状态必须可见，不允许继续出现“点击保存没有任何反应”。

### 3.3 顶部导航

- 完整移除“最近打开”的展示、记录和读取逻辑。
- 新进入页面默认回到顶部。
- 用户手动向下滚动时，顶部按正常文档流离开视口，不改成吸顶导航。
- 浏览器后退或前进时恢复该历史页面的滚动位置。
- URL 带锚点时滚动到锚点。
- 保留无障碍主内容聚焦，但使用 `preventScroll`，避免聚焦动作覆盖路由滚动规则。

### 3.4 整站多维表格口径

“所有表格做成多维表格”在本项目中的确认口径是：

- 所有需要多行填写、计算、校验、复制或粘贴的业务明细，应采用 `JgBusinessGrid` 或其领域适配组件。
- 只读台账、查询列表、审批记录和审计列表继续使用 TDesign 表格，不为了形式统一改造成可编辑多维表格。
- 本次只实施合同清单迁移，同时产出整站“填写型明细尚未迁移清单”；其他页面是否迁移进入后续独立切片，不在本次顺手改造。
- 合同付款条款未来仍按总规格进入多维表格，但本次解决的是合同条款正文保存问题，不扩大为付款条款结构重做。

## 4. 方案选择

### 4.1 不采用：只放大当前手写表格

该方案能暂时改善可视面积，但仍保留“只允许一条未保存行”、逐行接口、粘贴能力弱和两套表格交互不一致的问题，无法落实已经确认的整站多维表格规则。

### 4.2 不采用：前端连续调用现有单行接口模拟批量保存

该方案改动较少，但中途失败时会产生部分行已保存、部分行未保存的状态；并发冲突、金额重算、文档失效和审计也会被拆成多次动作，不符合“保存全部要么全部成功，要么全部不变”的要求。

### 4.3 采用：受控迁移到 `JgBusinessGrid`，后端提供整表事务保存

采用现有共享多维表格作为渲染和基础编辑底座，新增合同领域适配层承载列定义、计算、校验、Excel 和移动端规则；后端在现有清单修订号守卫之上新增整表事务写入。

该方案复用现有基础能力，同时从根因上解决连续新增、批量导入、狭窄编辑、部分保存和并发冲突问题。

## 5. 清单页面与组件设计

### 5.1 正常工作台

合同工作台右侧不再渲染完整可编辑宽表，改为清单摘要卡：

- 清单名称和当前版本；
- 已保存行数；
- 当前本地候选行数（存在未保存修改时展示）；
- 不含税、税额、含税合计；
- 是否存在校验错误、并发刷新要求或待保存修改；
- “放大编辑”主按钮；
- “下载标准模板”和“导入 Excel”辅助入口。

摘要卡只提供概览和入口，不在窄栏内重复实现另一套行编辑器。

### 5.2 清单专注模式

点击“放大编辑”后进入合同工作台内部的全宽专注模式，不打开新的浏览器页面。专注模式包含：

- 顶部：返回合同、清单名称、已保存/待保存状态；
- 操作区：新增行、复制行、删除行、上移/下移、下载模板、导入 Excel、保存全部；
- 主体：`ContractBillGrid`；
- 底部固定汇总：行数、不含税、税额、含税金额；
- 校验区：错误数量及“跳到下一处错误”；
- 离开保护：有未保存修改时，退出专注模式、切合同分区或离开路由均提示保存、放弃或继续编辑。

全宽模式使用视口内可用高度，表头和底部汇总保持可见，表格主体独立滚动。100 行以上继续使用 RevoGrid 虚拟滚动，不按编辑分页切断连续粘贴和键盘操作。

### 5.3 组件职责

`JgBusinessGrid` 保持通用，不理解合同、税务、金额或 Excel 规则。

新增合同领域组件 `ContractBillGrid`，负责：

- 合同清单列定义；
- 本地行键和服务端行键映射；
- 连续新增、复制、删除和排序；
- 剪贴板粘贴后的字段归一化；
- 行内计算与校验展示；
- Excel 预检结果转成本地候选行；
- 桌面网格与移动卡片之间的同一数据模型；
- 向页面上报完整候选行、脏状态和错误摘要。

工作台页面负责模式切换、离开保护、调用 API、展示保存结果和重新读取服务端权威数据，不把领域规则塞回通用网格。

### 5.4 本地行模型

每一行包含稳定的客户端 `clientRowKey`：

- 已保存行同时携带服务端 `rowKey`；
- 新增行只有不可碰撞的临时 `clientRowKey`；
- 排序以候选数组顺序为准；
- 删除已保存行只在本地候选中移除，直到“保存全部”成功才真正删除服务端事实；
- 保存失败时本地候选和临时行键保持不变。

金额、数量、税率等字段在本地以字符串录入，遵守当前合同清单的精度和合法性规则；前端只做快速反馈，最终合法性仍由后端判定。

## 6. 清单批量保存契约

### 6.1 接口

新增：

```text
PUT /contract-bills/:billId/rows
```

请求体：

```json
{
  "expectedBillRevision": 7,
  "idempotencyKey": "由客户端为本次保存生成的唯一键",
  "rows": [
    {
      "clientRowKey": "local-or-stable-key",
      "rowKey": "已有行才携带",
      "sortOrder": 1,
      "values": {}
    }
  ]
}
```

响应返回完整服务端权威清单读模型，至少包含新 `billRevision`、最终行键、最终排序、重算金额和合同草稿修订号。前端成功后必须用响应整体替换本地候选，不能自行拼接“看起来成功”的状态。

### 6.2 原子事务

服务端在一个事务内完成：

1. 校验请求结构、幂等键、行数和重复键。
2. 锁定清单及所属合同版本。
3. 复用现有合同所有人、作废状态、可编辑状态和 `expectedBillRevision` 并发守卫。
4. 对所有行执行现有字段、数量、单价、税率、金额和列结构规则。
5. 按服务端 `rowKey` 计算新增、修改、删除和最终顺序；客户端临时键永远不作为数据库主键。
6. 整体写入最终行集合。
7. 复用现有清单及合同金额重算、合同渲染输入修订和旧文档失效逻辑。
8. 清单修订号只递增一次。
9. 写一条 `contract.bill.rows.replace` 审计，记录新增、修改、删除数量、前后修订号和幂等键摘要，不在审计中复制敏感正文或整表数据。
10. 返回事务内重新读取的权威结果。

任一步失败则全部回滚，不允许部分行成功。

### 6.3 并发与幂等

- `expectedBillRevision` 不匹配时，整次保存失败，返回“清单已变化，请刷新后重试”，不覆盖他人修改。
- 服务端以“用户 + 清单 + `idempotencyKey`”串行化同一保存动作，并在审计回执中记录键摘要、请求摘要和前后修订号；不记录明文整表。
- 相同键且请求摘要相同的网络重试返回该次保存后的当前权威结果，不重复递增修订号或写审计；相同键但请求摘要不同则拒绝。
- 幂等回执复用现有审计事实和清单事务锁，不为本次改造新增独立业务表。
- 页面收到并发冲突时保留本地候选，允许用户先复制或导出当前内容，再选择刷新服务端版本。

### 6.4 错误响应

业务校验失败返回结构化错误：

```json
{
  "code": "CONTRACT_BILL_VALIDATION_FAILED",
  "message": "清单有 3 处需要修改",
  "rowErrors": [
    {
      "clientRowKey": "local-key",
      "field": "quantity",
      "message": "数量最多保留两位小数"
    }
  ]
}
```

前端在对应单元格显示错误，并可跳到下一处错误。权限、合同状态或修订号冲突属于整表错误，显示在顶部且不伪装成某一行字段错误。

## 7. Excel 标准模板导入

### 7.1 固定流程

```text
下载当前系统标准模板
  -> 用户在 Excel 中填写
  -> 上传 .xlsx
  -> 服务端预检
  -> 页面展示行数、合计、错误和替换影响
  -> 用户确认应用
  -> 预检结果进入本地候选
  -> 用户点击“保存全部”
  -> 整表事务保存
```

“应用预检”只替换浏览器内的候选数据，不直接写服务端；真正业务写入仍由“保存全部”统一触发。

### 7.2 替换规则

- 导入语义固定为整体替换，不提供自动追加或智能合并。
- 已有未保存修改时，应用前明确显示将丢失的候选行数；用户确认才替换。
- 上传文件不符合系统模板版本、列结构、字段类型或行数边界时，只展示预检错误，不改变当前候选。
- 预检通过但仍含业务字段错误时，允许载入候选并定位修改，不能绕过最终服务端校验。
- 预检及应用支持 100 行以上，不以 100 行作为上限；服务端仍设置防滥用的合理文件大小和最大行数，并沿用当前 Excel 上传安全限制。

## 8. 条款编辑与保存设计

### 8.1 受控输入

条款标题、正文和相关选项改为标准双向受控绑定，输入事件发生时立即：

1. 更新合同草稿模型；
2. 标记草稿已修改；
3. 写入当前本地恢复副本；
4. 更新页面保存状态。

切换“条款/清单/资料”等工作台分区只切换视图，不重新用旧服务端数据覆盖本地草稿。

### 8.2 选择标准条款

- 选择标准条款后立即将标准标题和正文复制到当前合同草稿。
- 草稿内容为空时直接填充。
- 草稿内容非空时弹出替换确认，说明当前内容将被覆盖；取消后选择和正文均恢复到操作前状态。
- 草稿记录标准条款 ID、版本和填充时摘要。
- 用户编辑填充后的标题或正文时标记 `deviatedFromStandard = true`；恢复成标准原文时可重新计算为未调整。
- 标准条款后续更新不反向改写已经保存的合同草稿或合同版本。

这些来源信息存入现有合同草稿结构，不因本次改造新增独立业务表。

### 8.3 首次保存与后续自动保存

保存规则固定分为两段：

**首次手动保存前**

- 条款等普通字段输入后立即进入本地模型和本地恢复副本；
- 不触发服务端自动保存；
- 只有用户点击右上角“保存”，并且服务端成功，才分配正式合同编号；
- 状态显示“未正式保存”或“本地已备份”，不得显示“已保存”。

**首次手动保存成功后**

- 条款等普通非清单字段修改后约 1 秒自动保存；
- 右上角“保存”继续保留，用户可立即主动保存；
- 清单仍不参与该自动保存，只由“保存全部”写入；
- 状态明确区分“保存中”“已保存”“保存失败”。

自动保存失败时保留本地草稿并展示可重试错误；不得清空内容或用旧服务端响应覆盖用户新输入。

### 8.4 右上角保存行为

- 有修改时：提交当前普通草稿字段，成功后展示保存时间和权威修订号。
- 无修改时：展示“当前内容已保存”，不重新加载工作台，不造成输入闪烁或丢失。
- 正在自动保存时点击：复用或等待当前保存请求，不并发发出互相覆盖的请求。
- 保存成功后的服务端回读只在确认本地没有更新版本的输入时合并；响应到达期间的新输入必须继续保留。

## 9. 顶部导航与滚动行为

### 9.1 移除“最近打开”

从全站布局移除：

- 最近打开条带；
- 路由记录监听；
- 本地读取和写入；
- 最近路由辅助模块及对应测试；
- 为该条带预留的样式和布局空间。

新版本首次加载布局时清理既有“最近打开”本地存储键，避免遗留无效数据。该清理不涉及服务端业务数据。

### 9.2 路由滚动规则

路由器统一配置：

1. 浏览器后退/前进且存在 `savedPosition`：恢复历史位置。
2. 目标路由带 hash：滚动到对应锚点。
3. 其他新导航：滚动到页面顶部。

主内容焦点仍在路由完成后更新，使用：

```text
mainContent.focus({ preventScroll: true })
```

滚动位置只由路由规则决定，焦点管理不再产生第二次隐式滚动。

## 10. 状态与数据一致性

合同工作台同时存在三类修改，必须分别展示：

| 修改类型 | 本地状态 | 服务端写入方式 |
| --- | --- | --- |
| 首次正式保存前的普通字段 | 模型 + 本地恢复副本 | 用户首次点击右上角保存 |
| 首次正式保存后的普通字段 | 模型 + 本地恢复副本 | 约 1 秒自动保存或右上角手动保存 |
| 合同清单 | `ContractBillGrid` 完整候选 | 用户点击“保存全部” |

页面不得用一个模糊的“已保存”覆盖三类状态。离开保护只在仍有未落服务端的内容时出现；本地已有备份不等于正式保存。

## 11. 验收标准

### 11.1 清单

- 可连续新增至少 20 行而不需要逐行保存。
- 可粘贴、复制、删除、排序并一次保存全部。
- 100 行以上滚动、编辑和错误定位可用，无明显整页卡顿。
- 任一行不合法时服务端零行落库，并准确定位错误。
- 修订号冲突时不覆盖服务端，也不丢本地候选。
- 保存成功后行键、排序、金额和修订号以服务端响应为准。
- 标准模板可下载、预检和整体替换；有未保存行时必须确认。
- 正常工作台不再出现 380–440px 内的窄幅可编辑宽表。
- 桌面专注模式与移动卡片使用同一候选数据和校验结果。

### 11.2 条款

- 输入一个字符后立即形成脏状态和本地备份。
- 未失焦直接点击保存也能保存该字符。
- 输入后切换到清单再返回，内容不丢失。
- 首次手动保存前不会因输入或停留 1 秒而分配正式编号。
- 首次保存成功后修改条款，可自动保存且有明确状态。
- 选择标准条款可立即填充；覆盖非空内容前必须确认。
- 编辑标准正文后显示已调整并保留标准来源版本。
- 无修改点击保存有明确反馈，不重新加载并清空控件状态。

### 11.3 导航

- 全站不再显示“最近打开”，也不继续记录相关本地数据。
- 从任一页面点击进入另一页面时落在新页面顶部。
- 手动滚动时顶部可自然离开视口。
- 浏览器后退和前进恢复原滚动位置。
- 带锚点链接正确定位。
- 键盘和读屏用户仍能在路由切换后获得主内容焦点，且页面不被焦点动作二次滚动。
