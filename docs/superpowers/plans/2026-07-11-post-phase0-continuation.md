- 阶段 0B 的 21/21 金额列 `BIGINT`、API 十进制字符串和 Web 纯字符串金额适配已经生产发布。
- 阶段 0C 的私有文件哈希、存储状态、替换链和失败补偿已经生产发布；剩余是专用 UAT 的真实 COS 写入验收。
- 阶段 0D 的全局输入校验、中文错误治理和 AST 回归门禁已经生产发布。
- 普通付款审批链已经收口为经办人发起后：综合部主管 -> 项目经理 -> 财务总监 -> 董事长/总经理 OR 签。
- 报销和零星采购已有审批、实付、凭证、入账、PDF 和审计闭环；后续先审计差距，不重复开发。

## 阶段 A：剩余生产 UAT

需要用户提供或确认专用 UAT 项目、可用账号、脱敏文件、清理口径和验收窗口后才能执行生产写入。验收覆盖真实 COS 上传、数据库登记、授权下载、短时链接、过期/篡改/越权拒绝、文件替换和审计。缺少这些输入时不阻塞后续本地代码阶段。

## 阶段 B：组织权限与真实业务基础

1. 组织目录账本：部门树、人员状态、固定岗位、全局岗位和项目岗位统一读模型。
2. 组织变更 API：部门、人员状态和归属管理，二次确认并写权限审计。
3. 岗位与项目范围：全局岗位、项目岗位、项目成员增删；项目经理不得授予敏感岗位。
4. 批量移除影响预览：先展示项目、岗位、待办和业务影响，再允许确认应用。
5. 自审规则：除董事长/总经理外禁止自审；董事长/总经理自审必须填写原因、二次确认并明确审计标记。
6. Web 管理 UI：独立 `organization.api.ts`，部门树、人员、岗位和项目范围使用 TDesign 与 `--jg-*` token。
7. 真实小样复验：未经用户确认不导入真实数据；有输入后验证项目隔离、文件权限和审计。

阶段 B 的详细计划按子系统逐份刷新，首份为 `2026-07-11-phase1a-organization-directory.md`。

## 阶段 C：合同办公化

- 模板详情聚合读模型和后端可执行动作。
- 项目 -> 业务场景 -> 推荐模板 -> 预览/更换 -> 创建草稿。
- 合同文档画布、业务侧栏、顶部阶段/保存/主操作和就绪检查。
- Word 下载、线下修订、上传、PDF 预览、修订历史和正文/账本差异检查。
- 合同变更与补充协议形成新合同版本，历史业务引用不漂移。
- 四类真实母版逐页验收；不建设签字台账。

## 阶段 D：结算办公化

- 有效合同清单引出结算明细。
- 全宽表格、粘贴、多行编辑、批量备注、固定合计和异常抽屉。
- Excel 模板版本、导入预检、确认应用、幂等和结果导出。
- 后端重算金额并硬拦超量、负数、重复期间和无效合同版本。
- 归档确认后才生效并成为付款来源。

## 阶段 E：资金闭环差距治理

- 先审计普通付款、报销、零星采购、业主额度和现金池已有能力。
- 只补现金池调整账本、超额授权并发重算、实付幂等和事务回滚等真实缺口。
- 三条真实账号链路完成审批、实付、凭证、财务记录、PDF 和审计验收。

## 阶段 F：真实数据与试运行

真实项目、组织、业主主合同、约 20 个历史合同和 3-5 个活跃合同必须由用户提供并确认后导入。先接管 3-5 个可继续业务的活跃合同并跑长链路，对账稳定后再扩到约 20 个历史合同。不得编造日期、金额、审批、附件或付款事实。

清理 P0/P1 缺陷，复验权限、金额、状态、版本、文件和审计；运行全量测试、构建、备份、迁移、域名、HTTPS 和生产健康检查；确认 `origin/main`、生产 SHA 和发布记录可追溯。生产写入、真实数据、推送 `main`、迁移和部署仍需用户明确批准。
