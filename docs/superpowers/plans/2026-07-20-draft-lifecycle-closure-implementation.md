# 全系统草稿生命周期与合同工作台收口实施计划

日期：2026-07-20
状态：已确认，开始实施
范围：在已发布的草稿生命周期领域能力上，补齐真实页面使用、台账、未保存保护、自动化验收和合同工作台缺陷。

## 1. 完成定义

一个业务域只有同时满足以下条件，才允许标记为“完整完成”：

1. 页面能看到服务端允许的生命周期动作和阻断原因。
2. 删除纯净草稿、放弃申请等动作不依赖再次保存当前无效或未完成表单。
3. 存在未保存修改时，用户可以明确选择继续编辑，或丢弃本地修改并结束服务端已保存草稿。
4. 动作失败保留原因输入和当前页面内容；动作成功后重新读取服务端台账、统计和首页队列。
5. 列表使用服务端真实分页与统计，不以固定条数截断或前端过滤伪装完整结果。
6. 至少有一个页面级浏览器场景覆盖成功、失败或并发冲突中的关键路径。
7. 真实岗位 UAT 由岗位本人签认；自动化和开发者不能代签。

## 2. 实施批次

### Task 19：口径纠正与验收矩阵

- 在 `PROGRESS.md` 重新打开 Task 14、16、17 的业务闭环状态。
- 固化本计划和页面验收矩阵。
- 不修改生产数据，不推送或部署。

### Task 20：P0 合同与结算工作台

- 合同、结算生命周期动作取消“动作前强制保存”。
- 使用当前服务端修订号直接 CAS 结束已保存草稿。
- 有未保存内容时在敏感动作对话框明确说明这些本地修改不会保存。
- 合同台账和结算台账的草稿/退回行提供明确的结束入口，仍只消费服务端动作。
- 材料采购合同移除“交货期限”；劳务与租赁日期保持字段但改为选填。
- 修复清单导入读取不到合同默认税率的问题。
- 修复草稿保存失败，并验证保存后合同文档能够生成。
- 增加合同删除、结算放弃、税率导入、保存与文档生成的定向测试和 Playwright 场景。

### Task 21：首页与零星采购台账

- `/me/work-items` 的“我的草稿”聚合合同、结算、历史接管、零星采购、零星付款及模板草稿。
- 返回总数和截断/分页事实，不把草稿混入审批待办。
- 零星采购、零星付款、零星收货改为服务端分页、服务端统计和明确生命周期视图。
- 动作成功后刷新详情、列表、统计和首页队列。

### Task 22：其余页面真实使用闭环

- 历史接管、四类模板编辑页补统一未保存离开保护。
- 税务修订、项目支出、普通付款补动作后刷新和页面级浏览器验收。
- 四类模板分别覆盖废弃草稿版本的浏览器行为，不以结算模板单例代替全域验收。

### Task 23：长期治理与复制代替恢复

- 业务草稿超过 30 天标记“长期未处理”，超过 90 天进入折叠筛选；绝不自动删除。
- 可复用的已放弃合同、结算等记录提供“复制为新草稿”，生成新身份并保留来源引用。
- 零星付款继续使用专用“重新创建付款申请”，不恢复旧付款草稿。
- 为导入预览、生成任务、比较任务、检查点和未绑定临时文件建立保留策略读取模型。
- 技术清理先提供只读预览和默认拒绝的受控执行入口；实际物理清理继续使用独立授权门禁。

### Task 24：全量验证与候选收口

- 运行 Shared/API/Web 定向及全量测试、typecheck、lint、build、`check:ui` 和 P0 Playwright。
- 更新实施报告、发布准备收据和 `PROGRESS.md`。
- 形成精确候选 SHA 后停止；推送、部署、生产迁移和现有 7 条生产草稿治理均需独立授权。
