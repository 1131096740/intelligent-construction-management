# 新正文快照显式锁定离线 docx4j 运行时

完整已审劳务的实际公开下载在原LO中缺失三个U+FF0C，字体嵌入或语义文本提取不足以证明正文可用；同一Word字节的受控docx4j方案已由任务08选定。新正文生成快照显式记录docx4j版本及运行时锁指纹，以独立幂等维度经原队列、私有下载、内容修订/指纹和审计链输出；原无该选择的queued快照、旧成功文件和XLSX保留原引擎，不全局替换或隐式回退LO。

运行时由明确manifest指向精确JDK17、JAR、Java源码/class来源和已锁字体，子进程仅能访问独立scratch与锁定只读文件，清除继承的JVM/loader配置，加载Word前按命名空间和字段边界拒外部关系、简单字段及跨run主动指令并限制ZIP/XML资源；PDF流与父端读取均固定100000000字节上限，正式转换不落盘FO，JVM限制heap/direct memory/metaspace和线程栈。代价是部署方必须单独装配、核验运行时及字体，缺少或不匹配时失败，不以本机正控代替生产资格；完整字形/标点/分页/签署、实际新运行时负控及44发布门仍需独立证据，Python检查器仅在测试使用。
