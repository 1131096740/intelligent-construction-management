# 个人手写签名保存失败：本地诊断与修复

原诊断轮仅授权本地修复和验证；当前已另获提交、推送、PR、复审、完整CI通过后合并及准确合并SHA全17门授权，仍不部署生产。代码位于独立 `codex/signature-save-mobile` 目录，基于 `75d8f4b7`；未提交、未推送，未混入 PR #366。PR #366 合并版本为 `2f24cee3a44b9e4e37a9bd0107f3feaa4a0723e4`，其完整17门收据仅覆盖该合并源码，不覆盖此未提交签名修复。

## 已证实的失败链

2026-10-22 生产只读核验时源码为 `3f62377db3d1b1e1ca458310d094d7b3591f0796`。当日日志出现7次 `setCanvasSignature` 保存调用，对象存储响应 `451 / UnavailableForLegalReasons`。没有读取签名图像、密码或令牌，也没有替罗经理提交签名。

一次对绝不存在的合成对象键进行签名 GET（未读取已有对象、没有 PUT/DELETE），同样返回451；上游响应归类为账号欠费限制。没有查询账单金额或执行充值，不能将此结论写成已核实账务明细。腾讯云[错误码](https://cloud.tencent.com/document/api/436/7730)与[欠费说明](https://cloud.tencent.cn/document/product/436/10044)给出了相关451响应规则。其他员工和上传入口共用同一存储，因此也可能失败；不是罗经理岗位、手机直接登录或手写图片格式造成的专属权限问题。

真实 multipart HTTP 最小复现经过原控制器、解析器、MeService、FileService 与 PrivateFileStorage；模拟同一451返回，修复前实际得到500，前端对应“系统暂时无法完成操作”。原错误为普通 Error，且确定拒绝的PUT仍可能进入对象清理，导致上游原因被通用内部错误替代。

## 本地改动

- 存储明确返回451时输出固定中文503：“资料存储服务当前受限，暂时无法上传。请联系管理员检查服务状态，恢复后重试。”读取和删除沿用相应操作中文；不向用户暴露云端原文、云错误码、对象路径或凭据。
- 只对已确定被拒绝的PUT跳过对象删除；传输中断、未知写入结果、数据库失败等原有清理与防孤儿机制保持。失败不登记文件、不生成签名版本、不写成功审计。
- 手机直接签名及扫码签名失败提示明确“签名未保存，笔迹已保留”，可用原笔迹重试；扫码页的提示放在签字板和保存按钮后方。
- 缺文件或不是签字板图片属于输入错误，返回明确400；不更改签名来源、岗位、项目范围、审批权限或资金规则。
- 新签名继续产生不可变版本；旧签名文件与审批冻结引用保持，不回填真实人员或旧审批。
