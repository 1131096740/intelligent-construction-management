## 已完成的剩余缺口

| 缺口 | 最终代码行为及核算约束 |
| --- | --- |
| 经济重复复核 | 按真实履约范围关联文书，区分独立、补充、替代、共同依据；冻结双方版本、覆盖范围及本次生效目标；合同与财务按要求独立确认，留存追加修订链。部分重复仅排除确认覆盖部分，不能由任意复选框调成本。结算覆盖占用防止同一范围二次确认 |
| 同时变更 | 两份关联文书均有待确认版本时，明确选择本次先确认的文书，与另一份当前有效版本核对。另一份随后确认须重新复核；同一外部原事实只允许一份待确认更正，避免列表整体不可用 |
| 受控主体 | 表外下游使用受控相对方版本、名称及法人身份；我方公司互签、多方或无法识别关系保留例外核对，不静默塞入三类。旧资料不因缺字段自动分类 |
| 合同金额 | 表内、表外承诺、对上金额、业主依据分别列示；全额版本只形成净变更；对上固定/未定/无上限分开，追加金额修订保留历史基准日。合同金额不直接生成成本 |
| 财务分账 | 原债务人、批准付款人、实际出款人分别冻结；公司余额按实际现金持有人与真实债权债务归属计算；项目、单公司、授权跨项目使用同一来源及日期。对上往来保留主体分账，项目合并不重复收入成本 |
| 真实到账与核销 | 真实资金执行先形成一次现金事实及对应主体镜像；后续匹配/解除对上应收只改变核销，不再次改变现金。部分匹配、重复操作、并发及超额均校验；仍有匹配时不得直接冲销原到账，解除匹配后真实退回才恢复两侧资金 |
| 代付办理 | 新入口支持原结算关联、跨主体代付、一笔银行流水分配多笔同债务人/收款人结算、退款和代付款归还。原分类不随实际出款人变化；成本不随付款再增加。归还只清主体往来；退款恢复原核销。公司间归还须同时核验出款与入款侧流水 |
| 银行核验入口 | 财务经办提交回单；独立公司财务负责人查看私有原依据、上传本人独立账户证明并重新输入完整账号核对后确认。只存账号摘要及尾号，账号/流水号标准化防绕过；核验本身不改变资金。默认待核验、状态筛选、50 条分页，历史量增长不会阻断办理 |
| 同笔资金防重复 | 普通合同实付、资金执行、对上拨款、代付共享银行认领排他；施工企业付款对跨入口、法人版本别名及格式化流水号去重。数据库再校验来源项目、方向、金额、日期与持有人；同公司不同项目不能误认领。原全局受控银行来源保留其原权限链 |
| 历史兼容 | 只读预检在只读事务中比较已冻结事实与当前来源，并列示未投影来源、分类缺失及待复核；不执行补录、更新、重放或迁移。资料不完整保留金额及缺口，不能把未知报成完整零余额 |

退款、归还均受原款剩余容量与有效分配约束；不允许通过改分类或无原款关联操作创造负余额。已有工资、零采、费用、预付抵扣、保留款与到期可付规则保持各自权威来源，以非合同/原业务来源列示，不另复制一份合同成本。
