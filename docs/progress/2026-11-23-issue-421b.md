## 1. 结论

- 付款、零星采购、综合采购、报销四类台账均具备服务端筛选（项目/日期区间/状态/关键字）、白名单排序、显示列与必要列、导出预览与服务端 Excel 导出。
- 导出与列表**同读模型、同逐行可见性**：付款复用 `listRecent` 的逐行 `sensitiveBusinessReadAllowed`；零星复用 `scanAccessibleProcurements`/`accessibleProcurementIds`；综合采购复用同一访问 `where`；报销复用同一 `expenseLedgerRows` 跨项目/本人范围。无权行不会出现在导出中。
- 导出底层复用 421a 的 `ledger-excel.ts` 与 `ledger-export-query.ts`，新增 `business-ledger-export.ts` 统一收口工作簿生成与导出审计；公式注入转义、数值/日期单元格、合计与打印布局沿用同一实现，未知金额不写 0。
- 六台账导航入口统一收口到侧栏“业务台账”分组；付款台账路由补齐 `meta.title`。
- 表格排序、个人视图 v2（可见列/列顺序/列宽/排序，localStorage 按 `user.id` 分 key）与导出预览对话框已接入四个台账页面；综合采购由卡片列表改为统一表格。
- 真库/HTTP 5/5 用例通过；API/Web typecheck、`check:ui`、受影响与非受影响单测通过。

## 2. 服务端实现

### 2.1 共享导出收口（复用 421a）

新增 `services/api/src/core-flow/business-ledger-export.ts`：

- 输入已筛选、已逐行过滤的行与列定义，调用 421a 的 `buildLedgerWorkbook`（数值/日期单元格、合计、打印、公式转义）。
- `resolveLedgerExportColumns` 保证必要列始终导出；`exportBusinessLedger` 统一写审计（实际行数、可见项目数、筛选条件、导出列、`scope`）。
- 无审计服务时直接失败，不静默丢审计。

未另造导出底座：`ledger-excel.ts`、`ledger-export-query.ts`、`signed-settlement-ledger.service.ts` 的读模型/筛选/排序/列解析与审计形状均原样复用。

### 2.2 四类台账

| 台账 | 列表读模型 | 导出端点 | 行级可见性 |
| --- | --- | --- | --- |
| 付款 | `GET /payments?view&projectId&dateFrom&dateTo&status&keyword&sort&page...`（原 `listLedger` 扩展） | `GET /payments/ledger-export` | `listRecent(..., {all:true, actorUserId})` 内逐行 `sensitiveBusinessReadAllowed`；导出复用 `readLedgerRows` |
| 零星采购 | `GET /spot-procurements?...`（原列表扩展日期/排序/列） | `GET /spot-procurements/ledger-export` | `scanAccessibleProcurements` → `accessibleProcurementIds`；列表与导出共用 `filteredProcurementRows` |
| 综合采购 | `GET /general-procurements?projectId&dateFrom&dateTo&keyword&sort...` | `GET /general-procurements/ledger-export` | 复用原 `listRoles` 访问 `where`（申请人/项目经理/综合/财务/归档）；列表与导出共用 `ledgerWhere` + `toLedgerItems` |
| 报销 | `GET /expense-claims/ledger?...`（新增） | `GET /expense-claims/ledger-export` | 财务/综合/公司领导/项目经理按可见项目跨项目查账（含公司日常 `projectId=null`）；普通员工仍走 `listMine` 本人/经办/参与审批范围；列表与导出共用 `expenseLedgerRows` |

- 付款行新增真实业务双方：签约方（甲方）取合同 `companyEntityName`，相对方（乙方）取合同 `counterparty`；项目、合同标识进入行模型，供服务端筛选与导出使用。
- 综合采购行新增采购单位（公司主体）、供应商与实际采购金额（来自 `ActualPurchaseBatch`，无批次时保持“待确定”/空白）。
- 报销行新增报销单位、费用类别、收款对象；公司日常不伪造成项目。
- 未知金额：零星/综合/报销的未知金额保持空白或“待确定”，数值列不写 0；付款“已付 0”是真实资金事实，保留 0。

### 2.3 审计

新增导出审计动作：`payment.ledger.export`、`spot_procurement.ledger.export`、`general_procurement.ledger.export`、`expense_claim.ledger.export`。
