## 4. Task 1 实现事实

共享领域层新增 `SETTLEMENT_IN_PROGRESS_STATUSES`，只包含：

- 草稿；
- 审批中、待审批、审批驳回、撤回；
- 最终文件生成中；
- 审批完成待归档及待归档确认。

它明确排除：

- 已生效；
- 部分付款；
- 已付款；
- 已作废。

因此，上一期结算归档生效但尚未付清时，不会阻止下一期结算。

`SettlementDraftService.create` 和 `copyAbandoned` 在已锁定合同及当前有效版本后，依次检查：

1. 是否存在未提交且未作废的结算草稿；
2. 是否存在仍在办理的正式结算。

存在占用时返回包含结算编号的中文业务错误，不创建第二份草稿。
合同锁使两个并发新建请求串行观察同一占用事实。

## 6. 数据与发布边界

后续 Schema 可以前向新增稳定来源字段、映射表、索引和约束，但历史来源回填不进入普通迁移自动执行。

历史回填必须另行完成：

1. 生产只读预检；
2. 无歧义和待人工确认清单；
3. 备份及隔离恢复验证；
4. 独立数据变更授权；
5. 执行后数量、金额和结算可用量只读复核。

应用发布授权不能替代历史业务数据回填授权。
