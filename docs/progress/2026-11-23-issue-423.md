## 二、矩阵派生方式（单一真相）

`packages/shared-domain/src/navigation-access.ts`：

1. 入口目录 `NAVIGATION_ENTRY_ACCESS` 共 39 个入口，每个入口只声明三类来源之一：
   - `authenticated`：后端对应列表接口本身就是登录可读（如零星采购、综合采购、费用报销、系统配置/我的账号）；
   - `actions`：岗位由 `ACTION_REQUIRED_ROLES` 展开——这是后端 `canPerform` 守卫使用的同一张表（如工资承担＝`wage_statement.*`、公司互转＝`fund_flow.read`+`contract.create`、其他项目付款＝`project_expense.*`）；
   - `positions`：岗位来自后端只读 Guard 的常量。
2. 只读岗位常量上移 shared-domain，并让 Nest 控制器同源引用，避免“导航一份、Guard 一份”：
   - `CONTRACT_LEDGER_READ_ROLE_KEYS`（合同/结算/付款台账，`services/api/src/auth/ledger-read-positions.ts` 改为引用）；
   - `PROJECT_OVERVIEW_READ_ROLE_KEYS`（项目经营总览）；
   - `ARCHIVE_READ_ROLE_KEYS`（`ArchiveController`）；
   - `AUDIT_READ_ROLE_KEYS`（`AuditController`）；
   - `FUND_ACCOUNT_READ_ROLE_KEYS`（`FundAccountController`）；
   - `FUND_EXECUTION_READ_ROLE_KEYS`（`FundExecutionController`）；
   - `ORGANIZATION_DIRECTORY_READ_ROLE_KEYS`（`ORGANIZATION_MANAGER_ROLE_KEYS` 改为引用）。
   以上替换与原子面量逐字等价，不改变后端授权行为。
3. `visibleNavigationEntryKeys(roleKeys, globalRoleKeys)` 是唯一展开点：兼职岗位自然取并集、去重；`company_entity` 保留 global-only 语义。
4. `route-records.ts` 只引用 `NavigationEntryKey`；`routes/index.test.ts` 断言每个导航项**不存在** `requiredRoleKeys/requiredGlobalRoleKeys`。
5. 判断保留：合同/结算工作台按后端台账读取岗位（含 `employee` 的摘要路径）可见；审计/档案/员工管理/资金账户/项目经营按后端只读 Guard 收紧。导航可见性不是授权边界，写动作仍由后端逐接口校验。
