## 2. 判定：harness 授权缺口，不是产品 07500 缺口

- `07500` 的 ACL 保留块把旧 `jg_file_business_binding_columns()` 的 ACL 复制给新别名 `_before_signed_settlement` 与新 current，**迁移前已存在的生产角色**因此保留 EXECUTE；迁移无法、也不应给迁移后才创建的测试角色按名字发 GRANT。
- bank fixture 的 `fileGuardCalls` 由静态 `local-staged-migration-qualification.json.collision_routines` 生成；该目录只到 `_before_registered_payment` 一代，没有 07500 的 `_before_signed_settlement`，所以 role 创建后没有被授予新别名。
- `ContractSignedChange` / `SignedContractSettlementAttachment` 是 forward 新表；bank fixture 的 `GRANT SELECT ON ALL TABLES` 快照没有覆盖它们（本 lane 实测缺 SELECT），而 enforcer 的跨业务冲突循环会以 runtime（SECURITY INVOKER）读取这两张新表。
- 结论：**test/harness 授权 provisioning 缺口**。生产侧由 ACL 安装在后置阶段以 `GRANT SELECT ON ALL TABLES`/既有 ACL 继承覆盖；本次不在 07500 内按未知角色名补 GRANT，也不放 PUBLIC。
- `failure-projection.cjs` 的 known function 名单只有 `…_before_registered_payment`，新别名被归为 `unclassifiedDenial=true`；已补入，避免把真实 42501 误投影成未知拒绝。
