## 6. 切换与回滚

### 切换

1. 冻结：撤销 `PUBLIC` 与应用角色 CONNECT，`has_database_privilege=false`；
   owner 核对会话仍可连接；冻结期间指标与冻结前一致，迁移账无 pending。
2. 开放：恢复 CONNECT，写入增量——新合同/版本（`numericProtocolVersion=2`、
   `amountYuan=1234.5678`）、结算草稿、资金账户、2 条审计。
3. 判据：`Contract 80→81`、`ContractVersion 107→108`、`Settlement 120→121`、
   `RegisteredFundAccount 0→1`、`AuditLog 20000→20002`；旧表摘要不变。
4. 切换后再备份/恢复：增量存在于恢复副本，其余指标一致。

### 回滚

- **写前回滚**：`pre.dump` 恢复后与基线指标逐字节一致；迁移账回到 261；
  增量 ID 不存在；旧版付款查询仍返回 `360 / 306,616,050`。
- **写后边界**：直接用 `pre.dump` 恢复会抹掉增量（`AuditLog 20002→20000`、
  `Contract 81→80`），因此写后不得直接回滚旧备份。正确路径是停写、导出增量、
  恢复旧备份并前向前移、重放增量并逐项对账。
- **前向修复验证**：`pre.dump` → 迁移到 277 → 重放 `increment.sql`，其指标与
  切换后主库**逐字节一致**（`7762f878…`）。

## 7. 失败与处置

1. 直接用 `prisma migrate deploy` 从空库重放 261：在
   `20261108220000_contract_archive_v2_authority` 被“真实归档应用角色或函数资格未提供”
   拒绝。处置：改用仓库既有 staged migration fixture（CI 同源），在 204 前安装
   ACL/角色并在 213/215/218/221 执行 tail qualification；未改迁移文件。
2. `20261118221000_contract_legacy_guard_relation_namespace`：干净重放缺少生产安装器
   写入的函数前态，报 `query returned no rows`。处置：应用
   `services/api/prisma/line-a-replay-archive-install-shim.sql`，再
   `migrate resolve --rolled-back` 后续跑；shim 前态不匹配会拒绝，未伪造。
3. `20261118223000_contract_normal_generated_archive_assignment_lock`：报
   `NORMAL_ARCHIVE_ASSIGNMENT_INSTALL_SCOPE`。该迁移要求
   `jg_contract_direct_upward_closure_v2` 恰有一行安装闭包；仓库内没有任何迁移写入
   该行，只有生产归档安装链（`.github/task12-install-295/contract-finance`）在真实
   角色、TLS、资源证明下产生。处置：**停止，不插入伪造行、不 `resolve --applied`**；
   将失败尝试标记回滚，留下 277 的干净账。后续 51 条迁移需在真实安装器执行后继续。
4. 首次清理遗漏了最早创建的辅助容器；最终复核时发现 `docker ps -q` 非空，已按容器
   名/标签只删除本演练容器及其命名卷，再次复核为空。
