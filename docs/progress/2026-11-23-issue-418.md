## 3. 去重键设计（可证明）

```
identity = {
  contractVersionId,          // 旧 Settlement.contractVersionId / 新已签冻结 sourceRecordId
  period,                     // 旧 periodLabel（或 code 回退）/ 新已签手填编号 number
  contractKind                // downstream | upward | outside_fact
}
dedupKey = contractKind + "\0" + contractVersionId + "\0" + normalize(period)
normalize = NFKC + 去空白 + 大写（仅归一全半角/空白，不忽略真实编号差异）
```

- 键不含「来源表类型」：正因旧/新入口是不同来源表，才需要跨表统一；`upward/outside_fact` 由 `contractKind` 分开，不同合同版本/不同期次也不互相去重。
- 写入：已签复核事务内、数据库复核函数之后执行旧结算检查；冲突抛 `ConflictException`，整个复核（含 `AuditLog`）回滚。旧结算归档确认事务内反向检查已签结算，冲突则归档确认回滚。
- 读取：对 `settlement` / `signed_contract_settlement` / `project_affiliate_settlement_fact` 三类来源的已存事实按同一键去重；先到事实保留，后续事实不再计入成本/应付，`asOf.crossSourceDedupedFactCount` + `integrity.notices` 暴露。金额不一致时关闭金额投影（`moneyComplete=false`），不静默择一。
- 期次或合同版本缺失时**不去重、不猜测**；既有历史事实快照缺少 `periodLabel` 的，需重放/迁移回填才能纳入，见第 6 节。
