## 3. 去重键与归属确认一致性

```
identity = {
  contractVersionId,          // 旧 Settlement.contractVersionId / 新已签冻结 sourceRecordId
  period,                     // 旧 periodLabel（或 code 回退）/ 新已签手填编号 number
  contractKind                // downstream | upward | outside_fact
}
dedupKey = contractKind + "\0" + contractVersionId + "\0" + normalize(period)
normalize = NFKC + 去空白 + 大写（仅归一全半角/空白，不忽略真实编号差异）
```

- 写入：已签复核事务内、数据库复核函数之后查旧结算；旧结算归档确认事务内查已签结算；冲突抛 `ConflictException`，整笔事务（含审计）回滚。
- 读取：`settlement` / `signed_contract_settlement` / `project_affiliate_settlement_fact` 三类来源按同一键去重；先到事实保留，后续不再计成本/应付；金额不一致关闭金额投影并提示。
- 归属确认：行上保存 `sourceDedupKey`；确认前若同一键已确认到另一事实则拒绝。读侧先按去重键保留唯一事实，再用确认行替换该事实的成本承担公司，因此「去重 → 归属」顺序一致，确认不会复活被去重的重复成本。
- 期次/合同版本缺失时不去重、不猜测；历史快照缺 `periodLabel` 的需回放回填后才能纳入。
