## 2. 共享导出底座设计

### 2.1 `services/api/src/core-flow/ledger-excel.ts`

- 列定义新增 `kind: "text" | "number" | "date"`、`numFmt`、`align`、`required`、`total: "sum"`。
- 数值列写 Excel 数值单元格（`#,##0.0000`），日期列写日期单元格（`yyyy-mm-dd`）；文本列统一转义。
- 未知值：`null`/空串保持空白；`待确定`/`不设合同总价` 等业务文案按文本写入；合计只累加真正的数值单元格，全部未知时合计保持空白。
- 公式注入：`escapeSpreadsheetText` 对 `= + - @` 以及前导 Tab/回车加单引号，数值列不误伤负数。
- 合计行、表头样式、冻结首行、自动筛选、列宽、边框；`print` 选项设置 A4 横向、`fitToPage`、`fitToWidth=1`、重复表头 `1:1`。
- 保持既有调用（公司互转、历史接管、签约关系等）向后兼容。

### 2.2 `services/api/src/core-flow/ledger-export-query.ts`

- `normalizeLedgerExportQuery` 只接受约定字段（未知字段忽略），日期必须是 `YYYY-MM-DD` 且开始不晚于结束；按 Asia/Shanghai 自然日比较。
- `matchesLedgerExportQuery` 统一项目/日期/状态/关键字筛选；调用前必须先完成行级可见性过滤。
- `resolveLedgerExportColumns` 按用户显示列顺序导出，未知列忽略，**必要列始终补回**。
- `sortLedgerRows` 仅接受调用方白名单字段，未知字段保持服务端默认顺序。

### 2.3 合同台账导出

- `GET /contracts/ledger-export` 接受 `projectId/dateFrom/dateTo/status/keyword/columns/sort`。
- 导出“全部筛选结果”：先由 `listRecent(unbounded)` 完成逐行可见性，再在服务端筛选/排序/选列。
- 列：合同编号、合同名称、合同分类、项目、签约方（甲方）、相对方（乙方）、类型/计价方式、合同金额（元）、金额说明、版本、付款条款版本、当前节点、当前责任人、停留时间、退回原因、下一步、更新时间。
- “合同金额（元）”为数值合计列；框架不设总价/金额未确定时写“不设合同总价/待确定”，不写 0。
- 审计新增筛选条件与导出列，`scope=all_filtered_visible_records`。

### 2.4 已签结算台账（G19）

- 新增 `GET /settlements/signed-ledger` 与 `GET /settlements/signed-ledger-export`。
- 读模型：`SignedContractSettlement.state = "confirmed"`，跨 `visibleProjectIds` 合并；项目名、冻结来源中的签约方/相对方/合同名称/关系、复核人、复核日期均来自真实数据。
- 行级：合同部主管/合同部、财务、综合主管、项目经理等有权查账岗位可见；员工等仅项目可见岗位不返回行。列表与导出共用 `readRows`。
- 列表返回 `summary`（已复核笔数、已知/未知金额笔数、已知合计、项目数、最近复核时间）、`filters`、`columns`（含必要列标记）；导出使用同一筛选与列解析。
- 导出审计 `settlement.signed_ledger.export`，`scope=all_filtered_confirmed_signed_settlements`。
- 旧 `GET /settlements/ledger-export` 保留并标注“历史数据兼容”，不作为本轮正式结算台账口径；旧 `Settlement` 的退役留给后续票据。

### 2.5 Web

- `core-flow-read.api.ts` 新增带筛选参数的合同导出、已签结算列表/导出调用；既有下载方法保持字面路径以通过 web-api 因果清单。
- 合同台账导出按钮改为传当前项目/关键字/状态/显示列。
- 结算工作台新增“已签结算台账（仅主管复核通过）”摘要条与“导出已签结算台账”按钮，展示已复核笔数与已知合计；待复核/草稿仍在“已签结算登记”工作台办理。完整独立台账页签/导航与筛选 UI 属后续 UI 收口。
