# POL108 计时、准备去重与受控写入时间戳（本地验证）

## 范围与基线

用户授权按顺序完善计时和准备去重，再验证受控写入直接返回数据库 `createdAt`；保留全部测试和业务校验，不部署、不操作生产。

本轮基于 `d899e4eacd8276f04fae4e26d21416650fcc1b84`，独立分支 `codex/pol108-preparation-created-at`。原 PR [#338](https://github.com/1131096740/intelligent-construction-management/pull/338) 已于 2026-10-19 合并；对应 [main CI](https://github.com/1131096740/intelligent-construction-management/actions/runs/39229965394) 成功。它不代表本轮未提交修改通过远端 CI。

## 实现

1. 查询计时先累计高精度耗时，再于阶段输出时统一取整；失败查询也记录耗时。分别记录幂等查询和写入后时间戳回读，增加套件夹具与 generate/build 准备计时。仅记录汇总，不打印 SQL 参数或密钥。
2. POL108 外层真实 generate/build 后直接启动对应分组，免除重复 preverify；独立 pnpm 入口原准备流程保留。remaining CI job 由自己的 runner 完成一次 generate/build，16 个批次直接执行原具名 Jest 文件，免除逐批 pretest。没有环境跳过开关、缓存信任标志或跨提交产物复用。一次选择混合多个门时，其他门与 remaining 仍各自负责准备；没有扩大为全仓缓存框架。
3. 新迁移仅扩展受控分录 INSERT 的返回列：`id, createdAt`。原授权、密码验证、INSERT 数据、约束、触发器和事务边界保持。现有服务优先使用返回时间，旧函数的兼容回读分支保留，没有用应用时钟代替数据库时间。
4. [PostgreSQL 16 要求改变函数返回类型时重建函数](https://www.postgresql.org/docs/16/sql-createfunction.html)。迁移使用原子 DO，保留 owner、ACL、grant option、安全配置和注释；依赖对象导致 RESTRICT 失败，委托授权链明确失败关闭。没有 CASCADE，没有修改历史迁移。迁移基线同步到 175。

## 测量方法及边界

两份独立源码快照从同一基线创建，各轮三组并行、每组独立一次性 PG16。旧版本完整结束后才运行优化版；生成源码 SHA-256 并核对运行前后不变。本地诊断不冒充干净提交的正式验收，正式 runner 的 clean/exact-SHA 检查未改。

准备测量单独重放 remaining job 的旧/新准备命令序列，排除 Jest 和数据库执行。它衡量去重掉的准备工作，不是整个 remaining job 的 CI 用时。机器上有其他本地任务，单轮墙钟差异不能全部归因于本次修改；远端 CI 仍须固定提交后实测。

两轮均 14/14，源码运行前后保持一致：

| 测量 | 旧版本 | 优化版 | 解释 |
| --- | ---: | ---: | --- |
| remaining 准备命令 | 72.479 秒 | 15.003 秒 | 节省57.476秒，约79.3%；不含测试/数据库 |
| 普通12项 | 35.265 秒 | 30.758 秒 | 墙钟观察值 |
| 20,001事实 | 521.699 秒 | 306.883 秒 | 观察下降41.2%，包含环境波动 |
| 100,001分录 | 803.978 秒 | 464.997 秒 | 观察下降42.2%，包含环境波动 |

**不把完整测试的约42%变化全部归因于代码。** 未修改的 crypt 在事实组也从171.703秒降到110.648秒，说明两轮机器负载不同。

为隔离单次回读成本，追加一个独立诊断：同一临时PG、同一真实授权/INSERT/幂等服务，交替让受控函数结果保持 `id+createdAt` 或仅向原服务交付 `id`、触发其真实兼容回读；2次200条预热后，两种模式各3批1000条，交错顺序。这个诊断不是旧数据库版本的完整验收，也没有替换或削减原14项。

- 原兼容回读：4431、4555、4389ms，均值4458.3ms。
- 直接返回时间戳：4057、4296、3918ms，均值4090.3ms。
- 同次配对均值减少368ms/1000条，约**8.3%**；这是本机样本，不能直接当作GitHub job的提速比例。
- 每批原幂等查询与受控写入均为1000；时间戳回读1000→0。

完整大测试的确定性计数：facts 回读20001→0，impacts 回读100001→0；幂等查询仍各20001/100001。含固定夹具，facts 的受控分录写入20021次/授权40033次/crypt40034次，impacts 的受控分录写入100021次/授权100035次/crypt100036次，前后完全一致。
