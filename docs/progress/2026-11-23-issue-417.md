## 1. 结论

- 综合部主管可在“历史费用核实入账”入口先选项目，按网格/粘贴一次登记多条历史无合同费用：用途、类别、金额、付款情况、已有依据；不要求也不创建合同或结算。
- 财务逐行核实为「已核实」「待核对」「未发生」，每行独立状态；20 行可先入 18 行，2 行保留待核对且不丢。
- **补资料**：待核对行补充付款公司、付款状态、金额依据后重新核实并再次主管复核入账；原行与上一次核实事实追加保存在行 `_history`，不覆盖、不删除。
- **更正**：已入账行由财务主管填写原因并更正；系统在同一事务内先冲销原经营事实（反转），再按更正后金额重登新事实，原行、原事实 ID 和原复核记录全部保留，审计记录原/新金额与差额。
- 付款状态未知是独立值，不按已付或未付；费用与已付可确认而付款公司/资金来源不明时，成本照常确认，另写「付款公司/资金来源待核对」提示。
- 显式 `0` 与空白金额分开：空白金额阻断；`0` 仅允许标记「未发生」，不生成经营成本。
- 同一输入重复导入返回原批次；重复激活/重复更正不重复计成本；未重新主管复核的补资料行不能入账。
- 历史费用不写资金账户、不产生付款/结算/合同事实，不再扣启用时现金/公司资金期初，与 #416 历史期初口径一致。

## 6. 未覆盖 / 边界

1. **经营账数据库函数未重放**：真库用例用受控端口记录经营账输入（与 #405 真库用例同口径），断言反转为完整反向影响、重登为新事实、`confirmed_cost` 次数/金额/无资金影响；未在真实 PG 内执行 `appendOperatingFactThroughService` 等迁移函数。生产前仍须由完整迁移链/正式入口复验。
2. **更正为单次链式**：同一原行只允许一次成功更正（防重复）；如更正行还需再更正，可对该更正行再次发起反转+重登，形成链。未提供批量更正。
3. **时间口径**：历史费用要求发生日期在项目经营账启用日前；启用日后的费用拒绝并提示走正式费用流程。`0` 金额行只能标记未发生，不能作为 0 成本入账。
4. **成本承担公司**：未填时，只有项目事实日恰好一个参与公司才自动使用；多个公司时阻断并要求补全，不虚配。
5. **付款公司/来源不明**：成本与实付金额可确认，但只写待核对提示，不写资金账户、不虚构付款主体；历史实付金额记录在接管事实快照，不产生正式实付。
6. **“项目或公司日常”分行归属**：本入口按 HIS-10「先选一项目」只支持项目范围历史费用；公司日常（不归属项目）历史费用未在本入口实现，且经营账事实按 `projectId` 记账。公司日常费用应走费用与报销/其他项目付款等正式入口；若要把历史公司日常费用纳入同一接管账，需另行确认数据归属和迁移。
