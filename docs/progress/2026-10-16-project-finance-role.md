# 项目财务授岗与建账提示修复

准确基线为 `1d415dd5c662d548b0de88618ff0d00d15f5491c`。按 [Issue #327](https://github.com/1131096740/intelligent-construction-management/issues/327) 交付；所有者已批准公开代码、测试与技术说明，并继续 PR、CI、合并和正式发布。本记录仅确认本地验证，发布结果须以准确提交的后续证据为准。

## 问题与行为

经营档案只允许明确绑定项目的财务人员维护，但财务经办被岗位范围注册限制为公司级，导致董事长无法通过组织页面给其他项目安排财务。沿用合同经办的双范围机制，将 `finance_staff` 纳入公司/项目双范围。项目授岗仍验证董事长身份、当前密码、预览一致性，事务内写岗位/花名册、撤销旧会话并记录审计；不会创建隐式公司岗位。财务主管仍为公司级岗位。

真实 PostgreSQL 16 测试同时发现缺公司资料时，Prisma 5.22 把数据库触发器的 23514 包装成未知错误，原提示转换未识别而返回 500。补充严格限定的包装识别，只返回既有精确中文白名单；其他错误和并发处理不变。数据库仍要求唯一施工企业和有效我方参与公司，未修改触发器、Schema 或迁移。
