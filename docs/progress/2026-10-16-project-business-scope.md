# 多项目业务范围验证记录

关联 Issue #333。规格：[多项目业务范围](../specs/2026-10-16-project-business-scope.md)；发布：[执行顺序与恢复](../runbooks/2026-10-16-project-business-scope-release.md)。本地候选基于 `685daba763182b64cff18ac8e565a868816d1ebf`，生产结果另按最终准确提交核验。

## 已复现的问题与改动

- 公司合同岗在通用项目选择、综合采购、本人费用和合同提交之间范围不一致。统一复用项目可见性及有效岗位规则，公司合同经办作用于全部启用项目。
- 普通人员仅登记项目岗位时，旧通用下拉可能漏掉所属项目。现取项目岗位、项目成员与花名册的当前所属项目并集。
- 零采旧试点仅放行特定项目，台账筛选还误用了材料岗位的新建范围。台账使用可见项目，新建使用可办理项目；正式配置支持单独的 `*`，新项目自动纳入，显式空值及限定清单仍可用于暂停或限定范围。
- 合同及结算审批查询只读取旧项目成员表，遗漏新组织管理中的项目岗位。事务内锁定并合并两种项目授权；现场复核、项目经理和总工始终来自单据项目，花名册不会成为专业审批授权。
- 独立审查发现普通付款重新承认错误全局项目经理，以及零采/普通付款缺人时仍可提交；真实 HTTP 红例复现后统一有效岗位解析，并在原岗位审批链提交时核验有效候选。本人费用和旧项目费用也排除错误全局项目岗，既有委托和审批顺序保留。
- 合同草稿隐私、原资金概览岗位、财务执行、自审、冻结候选、金额与来源项目约束保留；无需迁移和真实数据回填。

## 验证证据

新增一次性 PostgreSQL 16 / HTTP 验收共 11 项，含真实登录、公司/项目/跨项目/花名册人员、新建及停用项目、无项目经理、私有草稿和纯技术管理员边界。初始测试已实际复现范围和合同提交错误，修复后通过。普通合同付款、零采和综合采购均走实际申请及后续付款审批，验证其他项目经理和错误全局项目岗被拒绝、正确经理通过及付款项目继承；结算复核选项和冻结审批名单验证项目岗位兼容。

配套 Chromium 桌面与 WebKit 手机共 4 项，验证董事长台账筛选、材料岗位多项目明确选择和普通员工仅所属项目。未使用生产会话、真实手机号或真实材料。

相关 172 项与补充旧规则回归 118 项通过；全量 API 7,937 项、共享域 240 项、Web 2,150 项通过；类型、lint、UI 与动态门编排 52 项通过。API 常规运行跳过的数据库场景由原强制 PostgreSQL 16 动态门单独执行。固定提交双审、CI、准确 main 的原完整 17 门及生产验收继续按实际结果登记，不将本地证据当作上线完成。

失败记录包括：首次本机 Prisma 缓存沙箱权限、旧用例预期、合成主数据不完整、错误测试路由/选择器，以及改动期间生成清单构建过期；均保留私有原件。没有通过调大超时、跳过失败用例、关闭业务约束或改生产数据放行。
