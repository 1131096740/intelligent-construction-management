# 历史合同接管台账误路由修复

日期：2026-08-01
状态：本地候选已闭合，尚未推送或部署

## 现场结论

生产只读核对确认，用户反馈的 `CHYB-机械-2026-006` 没有被转换成新签合同：

- `Contract.source = historical_takeover`
- 当前 `ContractVersion.changeType = historical_takeover`
- 存在对应 `ContractTakeover`，状态为 `draft`
- 记录所属项目为 `JGXM-002`；截图中的历史接管页当时选中的是 `JGXM-001`

问题发生在台账投影与页面路由：普通合同台账没有返回历史接管坐标，操作列又统一进入普通合同工作台；历史接管页也没有消费项目和接管记录深链。因此记录在数据上仍是历史接管，但用户界面把它投影成了新签合同办理入口。

## 修复边界

1. 后端合同台账一次性批量加载当前版本、精确 `ContractTakeover` 关系与逐项目有效岗位，不逐行查询；只有当前项目具备历史接管读取岗位时才投影 `takeoverId`、`takeoverStatus` 和精确阶段。
2. 普通合同工作台只有在“当前版本不是 `historical_takeover` 且不存在精确接管关系”时才允许读写；历史合同后续已进入普通变更且不再绑定接管关系时仍走合同变更工作台。
3. 历史接管行按接管状态显示“继续接管”或“查看接管”，有历史接管读取权限的账号进入：

   `/历史合同接管?projectId=<项目>&takeoverId=<接管记录>`

4. 历史接管页按深链先选择目标项目，再选择目标接管记录；项目或记录不可见时明确失败，不回退到第一个项目。
5. 没有当前项目历史接管读取权限的合同台账用户只看到通用“历史合同接管”语义和“查看详情”，响应不包含接管 ID、精确状态或节点，不因在其他项目有岗位而扩权。
6. `changeType` 标志与精确接管关系任一存在都会失败关闭；二者不一致时向有权限账号投影“接管关联异常”，并禁止普通工作台 GET、保存及旧读写入口，绝不回退到普通新签工作台。
7. 旧收藏或旧链接若直接打开普通合同工作台，后端返回稳定错误码 `HISTORICAL_TAKEOVER_WORKBENCH_REQUIRED`；前端清空工作台模型、隐藏编辑器并引导返回历史合同接管。
8. 编辑租约、聚合保存、资料检查、审批提交、草稿复制/放弃、合同正文、清单、合作单位和磋商等普通写入统一经过共享版本锁边界；标志或精确关系命中时在幂等回执与任何写入前拒绝，写错误仅返回 `null/null` 坐标。后台文档任务仅可受控检查并标记 `stale`，不可继续生成。
9. 旧 `/contracts` 读取与导出也批量识别当前版本的接管关系；全局搜索/导出不再把接管中草稿显示为“提交合同审批”，而是不含 ID 和精确状态的通用“历史合同接管”语义。

本修复没有修改 Prisma Schema、数据库迁移、合同或历史接管业务数据，也没有改变历史接管审核状态机。
