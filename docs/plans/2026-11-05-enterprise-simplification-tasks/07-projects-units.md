# 07：项目与单位主信息按新角色简化

**状态：** `plan-confirmed` / `not-started`；前置工单未关闭，尚未实施。本轮用户已授权整套实施及 GitHub 工单推进；[#389](https://github.com/1131096740/intelligent-construction-management/issues/389) 已发布，归属父工单 [#382](https://github.com/1131096740/intelligent-construction-management/issues/382)。迁移、受控实验、部署与生产变更仍按各自具体授权执行。

**类型：** 业务垂直片。目标为一个新会话可完成的边界；如果探索发现仍跨越多个独立用户路径，应先收窄票据再执行。

**交付行为：** 授权人员维护项目和现有单位档案，项目唯一施工企业、可有多家我方公司；人员入口与完工状态明确。

**Blocked by：** [05 统一岗位配置、自审和委托权限](05-personnel.md)。

**需求：** IAM-09、IAM-10、IAM-11、IAM-12、BAS-04。以[完整规格](../../specs/2026-11-05-enterprise-simplification-spec.md)最终规则为准，不能只实现票据标题。

**技术决定：** [技术方案](../2026-11-05-enterprise-simplification-technical-plan.md) D01。**公开验收：** [验收情景](../2026-11-05-enterprise-simplification-acceptance.md) A05、A35。

## 验收条件

- [ ] IAM-09：这三类可新建/修改项目基础信息并保留记录；管理员配人。同名项目只提示核对不阻止。
- [ ] IAM-10：一项目仅一家施工企业，不做施工企业更正入口；从已有单位档案搜索选，缺档由综合主管或董事长先新增；一项目可多家我方公司。
- [ ] IAM-11：项目人员入口看经理/总工/合同员/物资员等；维护统一到人员与岗位。项目可标已完工，仍可结算付款查历史。
- [ ] IAM-12：沿用我方公司主体和合作单位档案，只有这两岗新增/修改/停用；旧合同留签约快照。普通填单人直接新名称只用于本单。
- [ ] BAS-04：表内合同=我方公司与下游；表外合同=施工企业与下游；对上合同=我方公司与施工企业。项目经营的表内=我方公司、表外=施工企业；业主与施工企业关系单独表达，不能把其也混称为我方对上合同。
- [ ] 施工企业从已有档案选择；不添加项目施工企业更正流程；同名提示允许。
- [ ] 仅综合主管和董事长维护单位；停用不破坏历史引用；项目经理只本项目。
- [ ] 项目已完工仍可结算付款查看，不能误设业务封账。

## 验证与边界

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
