# 13：补充协议和税务补充更正统一入口

**状态：** `plan-confirmed` / `not-started`；前置工单未关闭，尚未实施。本轮用户已授权整套实施及 GitHub 工单推进；[#395](https://github.com/1131096740/intelligent-construction-management/issues/395) 已发布，归属父工单 [#382](https://github.com/1131096740/intelligent-construction-management/issues/382)。迁移、受控实验、部署与生产变更仍按各自具体授权执行。

**类型：** 业务垂直片。目标为一个新会话可完成的边界；如果探索发现仍跨越多个独立用户路径，应先收窄票据再执行。

**交付行为：** 从合同台账或详情明显入口提交已签补充协议/变更，主管复核生效；税务待补直接补，已填更正复核。

**Blocked by：** [12 合同并联审批、盖章和签署归档](12-contract-lifecycle.md)。

**需求：** CON-19、CON-20、CON-21、HIS-09。以[完整规格](../../specs/2026-11-05-enterprise-simplification-spec.md)最终规则为准，不能只实现票据标题。

**技术决定：** [技术方案](../2026-11-05-enterprise-simplification-technical-plan.md) D04、D05。**公开验收：** [验收情景](../2026-11-05-enterprise-simplification-acceptance.md) A09、A12。

## 验收条件

- [ ] CON-19：合同台账行操作及详情顶部明显显示补充/变更；上传双方已签补充协议、填写简要变更及增减金额，合同部主管复核后生效，不重新走完整合同审批。
- [ ] CON-20：展示原金额、变更、当前金额；框架只改单价/范围而未定总价仍未约定；变更不改历史结算和付款，金额低于已结算/已付时提示核对但允许如实登记。
- [ ] CON-21：合同员手动更新付款约定，主管复核后生效；已经提交的付款提示约定已更新，可看提交时和最新约定，不自动阻断。
- [ ] HIS-09：原空税率/发票类型可直接补充并留记录；已填错误由合同部提修订、主管复核，保留原值；不自动重写已确认金额。
- [ ] 原金额/增减/当前金额并列，框架仍可未定总价；低于已结算/付款提示允许真实登记。
- [ ] 不改旧结算和付款；付款中显示提交时及当前文本差异，无比例硬阻断。

## 验证与边界

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
