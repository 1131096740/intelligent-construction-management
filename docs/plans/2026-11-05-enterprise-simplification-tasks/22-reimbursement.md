## 验收条件

- [ ] EXP-01：所有角色可发起；没有采购申请也可报销；可人工选择已有采购，系统不自动识别匹配；采购已付/已确认成本不得再次重复支付/计成本。
- [ ] EXP-02：多维表格填类别、事项、数量（可空）、金额；同单可餐饮/车辆等多类别，按行统计并汇总；不是只填一笔总金额。
- [ ] EXP-03：一张单只选一个项目，跨项目分单；公司日常费用单独，允许不关联项目。
- [ ] EXP-04：同单多PDF/照片统一上传，不要求每票关联明细；可先提交后补，提示待补充，审批人判断。
- [ ] EXP-05：追加附件不改金额/明细，不因此重走审批；有权审批/财务可见新增凭证；改金额/明细仍按撤回或更正规则。
- [ ] EXP-06：普通项目报销通过后确认成本，实付只清偿；公司日常记公司费用，不虚构项目；已有采购成本关联时不再增加成本。
- [ ] EXP-07：默认零星材料、水电、零星机械、零星人工、差旅、餐饮、后勤、办公用品、车辆使用费、其他；填单人可新增，公司复用并汇总；同名提示复用，不能重复建同名项。
- [ ] EXP-08：零采默认零星材料；综合采购按实际选办公等类别；关联采购报销沿用原类别，直接报销按各明细选择；类别不是业务流程选择器。
- [ ] PUR-12：零采和综合采购均可带出原采购信息及附件；公司直付600+员工垫400的1000采购，员工仅报400；保留同一成本来源。
- [ ] 每单单项目、公司日常另单；凭证全单可后补，新增类别共用复用、同名不重复；类别不改变业务路由。
- [ ] 采购600公司付+400个人垫时只报400，成本只采购批次确认一次；无采购的普通报销通过才确认费用。
- [ ] 明细数量可空、金额真实；一单餐饮车辆等分行，审批PDF与导出有中文明细。

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
