# 26：按真实来源登记垫资到账和使用

**状态：** `plan-confirmed` / `not-started`；前置工单未关闭，尚未实施。本轮用户已授权整套实施及 GitHub 工单推进；[#408](https://github.com/1131096740/intelligent-construction-management/issues/408) 已发布，归属父工单 [#382](https://github.com/1131096740/intelligent-construction-management/issues/382)。迁移、受控实验、部署与生产变更仍按各自具体授权执行。

**类型：** 业务垂直片。目标为一个新会话可完成的边界；如果探索发现仍跨越多个独立用户路径，应先收窄票据再执行。

**交付行为：** 财务/综合主管直接登记真实垫资，公共现金或公司账户保留多出资方来源；公司补足项目资金经确认形成相应往来。

**Blocked by：** [15 公司登记余额与公共现金期初闭环](15-fund-accounts.md)、[24 公共现金与公司资金双向转款接力](24-cash-transfers.md)。

**需求：** FND-05、FND-07、FND-12、FND-18。以[完整规格](../../specs/2026-11-05-enterprise-simplification-spec.md)最终规则为准，不能只实现票据标题。

**技术决定：** [技术方案](../2026-11-05-enterprise-simplification-technical-plan.md) D06。**公开验收：** [验收情景](../2026-11-05-enterprise-simplification-acceptance.md) A21、A23、A24。

## 验收条件

- [ ] FND-05：明显登记项目垫资入口；记录出资方（公司/施工企业/个人等）、金额、到账日、公司资金或公共现金/保管人；实际已收直接入账，不董事长/总经理审批，不先申请额度。
- [ ] FND-07：可选择实际公司资金/公共现金并记录项目；公司银行资金无需事先逐笔分配项目；不把系统登记余额当实时银行余额。
- [ ] FND-12：现金转公司及直接支付/报销时可选来源出资方；混合或未清楚来源标待核对，不自动猜FIFO或来源。转入公司仍保留原出资方垫资关系，不变成公司收入。
- [ ] FND-18：项目资金5、公司付款8提示核对差额3；经办确认属公司垫资后自动关联原付款生成记录，不再重复手录或重复创造账户资金。
- [ ] 无额度审批；来源未知不FIFO猜测，跨项目周转不强预分配。
- [ ] 项目资金5公司付8，未确认不自动造3到账；确认后只建立真实差额债权，不重复资金。
- [ ] 现金转公司和直接支付都可追溯同一来源，垫资不计经营收入。

## 验证与边界

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
