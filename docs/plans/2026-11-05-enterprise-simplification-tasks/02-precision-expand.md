## 验收条件

- [ ] NUM-01：数量、单价和非付款金额录入/保存/展示最多4位小数；超过4位保留输入并提示修改，不自动截断或替用户舍入。实际付款按2位四舍五入。
- [ ] NUM-02：数量×单价的计算结果四舍五入到4位，再逐行相加；1.2345×1.2345=1.52399025，行金额为1.5240。不存在数量/单价时不按0计算。
- [ ] NUM-03：合同累计结算先以4位精确汇总，再四舍五入到分作为支付上限；两笔0.005结算累计支付上限0.01，而非0.02。
- [ ] NUM-04：100.005业务金额实际付100.01，按支付口径视为付清，不提示0.005超付或欠款；合同、采购、报销等一致，原业务金额不改写。
- [ ] NUM-05：未约定/待确定/待核对/零为不同含义；不把空白当0，不猜失去的精度，不重算或覆盖历史已确认原事实。
- [ ] BAS-06：按北京时间显示和判断日期；允许补录过去真实日期；实际收款、付款、退款不能填写未来日期。中文提示应说明问题和下一步，不暴露技术ID、原始错误。
- [ ] 只增加兼容字段/适配器和版本，不删旧列；旧分精确转换，源六位超精度记录不自动舍入。
- [ ] 独立算例证明行合计、累计后到分、负数半入、NULL与0；溢出/5位从HTTP拒绝且无部分写入。
- [ ] 公开读写新值不被旧协议回写丢失；后续各领域票据接入并做双读对账。
