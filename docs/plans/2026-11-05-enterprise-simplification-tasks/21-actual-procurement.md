**状态：** `plan-confirmed` / `not-started`；前置工单未关闭，尚未实施。本轮用户已授权整套实施及 GitHub 工单推进；[#403](https://github.com/1131096740/intelligent-construction-management/issues/403) 已发布，归属父工单 [#382](https://github.com/1131096740/intelligent-construction-management/issues/382)。迁移、受控实验、部署与生产变更仍按各自具体授权执行。

**类型：** 业务垂直片。目标为一个新会话可完成的边界；如果探索发现仍跨越多个独立用户路径，应先收窄票据再执行。

**交付行为：** 原单记录多供应商/多批实际采购，各批发起付款并查看已付待付；首次付款通过确认整批成本，后续付款不重复。

## 验收条件

- [ ] PUR-07：原申请下可多批/多供应商实际采购，填真实事项/数量/单价（已知时）与实际总金额；同批可关联多次付款，不重复形成采购成本。
- [ ] PUR-08：付款前实际申请金额必须明确；允许与清单合计不同，展示差异供人员核对，不强制相等；不以申请预计额作支付上限。
- [ ] PUR-09：实际采购批次关联第一笔付款或垫付报销通过时确认整批实际成本；买1万首申3000，通过后成本1万，已付只按实际记录；后续付款/报销不重复计成本。
- [ ] PUR-10：确认后从统一更正入口由财务主管确认正确金额并重算成本；保留已付款，实际确认金额不足覆盖剩余付款才暂停，否则照常。
- [ ] PUR-11：原采购详情显示每商家、申请金额、已付、状态及累计实付；原申请不因多次付款拆成重复需求。
- [ ] 付款申请确定真实金额，优惠导致与明细合计不同由业务核对；10k批次首付3k仍确认10k成本一次。
- [ ] 实际采购更正财务主管复核，少于剩余付款时暂停；无收货表/接口残留前置。
- [ ] 采购付款并联岗位、财务/综合主管执行、退款重算和当前台账回原单完整。
