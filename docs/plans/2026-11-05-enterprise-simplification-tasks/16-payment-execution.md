## 验收条件

- [ ] PAY-11：推送给有权财务和综合部主管；系统外实际支付后登记金额/日期/公司银行资金或公共现金/项目/实际登记人；同申请可多家公司分次付。
- [ ] PAY-12：已付、剩余待付逐笔显示；仅付清或按规则关闭后共同待办结束；不因另一人付过部分就全部消失。
- [ ] PAY-13：先登记已实际付款及日期，电子凭证可后补并标待补充；不把未知网络结果当失败重发。
- [ ] 正常/提交异常/断连/响应丢失用真实PG证明成功响应必有事实，重复请求不双扣；当前Prisma异常须实证闭合。
- [ ] 申请剩余、资金、分摊、审计和事件同事务；并发两人支付仅合法金额生效，凭证可后补。
- [ ] 共享余额足够但项目归属不足的差额待业务确认，不自动记虚构垫资到账。

## 验证与边界

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
