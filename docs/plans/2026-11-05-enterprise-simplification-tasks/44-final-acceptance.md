## 验收条件

- [ ] BAS-03：合同、结算、付款、两类采购、报销、历史接管、项目经营、资金往来、人员权限、模板、审批通知、档案与搜索均在范围内；不以单页改好代替整体完成。
- [ ] BAS-05：用户数约10人以内，通常同时在线2～3人；在该规模和必要余量下验收，并覆盖真实业务并发竞争。
- [ ] CUT-07：不安排真实手机；多尺寸、Chromium/WebKit和适用模拟覆盖录入、上传预览下载、签字、链接、后台恢复等；微信宿主/硬件不能可靠模拟处明确列限制，不冒充真机通过。
- [ ] CUT-08：需求→任务→测试/证据可追溯；局部旧mock/原型/不同SHA测试不代替最终全链；代码变化后重绑受影响证据；真实短信送达、生产状态等未核验不得报已通过。
- [ ] 按约10账号、2～3同时在线和必要余量走全部角色，320～1920及横竖屏，不安排真实手机。
- [ ] 重跑受影响包检查和公开链，明确既存失败/跳过；任何改动使相关证据过期。
- [ ] 只清本任务资源并核不存在；真实短信/生产未执行时明确列出，不称完整上线成功。

## 验证与边界

- 承接门：02/03按用户确认以“本地阶段完成、PG待验”关闭，仅解除源码实施依赖。最终准确候选必须包含这些欠验的真实PG约束/并发、实际资金提交及资源身份/清理结果；16/42既有硬门亦保留，不得拿前置票关闭、登记场景数或source seal代替执行收据。资源、迁移与部署仍需具体授权。
- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
