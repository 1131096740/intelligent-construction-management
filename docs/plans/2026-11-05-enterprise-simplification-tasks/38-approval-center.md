## 验收条件

- [ ] APR-06：新机制驳回重提只保留最新一轮审批单及有效签字，不提供旧轮次审批单和签字；保留驳回人/时间/原因等必要记录；迁移前真实历史材料例外保留。
- [ ] APR-07：发起人、已处理/后续审批人和按权限可查看管理人员均能看进度；只有本人当前有效职责能办理；可见范围与可办理不混同。
- [ ] APR-08：需要我审批/我发起的/我参与的/我可查看；委托并入待审批、超时作为筛选；项目/发起人/状态查找，摘要显示主要事项、对象/金额及并联完成数。
- [ ] APR-09：流程中可查看原单/附件、各岗位处理人和状态、当前审批单并下载PDF、催办；本人可办理时底部同意签字/驳回，手机可达；无权者不显示办理按钮。
- [ ] APR-10：已签节点显示签字、未签留空、标审批中；保留水印和下载记录，不以未全批完阻止；纸上签字不影响线上流程。
- [ ] 委托并入待审批、逾期为筛选；有权查看流程者可按规则催办，但查看权不等于审批权；跨项目按角色。
- [ ] 办理中PDF仅完成签字、留空待办、带水印；退回只保最新轮无旧签字，真实旧历史档案保留。
- [ ] 所有流程适配使用职责状态，不能残留“第N节点以前都已通过”的推断。

## 验证与边界

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
