## 验收条件

- [ ] PAY-06：真实已付不因结算更动而被改写；显示已付/未付/超付并提示；历史真超付先保留，之后结算足够时可继续。
- [ ] PAY-14：统一更正入口填写正确金额/对象/日期/关联或来源，财务主管确认后重算余额及待付；原事实和更正保留；确认人是创建/提交人时自审。
- [ ] PAY-15：关联原实付，按实际收款的公司资金/公共现金直接登记，无新审批；原付10、退2显示原付10/退2/净付8；分次累计退款<=原实付。
- [ ] PAY-16：多付款退款不减原成本；退货/取消采购的无结算采购退款冲减确认采购成本；有合同结算退款先记资金并提示待负数结算，成本在主管复核负结算后减少。
- [ ] APR-13：入口同名、依单据类型/状态/权限引导：草稿编辑、审批中撤回、已确认金融记录更正、已签合同补充变更、已确认结算新增正负结算；不把统一入口变成直接改所有事实。
- [ ] APR-14：施工企业付款、实付、退款、归还、采购金额等按已确认职责提交复核；原记录保留，系统重算；本人为创建或提交人时可原因+密码自审。
- [ ] 确认结算不可走更正绕过；财务主管自审同样验证原因密码；原事实保留。
- [ ] 退款累计不超可退，退货成本调减与多付退款区分；合同成本须负结算，不因资金退款偷改。
- [ ] 更正重算资金/来源/债权，旧请求重试不生成第二补偿。

## 验证与边界

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
