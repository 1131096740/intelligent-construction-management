**交付行为：** 网页铃铛/手机页顶显示当前待办，所有可办环节自动短信，流程可选人催办，失败不阻断业务。

**Blocked by：** [05 统一岗位配置、自审和委托权限](05-personnel.md)、[16 财务与综合主管共办实付及资金提交安全](16-payment-execution.md)。

**技术决定：** [技术方案](../2026-11-05-enterprise-simplification-technical-plan.md) D09。**公开验收：** [验收情景](../2026-11-05-enterprise-simplification-acceptance.md) A30、A31。

## 验收条件

- [ ] NTF-01：新待办首次弹出，列表保留未办，点击跳对应单据；未处理不反复弹窗；重新打开系统仍可查。
- [ ] NTF-02：只在打开本系统时顶部条幅，不做关闭网页后的OS推送；与电脑内容一致。
- [ ] NTF-03：铃铛数字为当前需本人处理数，点开不减；完成/撤回/不再属于本人时减；共同职责一人完成后他人消失，部分付款剩余仍待办。
- [ ] NTF-04：审批并联时同时通知各需要人；非审批采购/填写/复核/付款/盖章/上传归档也覆盖，每条待办独立短信；本人未提交草稿不短信，驳回需修改发短信。
- [ ] NTF-05：按类型含项目或公司日常、发起人、事项、双方/对象、金额，付款可含累计结算/已付，报销主要明细与合计；未定金额写待确定；链接末尾直达，仍需登录及权限核验。
- [ ] NTF-06：默认催办所有尚未处理者，也可选人；发送短信同时产生站内提示；同流程同岗位职责的手动催办间隔1分钟，多人共享，自动新待办首发不被冷却误挡。
- [ ] NTF-07：失败显示失败可重试；请求结果不明显示待确认不自动重发；已提交供应商不等于手机送达；站内待办照常。
- [ ] NTF-08：职责已被处理后链接显示由谁完成并可查看，无重复办理；原先角色/项目撤销后不得凭链接维持办理权。
- [ ] NTF-09：账号用户名即手机号，创建时必填；不设计用户已确认不存在的未填手机号常态流程；号码变更/发送异常按实显示。
- [ ] outbox与业务事务关联，全部并联收件人与非审批环节逐人一次；摘要丰富但链接仍鉴权。
- [ ] 60秒按流程/职责跨点击者共享，自动新任务不受手动冷却；失败可控重试、未知不自动重发。
- [ ] 先以模拟供应商验收发送意图；真实送达需另行授权验证，不把受理当送达。

## 验证与边界

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
