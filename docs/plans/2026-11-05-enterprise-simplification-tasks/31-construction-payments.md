# 31：施工企业已付和我方到账同事实登记

**状态：** `plan-confirmed` / `not-started`；前置工单未关闭，尚未实施。本轮用户已授权整套实施及 GitHub 工单推进；[#413](https://github.com/1131096740/intelligent-construction-management/issues/413) 已发布，归属父工单 [#382](https://github.com/1131096740/intelligent-construction-management/issues/382)。迁移、受控实验、部署与生产变更仍按各自具体授权执行。

**类型：** 业务垂直片。目标为一个新会话可完成的边界；如果探索发现仍跨越多个独立用户路径，应先收窄票据再执行。

**交付行为：** 根据凭证登记施工企业对下游/我方实际支付，形成施工企业已付金额；转我方同时关联我方到账。

**Blocked by：** [30 业主正负结算、到账和预付款登记](30-owner-business.md)、[14 三类合同统一正负结算单复核入账](14-settlements.md)。

**需求：** OPS-04、OPS-05、OPS-07、OPS-09。以[完整规格](../../specs/2026-11-05-enterprise-simplification-spec.md)最终规则为准，不能只实现票据标题。

**技术决定：** [技术方案](../2026-11-05-enterprise-simplification-technical-plan.md) D06、D07。**公开验收：** [验收情景](../2026-11-05-enterprise-simplification-acceptance.md) A25、A26。

## 验收条件

- [ ] OPS-04：工作台及项目总览有同名登记施工企业付款；有系统申请可选带出，无系统申请可按真实凭据登记；直接汇总不新增审批，仍须有实际对应结算（非必须预先存在系统付款申请）。
- [ ] OPS-05：施工企业付我方或下游均先有对应结算；已结算10实际付12允许如实登记、提示超付2，不强改真实金额；不增加施工企业无结算预付款路径。
- [ ] OPS-07：项目总览固定名称施工企业已付金额，含付下游和付我方，点击看收款方/金额/时间；我方收到后再付下游不再计入施工企业直接已付。
- [ ] OPS-09：金额/对象/日期/合同或申请关联错误走同一更正，综合或财务提出、财务主管确认，自审按规则，更新汇总不覆盖原记录。
- [ ] 施工企业支付须有真实结算依据，不必有本系统付款申请；真实超付允许并显示。
- [ ] 同一事实两视图不重复收入/资金；财务更正后两端同步，不能把我方后续支付又加到施工企业已付。

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
