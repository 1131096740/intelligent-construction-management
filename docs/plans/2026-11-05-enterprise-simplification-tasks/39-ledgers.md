## 验收条件

- [ ] UI-11：合同、结算、付款、零星材料采购、综合采购、报销各有独立页；草稿在工作台，已提交单据按状态查看；结算例外：主管复核通过才进正式结算台账，待复核在工作台。
- [ ] UI-12：显示项目和甲乙双方/采购单位与供应商/报销人与报销单位等实际关系；公司日常显示公司日常，未确定对象显示待确定，不虚填甲乙方。
- [ ] UI-13：项目、日期、状态、关键字筛选；列宽、列顺序、显示隐藏、排序和个人视图保存；不改变数据含义和权限。
- [ ] UI-14：导出当前筛选与显示列，同时保留项目、实际业务双方等必要信息；中文业务列、合适列宽/表头/冻结/日期金额/适用合计及打印布局，不含原始技术字段。
- [ ] 项目/实际甲乙双方等必要归属清楚，框架未知不0；导出全筛选与显示列但必要列始终有。
- [ ] 金额精度、中文列、列宽冻结合计打印布局及公式注入防护核验，不夹技术字段。
- [ ] 个人列视图不改变权限、账务语义或他人设置；小屏表格稳定。

## 验证与边界

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
