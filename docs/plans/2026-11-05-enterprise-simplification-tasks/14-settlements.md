## 验收条件

- [ ] SET-01：选项目/合同，显示双方和现有累计，填本期金额、手填结算编号、上传已签PDF/照片，预览预计累计；不再填类型/期间清单数量或选择结算模板。
- [ ] SET-02：未填可存草稿，提交复核前必填；同合同重复编号提示但不阻止，不同合同可同编号；禁止系统自动生成替代该编号。
- [ ] SET-03：同入口、同操作、同主管复核；不分纠错/负数用途，不额外要求一份纠错说明资料；零不能提交，负数可以冲减。
- [ ] SET-04：只看合同、本期金额、已签附件和预计累计，复核通过或填写原因驳回；通过即入台账累计，不多节点审批、不再生成/冻结系统结算单及另行归档。
- [ ] SET-05：原制单人修改金额/附件再提主管复核；未确认记录不参与正式累计。
- [ ] SET-06：同合同历史已确认起点加接管后确认正负数；提交和主管复核均事务核验累计>=0。累计10，两笔-8同时提交，第一笔过后第二笔不得通过。
- [ ] SET-07：已确认单不可修改/更正/作废；金额、错合同或错附件通过普通负数冲减并正确重登，原事实保留；不增加不同负数UI。
- [ ] SET-08：可登记所有项目结算；本人创建/提交并复核按自审原因+本人密码办理。
- [ ] SET-09：只选择最近确认的一期（含负数），带出合同累计结算，不把负数本期当成总可付；默认合同/最新结算附件，可展开历史附件。
- [ ] SET-10：同单多PDF/多照片，能预览下载；金额一致由业务人员保证，不OCR/自动比对。
- [ ] CUT-03：用户确认结算功能从未实际使用，不安排旧多节点结算再确认；实施核查若发现相反真实数据，停止删除并报告事实，不自动按已确认处理。
- [ ] 提交和复核双检累计≥0，真实PG两笔-8竞争第二失败；零拒绝，重复编号仅提示。
- [ ] 无多节点、清单、税率和生成文书前置；本人主管自审须原因密码，驳回回原草稿。
- [ ] 确认序号定义最新含负数；历史基线只一次；API禁止确认单改附件/金额/合同或作废。

## 验证与边界

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
