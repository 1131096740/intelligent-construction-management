## 验收条件

- [ ] UI-04：合同清单、采购需求/实际采购、报销、历史费用等沿用用户确认的原型风格；单条主信息用同风格表单。正式事实不可因表格外观而任意编辑。
- [ ] UI-05：Tab/Shift+Tab跨可编辑格，Enter/Shift+Enter上下，Esc恢复本格；中文输入法组字和文本编辑原生操作不被误截获；复制粘贴多行多列，错误定位到格。
- [ ] UI-06：左侧复选、全选/半选、Shift连续多选、选中行高亮、选中数和所选合计；行旁复制/删除/适用的上下移动；批量复制/删除/取消选择；底部新增与整单合计；删除可撤销，复制后定位新行。
- [ ] UI-07：宽表占主要内容宽度；文本左对齐、数字右对齐、自动计算值只读浅底；表头/关键列固定、局部横向滚动；标题不被挤成逐字竖排，选择条换行不遮按钮。
- [ ] UI-08：先尝试触摸表格、重要列优先和局部滚动；仿真验证发现难用或不稳定时才采用逐条卡片；字段、规则和保存行为一致，不承诺完整手机宽表已经稳定。
- [ ] UI-09：所有填写型业务自动保存并保留保存草稿按钮；显示保存中/已保存/失败；保存不等于提交、审批、入账或付款；失败保留输入。
- [ ] UI-10：无网保留当前填写，联网再保存/提交；提交结果不明显示待核对并阻止重复写；查证成功显示结果，明确失败才重试；不做完整离线审批/付款系统。
- [ ] UI-15：中文填写模板不含隐藏技术列/工作表；上传后预览、逐行逐格定位问题，确认后只写草稿；默认追加，可选择替换并提示且可撤销；不自动提交或入账。
- [ ] 保留原型视觉与键盘细节；选择状态与焦点分开，中文组字不跳格，复制使用新行标识。
- [ ] 输入/保存冲突与断线不丢数据、不静默覆盖，不自动提交业务；导入追加/替换可确认与撤销。
- [ ] 各尺寸真实页面验证局部横滚、固定列、按钮和软键盘视口；测试使用服务端数据而非原型localStorage。

## 验证与边界

- 业务片贯穿需要的Schema/约束、领域公开API、页面与真实行为测试；既有层无需改动时说明复用证据，不能为形式齐全改无关层。验证前置/技术验证/发布准备片以其可核验产物验收。
- 金额、权限、状态、文书、归档、审计用后端公开行为验证；最窄检查通过后做受影响包typecheck/lint，Web另做check:ui。依赖外部网关时明确模拟与真实边界。
- 保留真实数据及既有未提交内容；本票不包括无关清理、生产变更、重启/删除状态不明旧资源。受控实验/迁移/远程写须在实际实施时按项目既有授权流程处理。
- 完成时提供可复核行为、指纹/检查结果和未通过事项，更新简短进度；不能把旧SHA收据或文档确认作为本票通过。
