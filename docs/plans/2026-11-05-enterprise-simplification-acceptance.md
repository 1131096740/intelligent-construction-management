# 重构测试边界与最终验收

> `plan-confirmed`，2026-11-05；验收边界已获用户确认。[业务规格](../specs/2026-11-05-enterprise-simplification-spec.md)全部需求均须验收；本文件列最高可用测试边界和重点风险，不取代每条需求。本轮整套实施和 GitHub 工单推进已获明确授权；当前只进行任务01基线准备，尚未运行下列本轮产品测试。受控实验仍须固定入口与具体授权。

## 测试接口与证明范围

优先复用现有公开业务HTTP接口，经真实Nest模块、认证/权限、真实PostgreSQL，核响应、持久结果、审计、文件与待办；Web从同一接口完整办理。需要故障注入只在可控制的连接/网络/文档worker/短信网关边界，不替换业务事务或数据库为mock。精确数字以独立手算例子断言，不能测试函数用自身结果当期望。

| 边界 | 可以证明 | 不能证明 |
| --- | --- | --- |
| 公开HTTP+独立PG+受限运行角色 | 金额/状态/权限、并发、回滚与持久结果、重试防重、真实约束 | 生产数据库权限、真实用户数据质量、云网关送达 |
| 浏览器真实页面+上述API | 键盘/表格/单据串联、布局、输入与错误定位、文件上传下载/返回原单 | 真机软键盘、微信内核差异、运营商短信 |
| 文书真实生成+字节/文字/版式检查 | 正文同步、分页、字体嵌入、当前签字与下载内容 | 用户线下是否按该文件签章 |
| 短信适配器确定性替身 | 发送意图/收件人/摘要/冷却/幂等、失败与未知处理 | 真实供应商受理和手机实际送达 |
| 隔离恢复+迁移演练 | 备份可恢复、转换/映射/重跑、数据与文件对账 | 未核实线上来源是否与快照一致 |

## 验证节奏与最终门禁

1. 每个票据先最窄相关公开行为/领域测试；通过后运行受影响包typecheck/lint。Web变更运行check:ui；资金、权限、状态、归档、PDF、审计必须有后端验证。不要为低影响样式写实现镜像测试。
2. 修改核心事务必须真实PG复验；TLS/权限/提交故障实验先固定范围、身份、执行入口与清理，按正式审批通道授权，失败关闭。禁止通过修改旧runner权限或mock来“过验收”。
3. 各垂直片用同一项目串链：新合同→审批签章归档→正负结算→付款→分次实付/退款→成本/资金/台账；另跑采购/报销和历史接管。这能捕获单模块测试未见的重复累计。
4. 最终候选重新固定指纹并重建必要全链证据：精度、并联竞争、资金提交、权限、文书、导出、迁移恢复、页面与任务清理。原有失败/跳过逐项说明，不能被总通过数掩盖。
5. 手机仅浏览器仿真；不安排用户真实手机验证，不宣称Safari/微信真机全兼容。真实短信与生产只读/切换不在本轮授权中，届时单独取得执行范围和结论。

**已确认验收边界**：此方案把公开HTTP+真实PG作为账务/流程主要验收边界，Web作为操作/响应式验收边界，保留文书实际生成与隔离恢复，短信先模拟再独立实送。用户已与任务粒度一并确认这些边界；不重问已确认业务。
