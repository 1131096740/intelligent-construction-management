# 单人可维护的首发上线收敛方案（已确认）

2026-10-13。目标是让公司开始处理真实业务，减少纸质办公；用户负责业务决定和重要操作批准，AI完成技术实施。用户已确认“受控首发，复杂自动发布机制延后”；本文登记该上线契约调整，未授权部署/迁移/数据清理、提交/推送或新生产访问。现有自动激活工具的生产禁用和验签规则不变。

## 首发交付与运行方式

复用现有响应式Web、NestJS/PostgreSQL、现有服务器及私有附件存储。首发使用现有合同、结算、付款审批、分次实付凭证、余额和历史回读闭环；首批由实际业务岗位核对一个项目的处理结果，不在系统中限制其他真实项目功能。权限和业务审批继续由后端执行，技术管理员不会变成业务审批人。

AI负责本地开发/修复/测试、编制固定发布和回退步骤；生产重要阶段由用户一次批准该阶段及准确条件退出。上线后先建立有界健康检查、完整备份和异常汇报；变更版本、迁移、数据恢复、权限变更和业务开放继续审批。当前未安装日常自动任务，也不能承诺已有持续AI值守。

用户不需要学习技术密钥管理、保管签名私钥、监看每个测试或聘请运维团队。技术凭据按最小权限、私有配置和受控脚本管理；需要新角色/配置时仍提交准确建设包批准，不让用户编写技术命令。

## 保留的首发必要条件

1. 固定一个可维护的候选版本，明确必要的业务和备份安全修复；保护全部旧草稿和失败证据，不默认把所有运维实验并入首发。代码范围与依赖经核实后再申请固定提交/远端交付。
2. 最终候选一次完整17门和真实业务闭环验证；桌面和手机实际岗位权限、金额、凭证、余额及历史不能失败。代码变化重新绑定证据。
3. 正式DB与附件完整备份，隔离恢复并核对内容；备份连接权限、目标保真、凭据保护及恢复能力是必要条件，不用旧备份或合成材料代替。
4. 一个明确维护窗口，暂停实际业务写入口/后台任务/三条备份调度，排空在途，并对外部及管理写入口作准确控制和持续检查。旧02:30任务保留。不能因为单人管理就假定没有后台写入。
5. 准确生产身份/版本/迁移和Schema、发布前后快照、真实命令结果、健康检查、失败停止及回退条件；部署和迁移各有准确批准。不更改业务校验、扩大skip或删除测试来缩短时间。
6. 测试数据与真实历史数据先区别处理。清理只对已确认的测试范围且另行批准；不为了满足旧收据规则删除公司真实记录。既有归零/开放上游要求须逐项映射，不能默默跳过或关闭Issue。
7. 首批实际岗位能够登入、操作及回读真实业务；明确维护中/失败提示和问题反馈渠道。技术测试不是公司业务验收。

## 已从受控首发前置移出的建设

独立临时CAM元数据读取身份及其策略写法试验、三职责自动签名服务、云签名算法改造、在线见证服务、不可逆WORM证据存储以及额外控制计算环境，作为未来无人值守自动发布的建设，不串联成为本次受控首发的默认前置。

具体CAM权限若实际业务附件、备份或维护控制必须使用，仍需核实和修复；延后的是为了机器权威取证而新增的辅助体系，不是忽略真实越权或备份失败。现有元数据读取账号、凭据和未知策略遗留均保留准确记录，不在本次方案选择中删除、禁用或新增关联。

这是用户于2026-10-13确认的契约变更。原POL25A原生v1和POL25B自动激活协议本来要求不同签名主体及可信观察；不能在原工具中删除验签或伪造收据以适配本方案。本次须更新治理规格、上游映射和受控首发runbook，明确人工批准+固定脚本+原材料核验的发布路径及残余风险。旧自动化入口继续禁用，后续具备其真实条件才启用。

## 替代保障和接受的风险

最终所有者可信；重要生产变更由用户批准准确版本/范围/窗口/回退，AI不能自批。生产执行使用固定步骤和临时最小权限，不给常驻AI主账号或任意root能力。保留实际原材料、云端操作记录、版本与前后摘要；备份身份与运行身份分开，保护历史备份不被运行身份删除。

不宣称上述安排具有三方独立签名或对抗最终所有者恶意篡改的强度。发布异常时可能需要用户决定延长维护、回退或恢复，AI不能完全无人值守。这一风险由已验收备份、准确回滚、明确停止点和用户阶段批准降低。当前同主机运行的故障风险保留，不把跨主机自动接管列为已完成。

纸质历史材料的录入和业务确认需要公司岗位参与；技术实施由AI承担。没有要求用户提供密码、密钥或额外找技术团队。

## 收敛后的推进顺序

1. 先核实首发必要代码与已合并主线，形成一个候选；只修会阻止业务使用、备份恢复或安全发布的明确缺陷。当前不再推进辅助CAM创建/审计试验。
2. 将所选受控首发方式与旧上游条件逐项映射，形成可执行的备份/维护/发布/失败退出包；缺现场参数集中取证，不每个点击报批。
3. 申请固定提交、一次最终17门及远端交付；通过后申请生产备份恢复和维护发布阶段。
4. 正式发布后用一个项目的实际岗位完成业务验收，再申请开放和扩大使用。用户决定真实业务资料和批准重要阶段，无需决定脚本实现细节。

不承诺未经实测的上线日期。工程工作是候选收敛、备份恢复及发布步骤验证；外部等待是必要账号登录/批准和公司业务确认，不再默认加入第三方团队、签名服务采购或辅助策略试验等待。
