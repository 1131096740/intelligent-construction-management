# 本地增量检查

`pnpm check:fast` 保留默认发布筛查基线：`merge-base origin/main HEAD`。数据库、依赖、共享领域源码、运维工具和治理清单仍退出2，提示准确SHA的完整门禁。

开发迭代可执行 `pnpm check:fast --dev-base <完整40位提交SHA>`。基线应选上一已完成相应检查的集成点；操作者需保留该检查回执。入口核实提交存在且为HEAD祖先，不替操作者证明历史检查已经完成。只接受不可变提交SHA，不接受分支名或Shell表达式。

两种模式均分别合并基线→HEAD、暂存、未暂存及未忽略的未跟踪路径。使用NUL分隔，覆盖删除、文件类型变化和重命名两端，避免暂存与工作树相互抵消时漏检。使用既有包级静态检查、相关测试发现与完整套件回退；删除测试无法定位时回退完整套件。开发模式对名称可识别的权限/身份路径额外拒绝快速验收；任何语义上影响权限、金额或归档的变更仍须按项目规则补真实门禁，路径分类不能证明业务影响不存在。未知路径仍退出2。

每次退出输出一行 `[check:fast] report: <JSON>`，含mode、实际base/head、四类coverage、最终paths、执行commands（含测试参数）、exitCode及毫秒timings。固定计时键包括collect、select、total及实际执行的既有阶段标签（如api:typecheck、api:selected-tests）。未执行的阶段不生成耗时；collect和select是工具的收集/分类成本，测试发现与执行另计。命令执行前另输出JSON参数，失败也保留已执行集合和耗时。报告描述运行开始时的范围；检查期间请勿同时修改该工作树。

开发结果仅证明这轮差量，不证明整个分支、CI或发布。最终候选仍运行准确SHA的完整规定门禁；换基线不能解除敏感变更、真实受限角色/数据库、文件或生产验收要求。脚本不会签发发布许可，也不自动写入或移动检查点。

工具自身验证：`node --test scripts/ops/run-fast-local-check.test.mjs`。测试通过现有CLI使用受控命令适配器检验选择机制，并以真实临时Git仓库检验基线、脏工作树、删除、重命名和特殊文件名；这些测试不运行真实业务或数据库。
