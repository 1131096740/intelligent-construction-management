# 合同办理分类选择与项目固定施工企业

本轮来源：用户于 2026-10-20 要求在合同新办、历史接管操作页直观选择表内、表外及施工企业与我方公司关系，并要求每个项目唯一绑定施工企业，绑定后不变，由董事长、综合部主管维护。此要求取代早期“首笔正式事实前可更换”的普通操作规则。仅授权本地代码与验证；生产数据、历史补录、迁移及部署仍待单独确认。

## 办理入口

- 新建合同先选项目，再选“表内（我方签约）”“表外（施工企业签约）”“对上（施工企业—我方）”，并展示双方身份及金额影响。表内继续原合同草稿、审批和归档流程；表外、对上进入现有专属事实登记与专业复核流程，不能冒称施工企业内部审批。
- 历史合同接管页面使用相同选择。表内仍使用历史合同专业/财务双确认；表外、对上按真实原件、日期、合同和相关历史事实在既有专属台账接管。入口意图不是新事实，不为同一合同复制第二份记录，也不修改已有分类。
- 表内批量预检只在表内选择时显示；对表外、对上不能借表内导入错误默认我方公司签约。历史不明资料继续待核对，不自动补齐分类、日期或金额。
- 合同、结算、付款页面继续共用签约关系分类台账和后台金额来源。选择不是新的可自由修改的会计字段；结算和付款继承冻结来源主体，实际代付方不改合同分类。

## 固定绑定

- 正式界面沿现行词典称“施工企业”。每项目只有一家；同一企业可服务多个项目。
- 入口：项目工作台 → 选择项目 → “施工企业与参与公司”，或“项目设置 → 唯一施工企业”；合同办理页为有维护权限者提供定位当前项目设置的链接；其他岗位显示维护路径和责任人，不展示不可访问的按钮。
- 仅公司级董事长、综合部主管可首次绑定，按原档案权限选择有效企业版本、填写真实生效日和依据；普通项目岗位、总经理、财务及技术管理员不获维护权限。
- 首次绑定即固定；即使没有正式合同或金额业务，也不允许改成另一企业、重绑同一企业或重写原日期。后台在同一项目行锁事务内检查，双人并发只允许一次首次绑定；沿用数据库当前绑定唯一约束。任何原正式事实或审计失败保护继续生效。
- 保留原绑定与版本历史；本轮不执行历史项目绑定。未绑定项目可继续整理资料，但原正式业务门禁仍要求唯一施工企业，不猜测企业、不自动启用经营账。

## 金额和验收

沿用 2026-10-19 合同分类规格。表内与表外真实下游承诺分别小计；对上合同及结算仅主体往来，不加入下游合同合计或重复计项目成本/收入。付款核销原债务，不能第二次确认成本。复用原经济重复复核、技术幂等及来源排他，不新增平行账。

验收包括：真实 API 的首次绑定、并发、重绑拒绝及岗位授权；桌面/手机选择三类、历史入口与项目定位、绑定后操作消失；原合同/结算/付款/代付/核销和公司余额回归。测试为本机一次性库与合成资料，不代表生产或真实员工验收。
